## 1. 当前状态

Phase 7 是计费系统的运营增强阶段，不是当前应立即执行的阶段。

执行前提：

1. Phase 3 短信真扣费已稳定。
2. Phase 4 视频转文本真扣费已稳定。
3. Phase 6 AI 真扣费已稳定至少 2 周。
4. 账务底座无负余额、无重复扣费、无长期冻结异常。

当前 Phase 5 之后还没进入 Phase 6，因此 Phase 7 当前状态为：

```text
blocked：等待 Phase 6 AI 真扣费稳定
```

## 2. Phase 7 目标

Phase 7 目标是把“能扣费”升级成“可运营、可对账、可预警、可扩展”。

主要能力：

1. 余额预警。
2. 扣费失败通知。
3. 冻结超时释放。
4. 异常账单重试。
5. 日账单和月账单汇总。
6. 对账导出。
7. 积分过期策略。
8. 资源包/套餐包预留。

## 3. 能力一：余额预警

### 3.1 规则

建议第一版平台级阈值：

```text
BILLING_LOW_BALANCE_THRESHOLD_CREDITS=5000
BILLING_CRITICAL_BALANCE_THRESHOLD_CREDITS=1000
```

后续可扩展租户级阈值。

预警状态：

| 状态 | 条件 |
| --- | --- |
| normal | available > low |
| low | critical < available <= low |
| critical | available <= critical |
| depleted | available <= 0 |

### 3.2 通知对象

- 租户管理员。
- 平台运营。
- 平台财务或运维。

第一版可先复用系统通知表；如果没有合适能力，再新增 `billing_notifications`。

### 3.3 验收标准

- 余额从 normal 降到 low 时只通知一次。
- 余额从 low 降到 critical 时追加通知。
- 充值后状态恢复，再次下降可重新通知。
- 测试租户不触发真实通知。

## 4. 能力二：扣费失败通知

### 4.1 触发条件

- `billing_settle_event` 返回失败。
- 价格规则缺失。
- 账单事件状态卡在异常。
- AI token 缺失。
- 视频任务成功但扣费失败。
- 短信成功但扣费失败。

### 4.2 通知内容

至少包括：

- 租户 ID 和租户名称。
- 业务类型：短信、视频、AI。
- 源业务记录 ID。
- failure_code。
- 错误信息。
- 是否可重试。

### 4.3 验收标准

- 每条异常只通知一次，避免刷屏。
- 重试成功后可标记 resolved。
- 平台计费中心能筛选未处理异常。

## 5. 能力三：冻结超时释放

主要用于视频转文本等异步任务。

### 5.1 规则

建议 TTL：

```text
BILLING_FREEZE_TTL_MINUTES=30
```

如果任务超过 TTL 未成功结算：

1. 自动 unfreeze。
2. 业务任务标记 failed 或 timeout。
3. 写异常 billing event。
4. 通知平台运维。

不建议自动重试扣费。

### 5.2 验收标准

- 超时冻结能释放。
- 释放后 `frozen_credits` 不大于 `balance_credits`。
- ledger 有 unfreeze 记录。
- 同一冻结重复释放不会重复写账。

## 6. 能力四：异常账单重试

### 6.1 可重试范围

可以自动重试：

- 短暂数据库失败。
- RPC 超时。
- 网络抖动。

不自动重试：

- 价格规则缺失。
- token usage 缺失。
- 租户归属缺失。
- 余额不足。

### 6.2 重试策略

建议：

```text
最多重试 3 次
间隔：5 分钟、30 分钟、2 小时
```

每次重试要更新：

- `retry_count`
- `last_retry_at`
- `failure_message`

### 6.3 验收标准

- 重试幂等。
- 已 settled 的 event 不再重试。
- 不可重试异常不会进入自动重试队列。
- 重试成功后异常状态关闭。

## 7. 能力五：日账单和月账单汇总

### 7.1 日汇总

建议新增：

```text
tenant_credit_usage_daily
```

维度：

- tenant_id
- date
- metric_code
- scene_code
- source_type
- credits
- event_count

### 7.2 月汇总

建议 admin 先按日汇总聚合出月数据，不急于落月表。

月导出字段：

- 租户。
- 期初余额。
- 充值积分。
- 消耗积分。
- 赠送积分。
- 期末余额。
- 短信消耗。
- 视频消耗。
- AI 消耗。
- 异常数量。

### 7.3 验收标准

- 日汇总与 ledger 按天汇总一致。
- 日汇总可重复生成。
- 修改历史账单后能重算指定日期。
- admin 能按租户和日期查看趋势。

## 8. 能力六：对账导出

### 8.1 平台对账

需要支持：

- 按租户导出 ledger。
- 按资源类型导出 billing events。
- 按供应商导出原始业务日志。
- 汇总充值、消耗、冻结、释放。

### 8.2 供应商对账

短信：

- 平台短信成功条数 vs 供应商账单条数。

视频：

- 平台计费分钟 vs ASR 供应商分钟。

AI：

- 平台 token usage vs 供应商 usage。

### 8.3 验收标准

- 可导出 CSV。
- 导出结果带时间范围、生成时间和操作人。
- 导出数据和页面统计一致。
- 大数据量导出不阻塞请求，必要时异步任务化。

## 9. 能力七：积分过期

第一版不建议立即启用强过期，但应预留方案。

### 9.1 规则建议

可选策略：

1. 充值积分 1 年有效。
2. 赠送积分 3 到 6 个月有效。
3. 人工补偿积分可单独设置有效期。

### 9.2 需要的模型

如果要精确过期，单账户余额不够，需要批次表：

```text
tenant_credit_lots
```

字段：

- tenant_id
- source_type
- credits_total
- credits_remaining
- expires_at
- created_at

扣费顺序：

```text
先扣最早过期批次
再扣无过期批次
```

### 9.3 验收标准

- 即将过期提前通知。
- 过期扣减有 ledger。
- 过期不会导致负余额。
- 账单能解释为什么积分减少。

## 10. 能力八：资源包/套餐包预留

第一版可以只预留，不立即上线。

### 10.1 未来模型

```text
tenant_resource_buckets
```

示例：

- 1000 条短信包。
- 100 小时视频转文本包。
- 100 万基础 AI token 包。

扣费顺序：

```text
先扣资源包
资源包不足再扣积分
```

### 10.2 验收标准

- 资源包扣减不影响积分余额。
- 资源包扣减有独立流水。
- 资源包过期有通知。
- 同一业务不能同时重复扣资源包和积分。

## 11. Admin 对接

平台计费中心需要新增或增强：

1. 账务健康概览。
2. 余额预警租户列表。
3. 扣费异常列表。
4. 冻结超时列表。
5. 日账单趋势。
6. 月度对账导出。
7. 价格规则变更记录。
8. 手工补偿入口。

租户账务中心需要新增或增强：

1. 余额预警提示。
2. 日消耗趋势。
3. 消耗分类。
4. 充值和消耗导出。
5. 即将过期积分提示。

## 12. 微信小程序对接

小程序主要做轻量展示，不承载复杂账务。

需要支持：

1. 余额不足提示。
2. AI/短信/视频功能不可用提示。
3. 联系装修公司充值。
4. 客户侧不展示复杂价格规则。
5. 员工端可展示“租户积分不足，请联系管理员充值”。

不建议小程序第一版做：

- 充值支付。
- 账单导出。
- 价格规则配置。

## 13. 定时任务建议

Phase 7 至少需要以下任务：

| 任务 | 频率 | 作用 |
| --- | --- | --- |
| 余额预警扫描 | 每天或每小时 | 触发低余额通知 |
| 冻结超时释放 | 每 10 分钟 | 释放超时冻结 |
| 异常账单重试 | 每小时 | 重试可恢复异常 |
| 日账单汇总 | 每天凌晨 | 生成前一天汇总 |
| 月度对账快照 | 每月 1 日 | 生成上月对账 |
| 积分过期提醒 | 每天 | 提醒即将过期积分 |
| 积分过期扣减 | 每天 | 扣减过期积分 |

建议所有任务使用分布式锁，避免多实例重复执行。

## 14. 是否现在执行

当前不建议执行 Phase 7。

原因：

1. Phase 6 AI 真扣费尚未执行。
2. Phase 7 依赖真实扣费运行一段时间后的异常样本和运营需求。
3. 现在直接做 Phase 7 容易做成空壳页面或过早抽象。

建议顺序：

```text
继续 Phase 5 AI 试算
样本达标后执行 Phase 6 AI 真扣费
Phase 6 稳定 2 周后执行 Phase 7
```

## 15. Phase 7 验收标准

Phase 7 完成必须满足：

1. 平台可以看到余额预警租户。
2. 扣费失败能通知平台运维。
3. 冻结超时能自动释放。
4. 异常账单可重试且幂等。
5. 日汇总和 ledger 可对账。
6. 月度账单可导出。
7. 租户可以看到自身账务趋势。
8. 小程序余额不足提示清晰。
9. 资源包和积分过期方案已明确是否启用。
10. 所有定时任务有运行记录和失败告警。
