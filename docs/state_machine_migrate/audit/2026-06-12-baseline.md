# State Machine Migration Baseline

## Scope

- Customers: old status transition endpoints and `customers.status` are still the primary compatibility surface.
- Projects: old project status endpoints and `schedule_project_construction_transition` are still active.
- Expense requests: legacy approval workflow still uses `expense_requests.status`, `current_step`, `current_step_role`, and `expense_request_approval_chains`.
- Task center: expense task builder still derives pending work from old approval chain and `current_step`.
- Mini-program/self-service: customer bootstrap/project detail style APIs still need `workflow_state` before old fields can be removed.

This baseline started as a static repo audit. Target database row counts and
live legacy object inventory were later verified during the 2026-06-12
pre-cleanup audit recorded in
`docs/state_machine_migrate/audit/2026-06-12-destructive-cleanup-report.md`.

## API Inventory

| endpoint | caller | old state dependency | migration behavior |
| --- | --- | --- | --- |
| `GET /customers/:id/status-actions` | admin/customer detail compatibility | `customers.status`, `listCustomerStatusActions` | derive from current workflow node/task |
| `POST /customers/:id/status-transition` | admin/customer status panel, possible mini-program compatibility | `resolveCustomerStatusTransition`, `customers.status`, `customer_status_transition_logs` | complete workflow task/node and return old shape + `workflow_state` |
| `GET /customers/:id/status-transitions` | admin customer timeline | `customer_status_transition_logs` | read `workflow_transition_logs` with compatibility mapping |
| `GET /projects/:id/status-actions` | admin/project detail, possible mini-program compatibility | `projects.status`, `listProjectStatusActions` | derive from current workflow node/task |
| `POST /projects/:id/status-transition` | project status panel | `resolveProjectStatusTransition`, `projects.status`, status logs, schedule RPC | complete workflow task/node; special-case project business facts |
| `GET /projects/:id/status-transitions` | admin project timeline | `project_status_transition_logs` | read `workflow_transition_logs` with compatibility mapping |
| `POST /expense-requests/:id/submit` | admin expense panel, possible mobile approval flow | `expense_requests.status/current_step`, approval chain | start or advance expense workflow |
| `POST /expense-requests/:id/approve` | expense approval flow | `current_step`, `expense_request_approval_chains` | complete current approval task with `decision=approved` |
| `POST /expense-requests/:id/reject` | expense approval flow | `current_step`, `expense_request_approval_chains` | complete current approval task with `decision=rejected` |
| `POST /expense-requests/:id/cancel` | expense owner/admin | `status/current_step` | cancel workflow instance and emit cancellation output |
| `POST /expense-requests/:id/pay` | finance payment | `status=approved`, `current_step=payment` | complete payment task |
| `GET /expense-requests/todo` | task center/expense page | `expense_request_approval_chains`, `current_step` | query `workflow_tasks` |

## Risks

| risk | mitigation | owner |
| --- | --- | --- |
| Mini-program old versions still rely on `status_actions` | Keep compatibility fields until orange team confirms rollout | API + mini-program |
| Expense approval chain semantics are richer than current workflow task model | Migrate expense first in staging and compare per-step task counts | API |
| Project schedule RPC updates status, start date, and primary construction manager together | Preserve business fact updates in service transaction before removing RPC | API |
| Removing `status` breaks list filters | Add `workflow_subject_states` and switch read paths before deleting columns | API + admin |
| Workflow runtime currently exposes management endpoints only | Add business subject/task API before mini-program integration | API |
| Destructive cleanup cannot be safely rolled back from migrations alone | Take production backup and store cleanup report before Phase 6 | DevOps/API |
