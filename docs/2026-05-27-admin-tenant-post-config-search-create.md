# Admin 租户侧配置岗位搜索新建合并说明

日期：2026-05-27

## 背景

租户侧组织架构的“配置岗位”弹窗原本同时提供两个输入：

- 新增岗位：用于创建岗位并加入当前部门。
- 搜索岗位：用于过滤已有岗位并勾选。

这两个入口的业务目标高度重叠。租户管理员通常先输入岗位名称，再判断是选择已有岗位还是创建新岗位。拆成两个输入会增加判断成本，也容易在未搜索已有岗位前重复创建。

## 调整内容

`apps/admin/components/organization/department-post-config-dialog.tsx` 已将两个输入合并为一个“搜索或新增岗位”输入。

输入行为：

- 输入内容会实时过滤下方已有岗位列表。
- 点击已有岗位会勾选或取消勾选该岗位。
- 如果输入内容没有同名岗位，会展示“创建并加入当前部门”操作。
- 如果存在同名岗位，不展示创建操作，避免重复岗位。
- 创建成功后继续沿用现有后端语义：新岗位会创建到当前租户部门，并自动进入当前部门岗位配置。

## 保留语义

- 保存部门岗位配置仍由底部“保存”按钮控制。
- 新建岗位仍是即时创建动作，不等同于底部“保存”。
- 创建岗位接口仍使用 `POST /posts`，并提交 `tenant_department_id`。
- 部门岗位规则保存仍使用现有 `PUT /department-post-rules/:department_code`。
- 不改变后端 API、不改变权限点、不改变租户隔离语义。

## 验收点

- “配置岗位”弹窗中只出现一个岗位输入。
- 输入已有岗位名称或编码时，下方列表按输入内容过滤。
- 输入不存在的岗位名称时，可以点击“创建并加入当前部门”。
- 输入与已有岗位同名时，不允许重复创建，只能选择已有岗位。
- 创建岗位后，当前部门已选岗位数量和岗位标签同步更新。
- 保存后关闭弹窗，部门行展示的岗位列表同步更新。
