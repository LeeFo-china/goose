# 多租户阶段 0 双租户测试策略

日期：2026-05-09

## 目标

阶段 2 开始后，必须用双租户数据验证核心隔离。阶段 0 先定义测试结构和断言。

## 测试租户

```text
Tenant A: tenant_a
Tenant B: tenant_b
```

每个租户准备：

- 1 个租户管理员。
- 2 个普通员工。
- 3 个客户。
- 3 个房产。
- 3 个项目。
- 若干项目日志。
- 若干费用申请。

## 核心断言

### 客户

- [ ] A 租户管理员调用 `GET /customers`，只返回 A 客户。
- [ ] A 租户管理员访问 B 客户详情，返回 403 或 404。
- [ ] A 租户员工无法通过搜索手机号查到 B 客户。
- [ ] 同手机号允许在 A/B 租户分别存在。

### 项目

- [ ] A 租户管理员调用 `GET /projects`，只返回 A 项目。
- [ ] A 租户管理员访问 B 项目详情，返回 403 或 404。
- [ ] A 租户创建项目时不能选择 B 客户。
- [ ] A 租户创建项目时不能选择 B 员工作为设计师/监理。

### 员工和组织

- [ ] A 租户管理员调用 `GET /employees`，只返回 A 员工。
- [ ] A 租户管理员不能给员工绑定 B 租户角色。
- [ ] A 租户管理员不能看到 B 租户部门、岗位。

### 小程序客户

- [ ] 客户只命中一个租户时，直接进入该租户客户态。
- [ ] 客户命中多个租户时，返回 `mode = select_tenant`。
- [ ] 客户不命中任何租户时，返回 `mode = platform_visitor`。
- [ ] 客户选择租户后，后端签发带租户上下文的会话。

### 平台超管

- [ ] 平台超管可以访问 `/platform/tenants`。
- [ ] 租户管理员访问 `/platform/tenants` 返回 403。
- [ ] 平台超管查询租户数据必须通过平台接口，不复用普通 admin 查询路径。

## 测试数据注意事项

- A/B 租户使用部分相同手机号，验证租户内唯一。
- A/B 租户使用相同部门 code、岗位 code、角色 code，验证租户内唯一。
- A/B 租户使用相同项目名称，验证搜索隔离。

## 阶段 2 验收要求

阶段 2 完成前，以上核心断言必须通过。
