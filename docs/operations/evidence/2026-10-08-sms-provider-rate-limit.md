# 管理员登录验证码供应商限流排查

## 根因与证据

租户 `8440bb1e-8b6c-44cb-9ef0-5558b0460609` 管理员手机号 `132****5725` 的员工记录归属正确，状态 active，`user_id` 为空、`admin_auth_version=3`。问题发生在发送验证码阶段，并未进入身份绑定。

2026-10-08 生产日志中，10 次 `/admin/auth/send-code` 失败均包含供应商错误：

`ALIYUN_SMS_SEND_FAILED: isv.BUSINESS_LIMIT_CONTROL 触发天级流控Permits:10`

当天短信发送日志记录该号码成功 10 条：后台 `admin_login` 3 条、统一身份登录 `login_identity` 7 条。阿里云拒绝后续请求，应用又将错误包装成 HTTP 500 / `DB_ERROR` / “发送验证码失败”，掩盖了实际限流原因。

## 修复范围

后台和统一身份验证码发送共用错误转换：确认阿里云 `BUSINESS_LIMIT_CONTROL` 后返回 HTTP 429 / `SMS_CODE_PROVIDER_RATE_LIMITED`。天级流控提示“验证码发送已达短信服务每日上限，请等待限流恢复后再试”，其他窗口提示频率上限。不把供应商调试信息返回客户端，不硬编码上限条数或承诺准确恢复时间。

两个入口继续先清理当前发送失败的 pending 验证码，保留清理异常和其他发送异常原有行为。后台代理和登录表单已透传并展示 API 错误，不需要前端变更。

本次不变更手机号、租户、身份、验证码校验、短信额度或阿里云限流配置；不涉及数据库 migration。未向用户发送测试短信，未读取验证码。

## 验证

- 修复前两个入口的回归测试均复现 HTTP 500，断言失败。
- 修复后 4 个测试文件共 28 项通过：管理员发送、统一身份发送、错误转换、换号登录竞态。
- `bun run api:check` 通过：类型检查、API 构建、500 行限制。
- 隔离工作区最初缺少 domain 依赖软链接，引发两份 Zod 类型冲突；补齐与主工作区一致的依赖链接后静态检查通过，无依赖版本或锁文件修改。

## 恢复边界

错误提示修复不能解除供应商限流。号码需等待供应商限流恢复，或由短信账户管理员在阿里云短信控制台调整发送频率；不要持续重试。后台和小程序同一签名发送可能合并计数，租户手机号迁移不清空供应商计数。

参考：[阿里云发送频率与白名单配置](https://help.aliyun.com/zh/sms/user-guide/configure-delivery-frequency-and-whitelist)。本次未调整供应商配置，未加入白名单。
