# 完整业务试用与范围调整验收

## 目标与根因

原范围目录只支持六个 core 模块；营销、财务、采购、库存、内容运营、AI、企业设置路由被明确排除。天喜租户虽拥有 225 项操作权限和有效试用，仍被服务范围检查拦截。超管只能设定六项范围及未来发放策略，不能调整已发放试用。

本次扩展为 13 个明确模块，完整业务是显式范围快照。新建租户开启试用时默认选完整业务，也可自定义；租户列表及试用管理可修改现有试用范围。保留原操作权限、租户隔离、企业核验前置要求及独立计费。未核验企业仍可由超管开通试用；手动新建固定 7 天只读宽限期，期限仍只允许延长。

AI 问答、建议、品牌及进件上传的内部权限检查补齐模块传递；AI 员工调用在请求第三方前检查实时租户范围，流式请求在接管响应前检查。

- Domain 全量：216 通过。
- API 范围、手动建户、版本与审计接口定向回归：203 通过。
- 路由目录、范围传递、旧线索/图库、读写及宽限期：88 通过。
- OCR 配额、授权与服务状态：60 通过；额度不足仍在第三方调用前被拦截。
- AI/上传内部权限传递及缓存场景定向回归：105 通过。员工身份在缓存返回前核验，宽限期缓存读取允许、触发付费生成拒绝。
- 流程费用审批/付款、项目收款、采购审批在实际变更前检查财务/采购模块，保留原有操作权限；4 个直接相关测试文件共 29 项通过。项目预算与收支汇总归属财务模块。
- API 类型检查、构建、500 行文件限制通过。
- Admin 类型检查与生产构建通过；范围管理相关单元/契约：38 通过；6 项浏览器 mock smoke 覆盖完整/自定义、最新版本、冲突重载、重复提交及幂等键变化。
- 真实 SQL 与并发测试（4/4 套件，含 3 套既有试用 SQL 与 3 项并发场景）：新旧 scope、service_role 调用、anon/authenticated 拒绝、平台权限撤回、过期/撤销/转化拒绝、日期保持、原子开户、同键并发一条审计、锁等待跨越到期时拒绝修改。`python3 supabase/tests/full_business_trial_concurrency.py` 退出 0。

SQL 并发测试仅连接 `gooes-manual-trial-db`，克隆独立数据库并在结束时删除。该一次性镜像的 supautils 在权限拒绝场景崩溃，因此测试连接禁用此会话扩展；数据库 ACL/RLS/约束均保留。此环境的 migration ledger 不完整，不能替代生产 migration 对齐验证。

## 发布顺序与回滚边界

先应用兼容 migration `20261008072135_full_business_trial_scope.sql`，不修改任何既有范围；再部署支持 13 项的运行时；最后通过正式超管 API 调整天喜当前试用。其他现有试用不自动扩权。

写入扩展范围后不可退回只识别六项的旧运行时。需要回退时使用新版审计接口收回新增模块或发布向前修复，保留期限、审计与计费记录。

## 验证边界

天喜管理员当前 `user_id` 为空、`admin_auth_version=2`，生产核查不能复用其原登录会话。服务端使用真实员工权限上下文及数据库试用事实验证，未修改登录绑定，完整租户 HTTP 登录验收仍需其重新登录。

开户整请求的丢响应重放存在原有边界：事务已提交后重试会被 slug/手机号唯一检查拒绝；本次不改变开户幂等机制。新的“调整范围”命令具备完整幂等重放。

## 生产结果

待发布后补充不可变候选、迁移、部署及范围变更证据。
