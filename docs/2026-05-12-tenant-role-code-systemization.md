# 租户角色编码系统化说明

日期：2026-05-12

## 背景

租户端新增角色时，角色编码属于系统内部标识，客户不应理解或维护。角色创建应只让客户填写角色名称、状态和说明，编码由后端统一生成。

## 已落地规则

- admin 新增角色弹窗不再展示“角色编码”输入项。
- admin 编辑角色时不允许修改角色编码，仅弱展示已有系统编码。
- API `POST /roles` 支持不传 `code`。
- API 创建租户角色时，如果 `code` 为空，后端生成 `role_${12位随机串}`。
- API `PATCH /roles/:id` 不再接收 `code` 变更，避免角色编码被人工修改后影响权限识别。
- 数据库继续使用 `roles(tenant_id, code)` 唯一约束，平台预置角色编码不受影响。

## Admin 对接

新增角色提交字段：

```json
{
  "name": "财务主管",
  "description": "负责费用审批",
  "status": "active"
}
```

编辑角色提交字段：

```json
{
  "name": "财务主管",
  "description": "负责费用审批与复核",
  "status": "active"
}
```

页面上不要把角色编码设计成客户可填写项。需要展示时，作为系统信息弱化展示。

## 微信小程序 / H5 对接

如果后续小程序或 H5 提供租户角色创建能力：

- 不展示角色编码输入框。
- 创建角色时不要传 `code`。
- 角色列表、员工分配角色等场景继续使用角色 `id`。
- 如需展示角色身份，优先展示 `name`，不要展示 `code`。

## 后端契约

`POST /roles`：

- `name` 必填。
- `status` 可选，默认 `active`。
- `description` 可选。
- `code` 兼容旧客户端可传，但新客户端不应传。

`PATCH /roles/:id`：

- 可更新 `name`、`status`、`description`。
- 忽略 `code` 字段。
