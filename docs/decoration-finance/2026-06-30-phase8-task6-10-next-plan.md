# Phase 8 Task 6-10 财务报表与结账后半段计划

日期：2026-06-30
前置基线：Phase 8 Task 1-5 已合入 `main`，发布后 smoke 通过。

## 目标

补齐月度结账从“可查看、可建快照”到“可管理、可审计、可导出”的后半段能力。

后半段不改变前半段的原则：

- 财务报表只从后端聚合结果读取，不在 Admin 或小程序本地计算。
- 已结账月份的历史快照不能被静默覆盖，后续业务修正必须通过实时数据与快照差异体现。
- 允许有权限人员通过受控流程反结账或补充修正，但必须留痕。
- 列表接口继续分页，报表导出需要有权限点保护。

## Task 6：结账写操作受控 smoke

### 目标

验证结账基础闭环真实可用，但不在真实经营月份上制造不可解释的账务变更。

### 验证对象

- 生成草稿快照。
- 确认结账。
- 反结账必须填写原因。
- 反结账后结账记录状态、原因和时间可追溯。
- 重新读取月度总览时能看到对应结账状态。

### 业务口径

本阶段不做硬锁账。

```text
closed 后不阻止业务单据修正；
报表必须清楚展示实时数据与结账快照的差异；
反结账必须要求权限和原因，并写入审计字段。
```

### 建议 smoke 月份

```text
优先使用无正式经营意义的测试月份，或使用测试租户/测试数据。
```

### 验收

- 生成草稿成功，`status=draft`。
- 确认结账成功，`status=closed`，`closed_at` 和 `closed_by_employee_id` 有值。
- 反结账无原因时被拒绝。
- 反结账有原因时成功，`status=reopened`，`reopen_reason` 有值。
- 本轮 smoke 不修改收款、费用、台账、workflow 或项目状态。

## Task 7：结账快照明细和差异追踪

### 目标

让结账记录不只是保存汇总值，还能解释“当时为什么是这个数”，并在后续业务修正后显示实时值和快照值的差异。

### 建议内容

- 固化 `snapshot_scope`：月份、租户、筛选范围。
- 固化 `snapshot_summary`：收入、支出、毛利、应收、异常数量。
- 增加只读差异计算：当前实时结果与最近结账快照的差异。
- Admin 展示“实时值 / 快照值 / 差异”。
- 不回写业务事实，不覆盖已结账快照。

### API 建议

`GET /finance/reports/monthly-overview` 的 `closing` 中增加：

```json
{
  "snapshot_summary": {},
  "difference_summary": {}
}
```

### 验收

- 创建草稿和确认结账时均有快照。
- 已结账后打开报表能看到快照摘要。
- 若结账后业务数据变化，再次查看能看到实时数据与快照差异。

## Task 8：报表导出

### 目标

提供月度财务报表导出能力，先做 CSV，后续再扩展 XLSX。

### 建议接口

```http
GET /finance/reports/monthly-overview/export?month=YYYY-MM&format=csv
```

权限：

```text
finance.reports.export
```

导出内容建议包含：

- 月度经营总览。
- 结账状态。
- 收入、支出、毛利。
- 应收、已收、未收、逾期。
- 对账异常数量。
- 生成时间和导出人。

### 验收

- 无权限不能导出。
- CSV 文件能被 Excel/WPS 打开。
- 金额字段不丢精度。
- 导出结果和页面当前筛选一致。

## Task 9：专项报表

### 目标

把当前月度总览拆成可继续 drill-down 的专项报表。

### 建议拆分

1. 项目经营排行：
   - 按项目展示收入、支出、毛利、毛利率、未收、异常数量。
2. 成本分类报表：
   - 按成本分类展示支出金额、占比和未归集金额。
3. 应收账龄报表：
   - 按账龄区间展示未收、逾期和项目数量。

### 验收

- 所有列表接口分页。
- 默认 `pageSize=20`，最大不超过 `100`。
- 排序和筛选由后端执行，不在前端本地过滤当前页。
- Admin 页面只渲染后端结果。

## Task 10：结账后修正审计闭环

### 目标

让结账后的反结账和修正动作进入审计视图，避免“改了账但不知道谁改的”。

### 建议能力

- 反结账必须填写原因。
- 修正动作关联结账期间。
- 修正审计列表支持按 `month`、`operation`、`operator` 查询。
- Admin 结账记录能跳转到相关修正审计。

### 验收

- 反结账原因可追溯。
- 结账期间发生的修正动作可查。
- 重新结账后快照更新。
- RAG 文档记录最终契约和 smoke 结果。

## Admin 对接

Admin 需要继续承接 Task 6-10：

- 报表页展示结账状态、快照摘要和实时差异。
- 结账操作按钮按后端权限和状态展示。
- 导出入口只在有 `finance.reports.export` 时显示。
- 专项报表用 tab 或二级区域承载，不把财务逻辑写到前端。
- 反结账弹窗必须要求填写原因。

## 小程序边界

当前阶段小程序无必改。

小程序端不应该接入：

- 结账。
- 反结账。
- 报表导出。
- 财务台账扫描。
- 利润本地计算。

如果后续需要让工程或业务人员感知锁账状态，建议后端只读返回：

```json
{
  "finance_period": {
    "month": "2026-06",
    "status": "closed",
    "status_label": "已结账",
    "snapshot_at": "2026-06-30T18:00:00.000Z",
    "has_snapshot_difference": true
  }
}
```

小程序只展示提示，例如：

```text
该月份已有财务结账快照，最新财务数据以后台报表为准。
```

小程序不得根据日期、本地状态或项目阶段自行判断月份结账状态或财务差异。
