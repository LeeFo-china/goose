# 多租户改造阶段 2 Todo：核心业务隔离

日期：2026-05-09

## 目标

完成客户、项目、员工、组织权限的租户隔离。确保 A 租户无法通过列表、详情、ID 参数、搜索、分页等方式访问 B 租户数据。

## 前置条件

- 阶段 1 完成。
- `AuthContext.tenantId` 已稳定可用。
- 核心接口性能基线已记录。
- 已准备 A/B 双租户测试数据。

## Todo

### 1. Repository 规范

- [ ] 核心 repository 方法必须显式接收 `tenantId`。
- [ ] `tenantId` 缺失时直接抛业务错误。
- [ ] service 不再直接拼核心业务表查询。
- [ ] controller 不直接访问核心业务表。
- [ ] 平台级查询必须走 `/platform/*` 或显式 `bypassTenantScope`。

### 2. 客户模块

- [x] 客户列表加 `tenant_id` 过滤。
- [x] 客户详情加 `tenant_id` 校验。
- [x] 客户创建自动写入当前 `tenant_id`。
- [x] 客户更新校验数据属于当前租户。
- [x] 客户手机号唯一规则改为租户内唯一。
- [x] 客户搜索、筛选、分页全部带租户条件。
- [x] 客户房产查询带租户条件。

### 3. 项目模块

- [x] 项目列表加 `tenant_id` 过滤。
- [x] 项目详情加 `tenant_id` 校验。
- [x] 项目创建自动写入当前 `tenant_id`。
- [x] 项目更新校验数据属于当前租户。
- [x] 项目关联客户时校验客户属于当前租户。
- [x] 项目关联房产时校验房产属于当前租户。
- [x] 项目成员、设计师、监理选择只返回当前租户员工。
- [ ] 项目统计接口按租户统计。

### 4. 员工与组织

- [x] 员工列表加 `tenant_id` 过滤。
- [x] 员工详情加 `tenant_id` 校验。
- [x] 员工创建自动写入当前 `tenant_id`。
- [x] 部门、岗位、角色增加租户过滤。
- [x] `roles.code` 调整为租户内唯一。
- [x] `departments.code` 调整为租户内唯一。
- [x] `posts.code` 调整为租户内唯一。
- [x] 员工角色分配只能使用当前租户角色。

### 5. 权限体系

- [ ] `permissions` 保持全局。
- [x] `roles` 租户化。
- [x] `role_permissions` 租户化或通过 role 归属租户约束。
- [x] `employee_roles` 租户化或通过 employee/role 双向校验。
- [ ] 区分平台超管与租户管理员。
- [ ] 当前 `system_admin` 行为收敛为租户管理员，平台超管另建角色或机制。

### 6. 双租户集成测试

- [ ] 创建租户 A/B。
- [ ] A/B 各创建员工、客户、项目。
- [ ] 使用 A 员工 token 调用客户列表，只返回 A 数据。
- [ ] 使用 A 员工 token 访问 B 客户详情，返回 403 或 404。
- [ ] 使用 A 员工 token 调用项目列表，只返回 A 数据。
- [ ] 使用 A 员工 token 访问 B 项目详情，返回 403 或 404。
- [ ] 使用 A 管理员 token 调用员工列表，只返回 A 员工。
- [ ] 使用租户管理员 token 访问平台接口，返回 403。

### 7. 性能对比

- [ ] 使用阶段 0 相同压测脚本重测核心接口。
- [ ] 对比 P95/P99。
- [ ] 响应时间增加不超过 10%。
- [ ] 检查数据库慢查询。
- [ ] 不达标时补充索引：
  - `(tenant_id, created_at)`
  - `(tenant_id, status)`
  - `(tenant_id, owner_id)`
  - `(tenant_id, customer_id)`
- [ ] 未达标不得进入阶段 3。

## 验收标准

- [ ] 客户、项目、员工三大模块完成租户隔离。
- [ ] 详情接口不能跨租户访问。
- [ ] 创建数据自动归属当前租户。
- [ ] 双租户集成测试通过。
- [ ] 性能对比达标。
- [ ] 直接核心表查询风险清单已清零或明确例外。
