# Admin 拆分后回归巡检记录

日期：2026-05-31

## 背景

`apps/admin` 超 500 行文件拆分已完成，本次巡检用于确认拆分后的关键页面入口、弹窗字段、列表字段和基础 API 访问路径没有明显回归。

## 巡检范围

已自动化覆盖：

- 登录后进入组织架构，并打开“配置岗位”弹窗。
- 项目页打开“新增项目”弹窗，确认客户、设计师、工程负责人字段存在。
- 员工页打开“新增员工”弹窗，确认姓名、手机号、部门字段存在。
- 员工页打开“配置员工角色”弹窗，确认保存角色入口存在。
- 权限点页确认权限、模块、资源、动作、状态字段展示。
- 费用审批页确认申请、处理人、操作字段展示；有可用操作时确认操作菜单可打开。
- 营销 H5 tab 打开“新建 H5 页面”弹窗，确认 AI、标题、描述、展示场景字段存在。

未做破坏性操作：

- 不创建项目、员工、权限、H5 页面。
- 不审批、驳回、撤回、打款费用申请。
- 不保存部门岗位配置。

## 当前数据限制

- 费用审批当前数据中存在已完成记录，操作按钮可能处于禁用状态；因此 E2E 只验证列表和可用菜单入口，不强依赖详情接口成功打开。
- 租户管理员权限点页当前只展示定义列表，不开放权限定义新增/编辑操作；因此 E2E 验证字段展示，不覆盖 `PermissionDialog` 的提交。
- 当前租户 H5 活动页数量可能为 0；因此 E2E 覆盖新建弹窗，不覆盖已有 H5 编辑页。

```bash
pnpm admin:check
pnpm --dir apps/admin build
pnpm --dir apps/admin test:e2e
git diff --check
```

## 后续建议

- 后续如要覆盖费用详情、审批、H5 编辑页，应先准备稳定测试数据或测试种子。
- 权限定义新增/编辑如只允许平台超管，应单独补平台超管 E2E 身份。
- 复杂保存链路建议用专用测试租户执行，避免污染当前业务数据。
