# 阶段 4A 小程序/H5 对接说明：营销/H5 租户化清点

日期：2026-05-09

## 1. 当前阶段结论

阶段 4A 只做后端清点和执行拆分，没有改变小程序接口。

小程序端暂时不需要改代码。

## 2. 后续需要小程序对接的阶段

### 阶段 4C：H5 公开链路租户化

预计影响：

- H5 session token 可能增加 `tenant_id`。
- 活动列表接口会按当前客户/员工所属租户返回活动。
- H5 提交线索仍然通过 slug，后端会从 page 反推租户。

小程序端原则：

- 不要自己拼 `tenant_id`。
- 打开 H5 时继续传当前登录态/短期 token。
- 使用后端返回的活动 `slug`、`description`、`url` 生成入口。

### 阶段 4D：客户登录态分支

客户手机号登录后可能出现三种模式：

```json
{
  "mode": "customer",
  "tenant_id": "xxx",
  "customer_id": "xxx"
}
```

```json
{
  "mode": "select_tenant",
  "tenants": []
}
```

```json
{
  "mode": "platform_visitor"
}
```

小程序需要准备：

- `customer`：进入现有客户首页。
- `select_tenant`：展示装修公司选择页。
- `platform_visitor`：展示平台访客页，引导提交装修需求。

### 阶段 4F：员工拓客直绑定

员工分享小程序码或 H5 链接时，会携带：

```text
share_token
```

小程序需要：

- 启动时识别并缓存 `share_token`。
- 登录/注册时带回后端。
- 不自行判断租户归属，由后端通过 `share_token` 绑定。

## 3. 当前不需要做的事

- 不需要在小程序端硬编码租户。
- 不需要小程序端维护 H5 页面归属关系。
- 不需要小程序端处理平台线索分配。

## 4. 联调关注点

阶段 4C 后：

- 同一个小程序账号在不同装修公司下登录，活动列表应不同。
- H5 表单提交后，线索应进入对应装修公司的 admin。
- H5 已提交状态仍应按 slug + 手机号正常生效。

阶段 4D 后：

- 未归属客户登录后不应进入任意装修公司客户首页。
- 命中多家公司时必须展示公司选择，不应默认进入第一家公司。
