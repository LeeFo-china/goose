# 阶段 0 Admin 对接文档：多租户规划与防护

日期：2026-05-09

## 阶段结论

阶段 0 不要求 admin 端改代码。当前阶段只完成规划、清单、风险扫描和后续对接边界。

## Admin 后续影响范围

阶段 1 起 admin 需要关注：

- 登录态返回 tenant 信息。
- 顶部或用户菜单展示当前公司名称。
- 租户停用时展示提示并阻止继续操作。
- 平台超管与租户管理员入口区分。

阶段 2 起 admin 需要关注：

- 客户、项目、员工页面不传 `tenant_id`。
- 后端通过登录态自动过滤租户数据。
- 页面上不暴露跨租户切换入口。

阶段 4 起 admin 需要关注：

- “老客户新线索”标记。
- “平台新线索”标记。
- 客户详情“线索来源时间线”。

阶段 5 起 admin 需要新增：

- `/platform/tenants`
- `/platform/leads`
- 平台线索分配操作。

## 阶段 0 对接动作

- [ ] 产品确认 admin 顶部公司名称展示位置。
- [ ] 产品确认“老客户新线索”在客户列表还是线索列表展示。
- [ ] 产品确认平台超管菜单信息架构。
- [ ] 研发确认普通 admin 页面不允许接收前端传入的 `tenant_id`。

## 当前不需要改动

- 不改 admin 登录页。
- 不改客户/项目/员工页面。
- 不改 H5 页面编辑器。
- 不新增平台超管页面。

## 后续接口预期

阶段 1 后，`/admin/auth/me` 建议返回：

```json
{
  "tenant": {
    "id": "tenant-id",
    "name": "某某装饰",
    "slug": "demo",
    "status": "active"
  }
}
```

admin 只读取展示，不把该 `tenant.id` 回传作为业务接口过滤条件。
