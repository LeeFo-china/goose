# 阶段 1 微信小程序对接文档：租户上下文预留

日期：2026-05-09

## 背景

后端已引入默认租户和员工登录租户上下文。阶段 1 不要求小程序立即改 UI，也不要求小程序传 `tenant_id`。

## 小程序本阶段需要做什么

本阶段无需改动生产交互。

小程序端需要注意：

- 不要在请求参数里主动传 `tenant_id`。
- 后端会从登录态识别租户。
- 客户多租户选择、平台访客态、员工分享直绑定会在后续阶段单独对接。

## 后续可能新增的登录态字段

员工端或客户侧后续登录响应可能增加：

```json
{
  "tenant": {
    "id": "tenant-id",
    "name": "装修公司名称",
    "slug": "tenant-slug",
    "status": "active"
  }
}
```

小程序可以先按可选字段处理：

- 有 `tenant.name` 时，可在“我的”或项目详情中展示所属公司。
- 没有 `tenant` 时，不影响现有流程。

## 后续阶段重点

- 阶段 2：客户、项目、房产、员工接口会开始按租户隔离。
- 阶段 4：客户未命中任何装修公司时进入平台访客态。
- 阶段 4：客户命中多家公司时进入公司选择页。
- 阶段 4：员工分享小程序码/H5 链接会携带租户参数，客户登录后直绑定目标租户。
