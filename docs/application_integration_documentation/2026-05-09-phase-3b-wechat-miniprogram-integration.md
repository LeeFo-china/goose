# 阶段 3B 微信小程序对接说明：施工日志租户隔离

日期：2026-05-09

## 结论

小程序端无需新增 `tenant_id` 参数。员工端和客户侧施工日志接口均由后端按登录态和项目归属自动隔离。

## 受影响入口

- 员工端项目详情施工日志列表
- 员工端新增 / 编辑施工日志
- 员工端日志评论
- 客户端项目详情施工日志列表
- 客户端施工日志评论与评分
- 客户首页最近日志摘要
- 客户分享施工日志活动

## 行为变化

### 员工端

- `GET /project-logs/projects?project_id=...` 只返回当前租户项目日志。
- `POST /project-logs` 不需要传 `tenant_id`，后端自动继承项目租户。
- `GET /project_log_comments?log_id=...` 只返回该日志所属租户评论。
- `POST /project_log_comments` 评论自动继承日志租户。

### 客户端

- `GET /customer/projects/:id/logs` 只返回该客户项目所属租户日志。
- `GET /customer/projects/:id/logs/:logId/comments` 只返回该客户项目所属租户评论。
- 客户评分去重只在当前租户日志评论内生效。

## 小程序端建议

- 不要缓存跨账号的施工日志、评论和评分状态。
- 客户多租户能力完全落地前，如果同一个微信账号绑定多个客户档案，后端仍会提示联系管理员处理。
- 如果客户看不到日志，优先检查客户档案和项目归属是否一致。

## 联调检查

- A 租户员工新增日志后，A 租户客户可见。
- B 租户员工和客户都不可见 A 租户日志。
- 客户评论后，评论只出现在同租户日志下。
- 客户首页最近日志摘要不混入其他租户项目日志。
