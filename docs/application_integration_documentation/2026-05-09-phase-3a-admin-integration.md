# 阶段 3A Admin 对接说明：费用审批与任务中心租户隔离

日期：2026-05-09

## 结论

本阶段 admin 端无需改接口路径和请求参数。登录态中已有租户上下文后，后端会自动按当前租户过滤费用申请、费用分类和任务中心待办。

## 受影响页面

- `/expenses`
- 首页 / dashboard 的任务中心摘要
- 费用申请详情、审批、驳回、撤回、打款相关交互
- 费用分类配置相关交互

## 行为变化

### 费用申请

- `GET /expense-requests` 只返回当前租户费用申请。
- `GET /expense-requests/:id` 不能读取其他租户费用申请。
- 创建费用申请时，后端自动写入当前租户。
- 关联项目只能使用当前租户项目。
- 审批候选人只能来自当前租户员工。
- 审批、驳回、撤回、打款操作只能作用于当前租户费用申请。

### 费用分类

- `GET /expense-request-categories` 只返回当前租户分类。
- 分类 `code` 和 `name` 现在是租户内唯一，不再是全平台唯一。
- 创建分类时后端自动写入当前租户。

### 任务中心

- `GET /task-center/todos`
- `GET /task-center/todos/summary`

以上接口只聚合当前租户的数据：

- 客户跟进待办只来自当前租户客户。
- 项目日志待办只来自当前租户项目。
- 费用待办只来自当前租户费用申请。

## Admin 端建议

- 不需要在请求里额外传 `tenant_id`。
- 不要在前端缓存跨租户共享的费用分类列表。
- 如果后续增加“切换租户”能力，切换后需要清空费用分类、费用列表、任务中心摘要的本地缓存并重新请求。

## 联调检查

- A 租户登录 `/expenses`，不能看到 B 租户费用申请。
- A 租户新建费用申请，项目选择器只能选择 A 租户项目。
- A 租户审批候选人搜索不到 B 租户员工。
- A 租户首页任务中心不能出现 B 租户客户、项目、费用待办。
