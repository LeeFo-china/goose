# 阶段 2 Admin 对接文档：核心业务租户隔离

日期：2026-05-09

## 变更摘要

后台核心业务接口已开始按登录员工所属租户过滤数据。

涉及页面：

- 客户列表 / 客户详情
- 项目列表 / 项目详情
- 新建项目客户选择器
- 新建项目成员选择器
- 员工列表 / 员工详情
- 房产列表 / 房产详情

## Admin 前端是否需要传 tenant_id

不需要。

前端继续保持现有请求方式，后端会从登录 token 对应的 `AuthContext.tenantId` 自动识别租户。

前端不要新增：

```text
tenant_id
tenantId
X-Tenant-ID
```

## 行为变化

### 客户

- 列表只返回当前公司客户。
- 详情访问其他公司客户会返回 403/404。
- 新建客户自动归属当前公司。
- 同一手机号允许存在于不同公司，但同一公司内仍不允许重复。

### 项目

- 列表只返回当前公司项目。
- 新建项目时，客户、房产、设计师、监理必须属于当前公司。
- 项目选择员工接口只返回当前公司员工。

### 员工

- 员工列表只返回当前公司员工。
- 新建员工自动归属当前公司。
- 更新或删除其他公司员工会返回 403/404。

### 房产

- 房产列表只返回当前公司房产。
- 创建房产时，关联客户必须属于当前公司。

## 前端建议

- 原页面无需增加租户选择器。
- 接口返回空列表时仍按原空状态展示。
- 如果接口返回“客户不存在或不属于当前租户”“项目不存在或不属于当前租户”，前端统一按无权限或数据不存在处理。
- 当前公司名称继续从阶段 1 的 `session.tenant.name` 展示。

## 联调重点

- 使用 A 公司账号看不到 B 公司客户。
- 使用 A 公司账号不能通过 URL 直接打开 B 公司客户详情。
- 使用 A 公司账号新建项目时，客户和员工选择器不出现 B 公司数据。
- 同一个手机号在 A/B 公司分别创建客户时，数据库不再因全局唯一索引报错。
