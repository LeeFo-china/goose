# 阶段 2 微信小程序对接文档：核心业务租户隔离

日期：2026-05-09

## 变更摘要

后端已开始按登录态识别租户并过滤核心业务数据。小程序端本阶段原则上不需要传 `tenant_id`。

## 小程序端请求规则

继续使用现有登录 token 请求接口。

不要在请求参数中主动传：

```text
tenant_id
tenantId
X-Tenant-ID
```

租户由后端根据登录态识别。

## 可能感知到的变化

### 客户端

- 客户登录后只能看到当前绑定公司下的项目、房产、验收等数据。
- 如果同一手机号未来绑定多家公司，后续阶段会提供“选择公司”的小程序交互，本阶段尚未开启。

### 员工端

- 员工端客户列表、项目列表、员工选择器只返回当前公司数据。
- 如果扫码或链接来自其他公司，后续阶段会通过分享参数直绑定目标租户，本阶段尚未开启。

## 错误处理建议

如果接口返回：

```text
客户不存在
项目不存在
无权限
缺少租户上下文
```

小程序端建议统一展示：

```text
暂无权限查看该数据
```

并提供返回上一页。

## 后续阶段

阶段 4 会新增小程序端需要重点对接的交互：

- 客户未命中任何公司时进入平台访客态。
- 客户命中多家公司时展示公司选择页。
- 员工分享小程序码/H5 链接携带租户参数，客户登录后直绑定目标公司。
