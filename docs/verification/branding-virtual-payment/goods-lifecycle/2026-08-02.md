# 微信虚拟商品生命周期验证记录

日期：2026-08-02

仓库：`gooes`

分支：`feat/virtual-payment-goods-lifecycle`

## 验证范围

本次验证覆盖品牌权益数字商品的配置、上传、发布和微信状态校验闭环：

- 商品配置新增稳定 HTTPS JPG/PNG 图片地址 `item_url`。
- 上传、发布均由超管显式确认触发，不在保存、查询或普通校验时自动执行。
- 上传和发布任务状态支持只读查询及前端有界轮询。
- 普通校验精确区分上传任务缺失、上传处理中、发布任务缺失和发布处理中。
- 生命周期动作使用配置版本进行并发保护，审计信息不包含 AppKey、access token 或微信原始错误详情。

不覆盖真实微信商品上传和发布。本轮没有调用 `goods/upload` 或 `goods/publish`，避免在验证阶段产生外部写操作。

## 根因与修复边界

原流程只能查询和校验微信商品状态，缺少图片地址、上传命令、发布命令及任务状态编排，因此微信返回任务处理中时，Admin 无法判断当前阶段，也无法在统一配置页面完成后续操作。

本次在既有支付配置边界内补齐三步流程：上传商品、发布商品、校验状态。独立微信支付商户号及普通支付能力未调整，继续用于后续平台自营实物商城和其他符合普通支付规则的交易。

## API 只读 smoke

在隔离端口启动本分支 API 后，使用开发超管会话请求配置快照和两个环境的 `goods-status`。三个请求均进入路由，但读取现有加密系统配置时返回：

```text
CONFIG_SECRET_DECRYPT_FAILED
```

对应 Request-ID 为 `req-2`、`req-3`、`req-4`。根目录 `.env` 未提供运行中开发环境使用的系统配置主密钥，因此本地进程无法解密已有配置。本次没有伪造密钥、清空配置或绕过解密。

合并并部署开发环境后，需使用服务器正确密钥补做以下只读 smoke：

1. 配置快照包含 `item_url`。
2. test 与 production 的 `goods-status` 返回当前真实任务状态。
3. 未上传时普通校验返回上传任务缺失；上传完成但未发布时返回发布任务缺失。
4. 全程不得通过 smoke 调用上传或发布动作。

## 安全与后续事项

- 本轮未触发任何真实微信上传、发布或其他外部写操作。
- 前端只展示服务端允许的错误码和安全消息，不透传微信原始响应。
- 生命周期动作仍要求平台支付配置写权限，并使用当前配置版本做并发校验。
- 既有 Supabase advisory 显示 `customer_wechat_pay_smoke_notifications` 和 `customer_wechat_pay_smoke_orders` 未启用 RLS。该问题与本功能无关，且需要先设计策略，不能在本变更中直接开启；应作为独立安全任务处理。
