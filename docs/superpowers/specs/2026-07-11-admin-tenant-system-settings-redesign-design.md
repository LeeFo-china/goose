# Admin 租户系统配置页重构设计

## 背景

当前 `/settings` 同时承载平台系统配置与租户系统配置。页面采用面向平台管理员的高密度配置框架，包含多项统计徽章、多分组导航、敏感项提示和平台配置语义。租户模式实际主要维护短信服务与客服入口，共用平台框架会增加理解成本，也让租户用户难以快速判断“需要配置什么”和“当前是否可用”。

本次只重构租户侧体验。平台模式继续使用现有页面结构、配置分组、支付配置与测试工具，避免租户体验优化影响平台运维能力。

## 目标

- 让租户管理员进入页面后快速识别可配置的业务能力及当前状态。
- 让用户先完成高层选择，再按需展开必要参数。
- 减少平台运维术语、冗余统计和装饰性容器。
- 保持现有保存接口、权限边界、配置继承语义和 URL 分组状态不变。
- 在桌面和移动端提供清晰、可访问、可恢复的编辑体验。

## 非目标

- 不重构平台系统配置页。
- 不修改后端接口、数据库结构、配置键或租户权限模型。
- 不改变短信通道切换时立即保存的现有行为。
- 不新增依赖、设计系统或全局主题。
- 不把多个配置项改为批量提交。

## 设计方向

设计语言为简约、专业、任务优先的后台产品界面。沿用 Gooes Admin 的暖白工作台、黑色主操作和克制的黄色焦点色，不使用营销式标题、渐变、玻璃效果、装饰动画或嵌套卡片。

设计参数：

- 变化度：4。采用稳定双栏结构，通过留白、分隔线和状态层级建立秩序。
- 动效强度：2。仅保留控件现有的悬停、焦点和保存反馈。
- 信息密度：6。配置说明完整，但不展示与租户任务无关的平台统计。

## 信息架构

### 页面头部

租户模式使用紧凑标题区：

- 标题：`租户系统配置`
- 说明：`管理本租户使用的短信服务和客服入口。平台密钥及模板不会在租户侧展示。`
- 状态摘要：只展示需要用户处理的未配置分组数量；全部完成时显示“配置已就绪”。

移除租户模式下的配置项总数、租户覆盖数、继承平台数、未配置项总数和敏感项数量等平台化统计。平台模式保留现有头部统计。

### 双栏设置工作台

桌面端使用一个顶层 `Card`，内部由边框分成两栏，不嵌套额外卡片：

- 左栏宽约 14rem，包含分组名称、简短说明、配置数量和完成状态。
- 右栏包含当前分组标题、状态摘要和编辑内容。
- 当前分组通过文字权重、浅色背景和左侧图标强调，不使用阴影卡片或粗重边框。
- URL 继续使用 `?group=<code>`，刷新和分享后保留当前分组。

移动端将左栏转换为顶部横向可滚动标签；标签保持单行，不缩小到 14px 以下。内容区为单列，操作按钮在窄屏下保持可点击并允许换行布局。

### 租户分组

租户模式为每个已返回的分组提供清晰元数据。已知分组使用业务化描述：

- 短信配置：选择平台统一通道或租户自有通道。
- 客服配置：维护客户可见的客服入口与联系方式。

未知分组使用通用说明，不暴露内部配置键作为导航文案。分组是否完成由现有 `source === "empty"` 计算，状态同时使用文字和图标表达，不能只依赖颜色。

## 交互设计

### 分组导航

- 使用 shadcn `Tabs` 保持键盘导航和当前状态语义。
- 切换分组时继续通过 `router.replace` 更新查询参数，不滚动页面。
- 路由更新期间禁用重复切换，并在当前项显示轻量加载状态。
- 未配置分组显示“待完善 N 项”；完整分组显示“已完成”。

### 短信服务

右侧先展示“短信发送通道”设置：

- 继承平台短信通道
- 自有阿里云短信通道
- 自有腾讯云短信通道

保持现有选择后立即保存行为。保存期间禁用选择控件，成功或失败信息紧邻通道设置展示。

选择继承平台时，只展示简洁说明，明确服务商、签名、模板和密钥由平台维护，租户无需操作。

选择自有通道时，展示对应服务商所需参数。配置项沿用现有 `SettingEditor` 的逐项保存、重置、敏感值输入和错误反馈能力，不展示另一服务商的字段。

### 客服及其他普通分组

普通分组使用扁平配置列表。每项包含：

- 业务名称和必要说明
- 当前来源或继承状态
- 输入控件及帮助文本
- 重置与保存操作
- 就近的保存成功或错误反馈

配置键作为次要技术信息保留，但弱化显示，不与业务名称竞争。

## 组件边界

### `SettingsPage`

- 继续负责会话、数据请求、模式判断和分组排序。
- 平台模式继续渲染现有平台头部与 `SettingsTabs`。
- 租户模式渲染新的租户头部与 `TenantSettingsWorkspace`。

### `TenantSettingsWorkspace`

- 仅负责租户模式的导航、URL 分组同步、响应式布局和分组状态展示。
- 接收已经排序的 `SettingsGroup[]`，不重新请求数据。
- 根据当前分组调用短信专用面板或普通配置列表。

### `TenantSmsSettingsPanel`

- 从现有共享组件中提取并保持现有业务行为。
- 负责短信通道模式、供应商字段过滤、即时保存和反馈。
- 不读取或展示平台密钥值。

平台模式继续使用现有 `SettingsTabs`、平台支付配置和平台测试工具。本次不复制平台业务逻辑。

## 数据流与状态

1. 服务端页面获取会话、访问令牌和系统配置。
2. 服务端通过 `isPlatformOnlySession` 判断模式。
3. 租户模式把已排序分组与统计结果传给 `TenantSettingsWorkspace`。
4. 客户端工作台从查询参数解析当前分组，无效参数回退到首个分组。
5. 切换分组只更新 URL，不重新提交配置。
6. 保存继续调用现有 `updateSetting`，成功后 `router.refresh()` 获取服务端权威数据。

## 异常、空状态与加载状态

- 页面级加载失败继续使用 `StatusAlert`，显示在头部与工作台之间。
- 无配置分组时，顶层工作台显示明确空状态：“当前租户暂无可维护的系统配置”，不渲染空导航。
- 分组为空时显示该分组暂无配置项，不产生空白页面。
- 保存失败保留用户输入并就近显示错误，允许再次提交。
- 保存中禁用相关控件，避免重复提交。
- 路由 `loading.tsx` 与租户双栏结构保持相同骨架，减少加载完成时的布局跳动。

## 可访问性

- 保留 `Tabs`、`Select`、`Field`、`Button` 等 shadcn/Radix 语义组件。
- 分组导航提供可读的 `aria-label`。
- 状态同时提供文字与图标，不只使用颜色。
- 所有表单控件保留可见标签、帮助文本、焦点环和禁用状态。
- 图标仅用于辅助识别，装饰图标设置 `aria-hidden`。
- 正文与辅助文字使用现有语义色，满足项目 WCAG AA 导向。

## 验证策略

### 自动化验证

- 为租户工作台补充源代码契约测试，证明租户模式使用专用工作台且平台模式仍使用现有组件。
- 覆盖租户头部不再渲染平台化统计，以及短信与客服分组文案。
- 运行相关 Bun 测试、`pnpm --dir apps/admin check` 和管理端构建。

### 浏览器验证

- 使用租户账号打开 `/settings`，确认默认分组、URL 切换和刷新恢复。
- 验证继承平台、自有阿里云、自有腾讯云三种短信状态。
- 验证普通配置项的修改、重置、保存成功、保存失败和禁用状态。
- 检查桌面双栏、平板布局和移动端横向标签。
- 检查空状态、加载骨架、长中文文案、键盘导航与可见焦点。
- 确认平台账号打开 `/settings` 时页面功能与原有结构不受影响。

## 完成标准

- 租户侧使用独立、紧凑的双栏设置工作台。
- 租户头部不再展示平台化统计和敏感项指标。
- 短信通道遵循渐进披露，仅展示当前选择需要的参数。
- 客服及普通配置保持可理解、可保存、可恢复。
- 平台侧配置页功能和信息结构保持不变。
- 自动化检查、类型检查、构建和浏览器关键路径验证均有通过证据。
