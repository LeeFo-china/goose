# Admin AI 模型路由交互重整设计

**日期：** 2026-09-12

**状态：** 已确认

**范围：** Gooes 超管后台、AI 配置 API、Supabase migration

**不包含：** Anthropic Format、Anthropic SDK、生产发布、付费生图验证、orange 仓库修改

## 1. 背景与目标

当前 AI 模型路由后台存在以下结构性问题：

- 供应商表单仍可维护连接信息，但模型维护组件已经与主页面脱节，管理员无法形成“供应商下维护模型”的完整操作路径。
- 模型创建仍要求用户填写内部编码，混淆了系统身份与供应商调用名称。
- 新增场景路由只能选择固定系统场景，现有数据库注册表和策略明确禁止创建自定义场景。
- 模型候选加载失败、无远端目录和候选为空被混在一起，管理员无法判断下一步操作。
- `runtime_status=not_connected` 会锁住模型配置区域，导致“装修生图”即使已经准备好供应商和模型，也无法提前完成路由配置。
- OpenAI Compatible 供应商并不必然提供可发现的 `/models` 接口，当前产品不能把无目录能力伪装成空列表，也不能猜测第三方接口。

本次目标是将页面收敛为两套清晰心智模型：

1. 在“供应商”Tab 中维护供应商连接及其模型清单。
2. 在“场景路由”Tab 中创建系统或自定义场景路由，并按“供应商 → 模型”选择主备模型。

成功标准：超管可以在不手工填写任何内部编码的前提下，完成火山方舟供应商、图片模型和装修生图路由配置；远端目录不可用时仍可通过明确的手动入口完成配置。

## 2. 方案选择

### 2.1 采用方案：供应商主从结构

保留“场景路由”和“供应商”两个主 Tab。供应商 Tab 使用左侧列表、右侧详情的主从结构；右侧详情包含连接配置和当前供应商模型清单。

采用原因：

- 供应商与模型从属关系清晰。
- 两个 Tab 可以覆盖完整操作，不需要在三个页面之间往返。
- 能复用现有 Provider、Model、Route 数据实体和 shadcn/ui 组件。
- 改动集中在现有 AI 配置边界，不引入新的后台信息架构。

### 2.2 未采用方案

- 独立“模型”Tab：适合跨供应商批量管理，但会拆散当前最常用的连接配置链路。
- 新建路由向导：首次使用引导更强，但重复维护、批量检查和错误恢复更复杂。

## 3. 领域边界与系统编码

### 3.1 供应商

用户维护：

- 供应商名称
- 协议类型
- Endpoint
- 密钥配置引用
- 状态
- 排序

本轮协议类型只包含：

- `openai_compatible`
- `openrouter`

所有新供应商的系统编码由服务端生成，格式为 `prv_` 加不带连字符的小写 UUID。现有供应商编码原样保留。创建和修改请求均不接受用户提供的编码，数据库拒绝更新编码。

`endpoint_url` 的产品语义统一为协议 Base URL。兼容层只识别并在内存中剥离现有值末尾的标准 `/chat/completions` 或 `/images/generations` 路径，migration 不重写历史 Endpoint；新保存值统一规范化为 HTTPS Base URL。Gateway 按协议和输出模态追加 `/chat/completions` 或 `/images/generations`，页面和 controller 不拼接推理路径。无法归一化的历史地址返回明确配置错误，不猜测第三方路径。

### 3.2 模型

用户维护：

- 模型名称
- 供应商调用名称 `model_name`
- 输出模态 `modality`
- 输入模态 `input_modalities`
- 状态
- 排序

所有新模型的系统编码由服务端生成，格式为 `mdl_` 加不带连字符的小写 UUID。通过手动输入或远端目录物化的模型使用相同规则。现有模型编码原样保留。

系统编码与供应商调用名称必须保持独立。调用火山方舟时发送 `doubao-seedream-5-0-pro-260628` 这类 `model_name`，内部日志、关联和审计使用系统编码。

数据库以“供应商 ID + 调用名称 + 输出模态”作为模型业务唯一键，避免手动输入重复创建。模型编码创建后不可修改。模型模态如已被路由引用则不可直接修改；管理员应新建正确模态的模型或先解除引用。

### 3.3 场景库

现有 `ai_system_scenes` 在本轮扩展为统一场景注册表，保留表名以降低迁移风险。场景来源增加为：

- `system`：代码库登记的系统场景。
- `custom`：超管创建的自定义场景。
- `legacy`：历史未知路由的兼容记录。

自定义场景由用户填写名称并选择模态，系统生成 `scene_` 加不带连字符的小写 UUID 作为编码。编码和模态创建后不可修改；名称、状态允许维护。

系统场景和历史场景继续受不可变保护。自定义场景已被路由或调用记录引用时只能停用；只有未引用记录允许删除。

自定义场景默认：

- `source=custom`
- `runtime_status=not_connected`
- `requirements_source=admin`
- `allow_new_configuration=true`
- `required_input_modalities=[modality]`
- `requires_streaming=false`
- `min_reference_images=0`

创建自定义场景只表示路由配置已建立，不表示微信小程序、抖音小程序或其他业务代码已经调用该场景。页面以“待业务接入”显示该状态。

### 3.4 路由

场景编码和输出模态是路由身份，创建后不可修改。场景注册表名称是场景展示名称的权威来源；`ai_scene_routes.name` 保留为兼容快照，新建时由服务端写入，不允许页面独立修改系统场景名称。

系统场景 `decoration_raw_drawing` 继续作为“装修生图”的唯一业务身份，不为同一功能另建自定义场景。

`runtime_status=not_connected` 只负责告知业务接入状态，不再禁止预先绑定模型。权限不足、保存中或配置版本冲突才会阻止管理员编辑。

## 4. Admin 信息架构与交互

### 4.1 供应商 Tab

页面使用左侧供应商列表和右侧详情。窄屏下改为单列，先显示列表，再显示选中详情；不创建嵌套卡片。

顶部操作：

- 搜索供应商
- 新增供应商

连接配置区：

- 系统编码：保存后展示，只读。
- 供应商名称：必填文本。
- 协议类型：Select，选项为 OpenAI Compatible 和 OpenRouter。
- Endpoint：必填 HTTPS 地址，标签和帮助文本明确其为 Base URL。
- 密钥配置项：从已登记的安全配置项选择。
- 状态与排序。
- 保存供应商。
- 删除供应商。

删除供应商前显示影响确认。存在模型、目录记录或其他引用时，后端返回稳定冲突错误，页面引导管理员停用供应商；不允许级联删除模型。

### 4.2 密钥配置

供应商表单只保存密钥配置引用，例如 `ARK_API_KEY`，不接收真实密钥。

真实密钥通过独立密码 Dialog 写入服务端安全配置：

- 输入使用密码字段，不回显旧密钥。
- 页面仅显示“未配置”“已配置，未验证”“配置引用异常”等状态。
- 保存前提示该配置项可能被多个供应商共享。
- 真实密钥不进入供应商请求、浏览器日志、错误提示或审计详情。
- 新建供应商时可以先配置所选安全配置项，再保存供应商引用；两个动作的状态必须分别展示，避免把“密钥已写入”误报为“供应商已保存”。

OpenRouter 只能选择其专用密钥配置。OpenAI Compatible 可以选择系统允许的通用或供应商专用密钥配置。

### 4.3 当前供应商模型清单

选择供应商后展示其模型表格，字段包括：

- 模型名称
- 供应商调用名称
- 输出模态
- 输入模态
- 系统编码
- 状态
- 编辑操作

“新增模型”默认绑定当前供应商，不再次要求选择供应商。创建表单不显示可编辑的系统编码；保存成功后在详情中显示只读编码。

模型清单、搜索和筛选均使用分页接口，默认每页 20 条，最大 100 条。

本轮支持新增、编辑和停用模型，不新增模型删除能力，以免误删正在使用的路由资产。

### 4.4 场景路由 Tab

页面顶部提供“新增场景路由”。编辑区通过来源切换选择：

- 系统或已有场景：从注册表 Select 选择。
- 新建自定义场景：填写场景名称并选择输出模态。

系统场景的名称、编码和模态只读。已有自定义场景的编码和模态只读，名称和状态可按权限维护。

路由继续保留现有质量档位、超时、温度、响应格式和状态字段；高级参数默认折叠。图片输出场景不展示仅适用于文本响应的格式字段。

### 4.5 主模型和备用模型

主模型和备用模型使用相同的两级选择器：

1. 选择启用的供应商。
2. 自动读取该供应商在系统内已登记、且输出模态匹配的模型。
3. 选择模型后展示调用名称、输出模态、输入模态和状态。
4. 备用模型允许明确选择“无备用模型”。

候选来源按以下顺序处理：

1. 系统已登记模型，所有协议都支持。
2. OpenRouter 已验证的远端目录及已物化模型。
3. 手动输入供应商调用名称。

OpenAI Compatible 不默认拼接 `/models`，也不把火山方舟 API Key 推理协议当成已验证的目录协议。

当远端目录不支持、加载失败或候选为空时，页面必须区分显示：

- 无远端目录能力：说明可直接手动添加调用名称。
- 加载失败：显示安全错误摘要和“重新获取”。
- 目录为空：说明当前筛选没有候选。
- 模态不匹配：说明为什么候选被排除。

手动输入时，模型显示名称默认等于调用名称，用户可修改；输出模态继承当前场景，输入模态使用场景要求作为默认值。保存时后端查找或创建模型记录，路由最终只保存模型 ID。

主模型和备用模型不能是同一模型。两者必须与场景输出模态一致，供应商和模型都必须处于启用状态才能作为新的选择。

### 4.6 页面状态

页面不得使用统一灰色禁用表达所有异常。需要分别呈现：

- 无管理权限：表单只读并说明权限原因。
- 正在保存：仅锁定会造成重复提交的操作。
- 运行时待接入：展示警告，但允许配置模型。
- 候选加载中：模型 Select 展示加载状态。
- 候选加载失败：保留供应商和已选模型，提供重试和手动输入。
- 原绑定已停用：保留回显，要求恢复、替换或清空后再保存。
- 配置版本冲突：提示刷新最新数据，不覆盖远端版本。

按钮使用“新增供应商”“保存供应商”“新增模型”“保存模型”“创建场景路由”等动词加对象的文案。所有 Select、Dialog、错误提示和加载状态支持键盘与辅助技术。

## 5. API 与服务数据流

### 5.1 分层

- Controller：读取请求、权限和 Zod 校验，调用 service，以 `ResponseHandler.success` 包装响应。
- Service：生成系统编码、处理模型查找或创建、编排场景与路由、执行领域校验和审计。
- Repository：访问 Supabase、SQL 或 RPC，限定字段并执行分页。
- Gateway：封装 OpenAI Compatible 和 OpenRouter 外部协议差异。

所有业务错误必须经 `error-factory.ts` 创建，不直接抛出普通 Error。

### 5.2 接口调整

沿用现有 `/platform/ai-config` 路由组，进行以下调整：

- 供应商创建和修改 schema 不暴露 `code`。
- 模型创建和修改 schema 不暴露 `code`。
- 模型列表增加 `providerId`、`modality`、`status` 和 `keyword` 分页过滤。
- 新增自定义场景分页列表、创建、修改、删除接口。
- 场景路由创建使用判别联合：`registered` 引用已有场景，`custom` 携带新场景名称和模态。
- 手动模型解析允许 `text`、`image`、`video`、`speech`，不再硬编码为 `text`。

所有列表默认 `page=1&pageSize=20`，`pageSize` 最大 100。

### 5.3 自定义场景事务

创建新自定义场景及首条路由必须原子完成：

1. Service 校验权限和请求。
2. Repository 调用由 migration 创建的受限数据库 RPC。
3. RPC 生成场景记录并写入首条路由。
4. 任一约束失败则整体回滚。
5. Service 写入审计记录并返回场景与路由。

不得使用两个独立 HTTP 写请求再由前端补偿。

### 5.4 手动模型解析

手动输入调用名称后：

1. 按供应商 ID、调用名称和输出模态查找现有模型。
2. 找到则复用。
3. 未找到则生成模型编码并创建模型。
4. 并发创建由数据库唯一约束收敛，冲突后重新读取现有记录。
5. 返回模型 ID，路由保存模型 ID。

### 5.5 连接验证

“验证连接”不得默认触发收费图片生成：

- OpenRouter 可以通过已有只读目录能力验证鉴权和网络连通性。
- OpenAI Compatible 若没有经过验证的无损探针，显示“配置已保存，模型调用未验证”。
- 真实文本或图片调用必须通过独立明确动作触发。
- 图片测试按钮必须提示可能产生费用，不自动重试。

本轮开发 smoke 默认不执行付费生图。

## 6. 数据库 migration

所有数据库变更通过 `supabase/migrations/` 中的新 migration 完成。禁止手工远端修库。

迁移内容：

- 将 `ai_system_scenes.source` 扩展为 `system | custom | legacy`。
- 将 `requirements_source` 扩展为包含 `admin`。
- 为自定义场景补充状态、版本和更新时间字段。
- 调整不可变触发器：系统与历史场景不可变；自定义场景只允许修改名称、状态和版本控制字段。
- 调整路由保护：运行时待接入不阻止模型预配置；身份字段仍不可修改。
- 为供应商、模型和场景编码增加更新保护。
- 增加模型业务唯一索引 `(provider_id, model_name, modality)`；迁移前先检测并拒绝存在歧义重复的数据，不静默合并。
- 创建自定义场景及首条路由的事务 RPC，并限制执行权限。
- 保持现有系统场景、历史场景、模型和供应商编码不变。
- migration 不重写历史 Endpoint；应用兼容层只剥离标准推理路径，无法归一化的地址返回配置错误。

迁移是增量兼容变更。应用代码回滚后，自定义场景和路由数据继续保留；旧应用不得删除或改写这些记录。破坏性反向 migration 不随本次发布提供，如需清理必须另行审查引用和调用日志。

## 7. 错误与安全

Admin 和 API 必须区分：

- 密钥未配置
- 密钥配置引用无效
- Endpoint 非 HTTPS 或格式错误
- 远端目录不受支持
- 远端鉴权失败
- 远端超时
- 目录为空
- 模型模态不匹配
- 模型或供应商停用
- 主备模型重复
- 场景不可维护
- 数据库唯一冲突
- 配置版本冲突

外部错误只映射为稳定的安全错误码和中文消息，不回传密钥、请求头、完整上游正文或敏感 URL 参数。密钥写入和外部请求日志必须脱敏。

删除供应商继续依赖数据库引用约束处理并发，前端预检查只用于改善提示，不作为安全边界。

## 8. 验证策略

### 8.1 后端

- 供应商、模型和自定义场景编码自动生成且不能修改。
- 现有编码不被迁移重写。
- 自定义场景和首条路由事务成功与整体回滚。
- 手动模型复用、并发唯一冲突恢复和多模态支持。
- 主备模型重复、模态错误、停用资产和版本冲突。
- 系统场景、历史场景保护规则不回退。
- 所有新增列表的分页、最大 pageSize 和必要字段投影。
- 错误脱敏与权限边界。
- migration 合同、触发器和 RPC 权限。

### 8.2 Admin

- 供应商新增、编辑、密钥状态和删除限制。
- 当前供应商下新增、编辑、停用模型。
- 系统场景、已有自定义场景和新建自定义场景三条路径。
- 供应商切换后按模态加载候选。
- 无目录、加载失败、目录为空和手动输入状态。
- `decoration_raw_drawing` 在“待业务接入”状态下仍可配置模型。
- 刷新后正确回显主备供应商、模型和调用名称。
- 窄屏布局、键盘操作、Dialog 焦点和实时状态提示。

### 8.3 开发环境 smoke

1. 打开供应商 Tab，编辑现有火山方舟连接。
2. 确认真实密钥不回显，供应商只保存密钥引用。
3. 将 `doubao-seedream-5-0-pro-260628` 登记或修正为图片输出模型。
4. 打开装修生图路由，选择火山方舟及该模型。
5. 保存并刷新，确认绑定回显一致。
6. 创建一个自定义文本场景及首条路由，确认编码自动生成。
7. 验证手动模型输入会复用同一模型记录。
8. 验证被引用供应商不能删除，但可以停用。

默认不执行收费生图。

## 9. 发布顺序

1. 运行最小静态检查和相关测试。
2. 确认待执行 migration。
3. 向开发数据库应用 migration。
4. 运行 `supabase migration list`，确认 Local/Remote 对齐。
5. 发布开发 API。
6. 发布开发 Admin。
7. 执行开发环境 CRUD 和页面 smoke。
8. 记录发布、migration 和 smoke 证据。
