# AI 模型路由简化设计

**日期：** 2026-09-05

**状态：** 已确认

**范围：** 平台超管 Admin、Gooes API、OpenRouter 目录同步与场景路由配置

## 1. 背景

当前“AI 模型路由”页面同时展示“场景路由、OpenRouter 目录、模型、供应商”四个一级 Tab，
把管理员真正要完成的业务配置与内部模型资产治理混在一起。

管理员的实际目标只有两个：

1. 配置一个可调用的 AI 供应商。
2. 为业务场景选择该供应商下的具体模型。

现有交互要求管理员额外理解目录同步批次、目录条目应用、内部模型编码、模型排序和价格快照，
操作链路长且容易产生错误配置。

现有实现还存在以下结构问题：

- 页面默认打开“场景路由”，但服务端仍加载 OpenRouter 同步记录和目录条目；目录读取失败可能导致整个页面加载失败。
- 路由模型选项只读取前 100 条模型，OpenRouter 模型数量超过上限后，部分模型不可选择。
- 模型查询支持关键词，但缺少 `provider_id` 条件，无法形成“供应商 -> 模型”的联动搜索。
- 供应商、模型和路由的读取位于 `AiModelCatalogRepository`，写入位于旧的
  `AiConfigRepository`，同一业务实体的读写职责分散。
- 场景路由只保存模型 ID，保存前没有统一验证供应商状态、模型状态、所属关系和模态能力。
- 运行时查询没有把模型及供应商启停状态作为明确门禁，配置状态与实际调用行为可能不一致。

## 2. 设计结论

平台超管页面只保留两个一级功能：

- **场景路由**
- **供应商**

`ai_models`、OpenRouter 目录同步记录、目录条目和价格快照继续保留为内部模型资产，
但不再作为常驻一级页面暴露给管理员。

```text
供应商配置
  -> 后台获取或维护供应商模型目录
  -> 场景路由选择供应商
  -> 搜索并选择模型
  -> 后端解析为内部模型记录
  -> AI Gateway 按场景路由调用
```

不采用把模型名称直接写入 `ai_scene_routes` 的方案。场景路由继续引用 `ai_models`，以保留：

- 稳定外键和历史调用标识；
- 模型能力与模态门禁；
- 当前价格快照；
- 模型启停状态；
- OpenRouter 目录审计与后续计费能力。

## 3. 目标

- 管理员只通过“供应商”和“场景路由”完成配置闭环。
- 场景路由采用“选择供应商 -> 搜索模型”的两级交互。
- OpenRouter 目录自动成为模型搜索数据源，不再要求管理员先同步、勾选、应用模型。
- 普通 OpenAI-compatible 供应商在无法读取模型目录时，允许手动填写文本模型调用名称。
- 所有搜索在数据库分页和总数统计前执行，默认每页 20 条，最大 100 条。
- 保持现有路由 ID、模型 ID、调用日志、价格快照和已发布业务调用兼容。
- 收敛后端读写职责，避免同一实体跨两个 repository 维护。

## 4. 非目标

- 不删除 `ai_models`、`ai_model_catalog_sync_runs`、`ai_model_catalog_entries` 或价格快照表。
- 不让场景路由直接依赖 OpenRouter 实时接口；运行时仍只读取本地已确认配置。
- 不承诺任意第三方原生协议自动兼容。第一阶段支持 OpenRouter 和 OpenAI-compatible 协议；
  Anthropic、Gemini 等原生协议需要独立 Adapter 后才能启用。
- 不允许通过模型名称猜测图片、视频或语音能力。
- 不在本次范围内重构 AI Gateway 的任务、计费或异步 Worker 架构。

## 5. Admin 信息架构

### 5.1 页面概览

页面标题保留“AI 模型路由”，概览指标调整为：

- 已启用场景数；
- 已连接供应商数；
- 当前可路由模型数。

顶部只显示“场景路由”和“供应商”两个 Tab。页面首屏不请求目录同步历史或目录条目。

### 5.2 场景路由

场景路由使用列表加编辑抽屉或独立编辑区，不要求管理员维护内部编码。

基础字段：

- 场景名称：从系统已注册的业务场景中选择；场景编码只读或隐藏。
- 功能类型：文本、图片生成、视频生成或语音生成。
- 状态：启用、停用。

主模型配置：

1. 选择启用的供应商。
2. 在带服务端搜索的模型 Select 中查找该供应商下、与场景功能匹配的模型。

备用模型使用相同的“供应商 + 模型”组合，可选择不同供应商。选择主模型后，备用模型默认不配置。

模型选项展示：

- 用户可读模型名称；
- 供应商模型调用名称；
- 功能标签；
- 可用状态或简短不可用原因。

不展示内部模型编码、目录条目 ID、目录哈希或同步批次 ID。

温度、响应格式、超时和质量档位归入默认折叠的“高级设置”。当功能类型不适用某项参数时，
不显示该字段，而不是让管理员填写无效值。

编辑既有路由时，即使当前模型后来失效，也必须展示原选择和明确警告，要求管理员更换；
不能静默清空或自动切换模型。

### 5.3 供应商

供应商页继续支持新增、编辑、启停和分页，表格重点展示：

- 供应商名称；
- 接口协议；
- 连接状态；
- 可用模型数量；
- 模型目录最后更新时间；
- 状态与操作。

供应商编辑表单包含：

- 名称；
- 接口协议；
- Endpoint；
- 密钥配置引用；
- 状态。

供应商编码和排序由系统维护，不要求管理员填写。

OpenRouter 供应商提供“更新模型”操作。同步详情、失败原因和历史记录放在供应商详情中的运维区域，
不作为一级 Tab。保存 OpenRouter 供应商后，Admin 自动发起一次独立的目录同步请求；供应商保存成功
不因同步失败而回滚。后续管理员仍可人工刷新，本次不新增定时调度能力。

OpenAI-compatible 供应商优先尝试已配置的模型发现能力。如果供应商不支持模型目录，
场景路由模型搜索无结果时显示“手动填写模型调用名称”。第一阶段该兜底只允许文本模型，
图片、视频和语音模型必须有经过验证的结构化能力信息。

## 6. 模型发现与物化

### 6.1 OpenRouter

OpenRouter 同步继续保存不可变 run 和 entry，用于：

- 目录缓存；
- 能力和价格变化审计；
- 结构化模态分类；
- 目录异常时保留最后一次有效结果。

场景路由的模型搜索直接查询该供应商最新一次成功同步中的有效条目。只返回：

- 未下架；
- `apply_status = eligible`；
- 模态与场景一致；
- 满足路由能力门禁的条目。

管理员选中目录条目时，后端按 `(provider_id, model_name, modality)` 查找或创建内部
`ai_models` 记录，并保存能力和当前价格快照。该动作取代原来的“目录勾选 -> 应用模型”操作。

目录同步不自动切换任何现有场景路由。

### 6.2 OpenAI-compatible 供应商

若供应商支持可靠的模型目录，后端 Adapter 将目录转换为统一模型选项；不能假设所有兼容接口都实现
`GET /models`，也不能根据 URL 拼接猜测第三方接口。

无目录时，管理员可以在模型搜索框中手动输入模型调用名称。后端：

1. 验证供应商处于启用状态；
2. 规范化并校验调用名称；
3. 自动生成内部模型编码和显示名称；
4. 创建或复用该供应商下的文本模型记录；
5. 返回内部模型 ID 供路由保存。

模型编码、排序和 `catalog_managed` 等字段不由管理员填写。

## 7. API 设计

### 7.1 路由模型候选搜索

新增专用于场景路由选择器的供应商范围接口：

```http
GET /platform/ai-config/providers/:providerId/route-model-options
  ?page=1
  &pageSize=20
  &keyword=claude
  &modality=text
```

规则：

- `providerId` 必须对应启用供应商。
- `keyword` 匹配显示名称和供应商调用名称。
- 只返回与 `modality` 匹配且可用于路由的候选；既有失效选择由路由详情单独返回，不混入候选。
- 所有条件必须在 `count` 和 `.range()` 前组合。
- 只选择 Select 和路由校验需要的字段，不加载大体积原始能力 JSON。
- `pageSize` 最大 100，搜索 Select 使用分页或游标加载更多。

服务端把“已物化模型”和“最新目录可选条目”归一化为统一的只读选项 DTO：

```ts
type AiRouteModelOption = {
  source: 'model' | 'catalog';
  value: string;
  provider_id: string;
  name: string;
  model_name: string;
  modality: 'text' | 'image' | 'video' | 'speech';
  availability: 'available' | 'unavailable';
  unavailable_reason: string | null;
};
```

`value` 是不透明值：已物化模型使用模型 ID，目录候选使用目录条目 ID。Admin 不解析其格式。

现有 `GET /platform/ai-config/models` 保持 `AiModelRecord` 分页响应，不混入目录候选；
可补充 `provider_id` 过滤用于内部诊断，但新 Admin 的路由选择器不依赖该接口。

### 7.2 解析路由模型

新增供应商范围内的解析命令接口：

```http
POST /platform/ai-config/providers/:providerId/route-model-options:resolve
```

选择既有模型或目录候选时：

```json
{
  "source": "catalog",
  "value": "目录条目ID"
}
```

手动填写文本模型时：

```json
{
  "source": "manual",
  "model_name": "deepseek-chat",
  "modality": "text"
}
```

该接口只接受 `platform.ai_config.manage` 权限，必须验证供应商状态和协议能力，
不能信任客户端提供的 `source` 或 ID。目录候选必须属于该供应商的最新成功目录并满足路由门禁；
手动输入只允许支持范围内的文本模型。服务端使用幂等查找或数据库唯一约束避免重复模型，
统一返回内部模型记录。

### 7.3 场景路由保存

现有创建和更新接口继续保存 `primary_model_id` 与 `fallback_model_id`，保持运行时兼容。
Admin 在提交路由前先把目录候选或手动调用名称解析为内部模型 ID。

后端保存路由时不能信任前端筛选结果，必须再次验证：

- 主模型存在、启用且属于启用供应商；
- 备用模型存在、启用且属于启用供应商；
- 模型模态与路由模态一致；
- OpenRouter 多模态模型满足能力和探针门禁；
- 主模型和备用模型不能引用同一模型；
- 乐观锁版本仍然有效。

错误继续通过 `error-factory.ts` 返回稳定中文消息和业务码。

## 8. 后端职责收敛

保持现有 controller/service/repository 分层，不引入新框架。

### `AiConfigController`

- 只解析 HTTP 参数、执行 Zod 校验、获取平台权限上下文和包装响应。

### `AiConfigService`

- 编排供应商配置、模型解析和场景路由保存。
- 执行供应商/模型/模态/状态业务门禁。
- 记录配置审计日志。

### `AiConfigRepository`

- 统一负责供应商、内部模型和场景路由的分页读取与写入。
- 移入当前位于 `AiModelCatalogRepository` 的 provider/model/route 列表读取。
- 删除无分页的旧列表实现，不保留两套同名读写路径。

### `AiModelCatalogRepository`

- 只负责目录 run、entry、价格快照和目录物化 RPC。
- 不再承担供应商、模型和路由通用列表读取。

### `OpenRouterModelSyncService`

- 负责第三方目录读取、严格解析、分类、同步和最后有效目录维护。
- 同步失败不覆盖最后一次成功目录，不影响场景路由和供应商页面加载。

### `AiGateway`

- 运行时继续从场景路由解析内部模型和供应商。
- 增加模型及供应商状态门禁；配置不可用时返回稳定错误，不静默调用已停用配置。
- 保留现有明确的兼容兜底，后续另行评估是否移除，不能在本次改造中扩大行为变化。

## 9. 数据库与兼容性

本设计不要求删除表或迁移现有路由外键。

如缺少以下约束或索引，只能通过 forward migration 增加：

- 模型按 `(provider_id, model_name, modality)` 唯一；
- 模型搜索使用的供应商、状态、模态和排序组合索引；
- 最新成功目录按供应商和创建时间读取的索引。

迁移前必须核查现有数据重复情况；若存在冲突，先输出审计报告并制定合并规则，禁止直接删除记录。
应用后使用 `supabase migration list` 验证 Local/Remote 对齐。

既有 API 和数据库记录保持可读。旧 Admin 在过渡期间仍可使用模型 ID 创建和更新路由；
新 Admin 不再展示“模型”和“OpenRouter 目录”Tab。

## 10. 错误与状态

- 供应商未启用：模型选择器禁用，提示“请先启用供应商”。
- 目录尚未同步：提供“更新模型”入口，不把整个页面置为错误。
- 目录同步失败：保留最后成功目录，并在供应商行展示失败状态和重试操作。
- 搜索无结果：普通兼容供应商允许手动填写文本模型；OpenRouter 提示更新目录。
- 模型不再可用：既有路由显示警告，保存时要求更换。
- 模态不匹配或能力未验证：候选不可选择，并返回稳定不可路由原因。
- 并发修改：返回 `AI_CONFIG_VERSION_STALE`，要求刷新后重试。

第三方响应、密钥、Authorization、原始目录 JSON 和供应商内部错误不得返回浏览器。

## 11. 验证要求

### API

- 供应商、关键词、模态、状态和 routable 组合筛选在分页前执行，`total` 正确。
- 第 101 条以后模型可以通过搜索或翻页选中。
- OpenRouter 最新有效目录可搜索，阻断和下架条目不可路由。
- 手动模型只允许支持范围内的文本模型，并能幂等复用。
- 停用供应商、停用模型、跨供应商模型和模态不匹配均被服务端拒绝。
- 既有模型 ID 路由保存和 AI Gateway 调用保持兼容。

### Admin

- 页面只有“场景路由”和“供应商”两个一级 Tab。
- 初始页面不请求目录 run 或 entry。
- 主、备用模型均为供应商联动的服务端搜索 Select。
- 搜索请求有防抖和竞态保护，切换供应商会清空不兼容模型。
- 手动输入入口只在无目录的兼容供应商搜索无结果时出现。
- 内部编码、目录哈希和同步批次不进入常规操作界面。
- 加载、空状态、同步失败、模型失效和保存冲突均有稳定布局和明确反馈。

### 回归

- 场景路由主备切换、调用日志和现有同步文字 AI 不变。
- OpenRouter 能力、价格快照和多模态 Worker 仍使用内部模型事实。
- API 单测、类型检查、Admin 检查和关键接口 smoke 通过。

## 12. 建议实施顺序

1. 收敛 provider/model/route repository 读写职责，并补充服务端路由门禁测试。
2. 增加供应商范围模型搜索与手动文本模型解析接口。
3. 让 OpenRouter 最新有效目录成为路由模型搜索的数据源，选中时自动物化模型。
4. 改造场景路由为“供应商 + 搜索模型”交互，隐藏内部字段和高级参数。
5. 将 OpenRouter 同步入口迁入供应商详情，并移除“模型”“OpenRouter 目录”一级 Tab。
6. 移除首屏目录请求，完成 API/Admin 回归和开发环境 smoke。

该顺序先建立后端正确性，再切换 Admin，避免出现界面已隐藏模型管理但路由尚不能完整选模的中间状态。
