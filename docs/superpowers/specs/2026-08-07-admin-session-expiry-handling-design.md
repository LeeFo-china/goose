# Admin 会话失效统一处理设计

日期：2026-08-07

## 背景与根因

Admin 当前登录成功后只把后端签发的 JWT 保存为 HttpOnly Cookie。租户
Admin 的当前有效期为 7 天，平台人员默认为 12 小时；系统没有刷新令牌或
滑动续期机制。

当 JWT 缺失、过期或失效时，API 已能稳定返回 HTTP 401 和
`TOKEN_MISSING`、`TOKEN_EXPIRED`、`TOKEN_INVALID`。但 Admin 的 BFF
代理只是原样转发响应，没有删除失效 Cookie；客户端请求层也没有统一处理
401。部分业务页面因此把请求失败降级为“无权限”，直到用户刷新页面后，
服务端布局重新校验会话并跳转登录。

本次目标是修复错误语义和交互闭环，不改变令牌寿命，也不在本阶段引入刷新
令牌体系。

## 目标

1. 会话缺失、过期或无效时统一判定为“登录态失效”，不能显示为业务无权限。
2. BFF 收到明确的认证 401 后删除 Admin JWT Cookie，避免持续携带坏令牌。
3. 客户端业务请求发现认证 401 后立即跳转登录，不要求用户手动刷新。
4. 页面长时间静置后，通过定时与页面重新可见检查发现失效会话。
5. HTTP 403 继续表示真实权限不足，不触发退出或登录跳转。

## 非目标

- 不新增 Refresh Token、服务端会话表或数据库 migration。
- 不修改租户 7 天、平台人员 12 小时的 JWT 有效期。
- 不改变角色、权限、租户状态或计费锁定规则。
- 不修改 API 对 401/403 的既有错误码契约。

## 方案

### 1. 认证错误分类

Admin 共享层维护唯一的认证失效判断：

- HTTP 状态必须为 401；
- 错误码为 `TOKEN_MISSING`、`TOKEN_EXPIRED` 或 `TOKEN_INVALID`；
- 为兼容代理或异常响应，HTTP 401 即按失效会话安全收敛，但不得把 403 纳入。

该判断供 BFF 响应处理、客户端请求工具和会话守卫复用，避免各页面自行解释。

### 2. BFF Cookie 清理

`/api/backend/[...path]` 和 `/api/auth/me` 在后端返回认证 401 时：

1. 保留后端原始 HTTP 状态、错误码、消息和 Request-ID；
2. 在响应中删除 `gooes_admin_token` Cookie；
3. 不把 API 请求改成 3xx，避免 `fetch()` 跟随跳转后把登录页 HTML 当 JSON；
4. 403 原样返回且不删除 Cookie。

当请求进入 BFF 时已经没有 Cookie，现有 `TOKEN_MISSING` 401 响应也必须附带
删除 Cookie 操作，保证客户端状态幂等收敛。

### 3. 客户端统一跳转

共享客户端请求工具在解析到认证 401 后调用幂等的会话失效处理器：

1. 清理以 `gooes:admin-session:` 开头的当前 Admin 本地缓存；
2. 使用 `window.location.replace("/login?reason=session_expired")` 跳转；
3. 使用模块级保护避免并发失败请求重复触发跳转；
4. 仍抛出带状态、错误码和 Request-ID 的请求错误，便于未完成跳转前的调用链
   正常结束。

登录页不使用该处理器，避免重定向循环。登录成功后现有跳转逻辑保持不变。

### 4. 长驻页面会话守卫

`AdminShell` 内挂载一个无 UI 的客户端会话守卫：

- 首次挂载不重复请求，初始会话已经由服务端布局校验；
- 每 5 分钟请求一次 `/api/auth/me`；
- 浏览器窗口重新获得焦点或页面从隐藏恢复可见时立即检查；
- 同一时刻最多存在一个检查请求；
- 认证 401 调用统一失效处理器；
- 网络错误和 5xx 不退出登录，下一个周期重试；
- 403 不退出登录，交由真实权限逻辑处理；
- 组件卸载时清理定时器和事件监听。

这样即使用户没有触发业务请求，失效会话也会在最多 5 分钟或重新打开页面时
得到纠正。

### 5. 登录提示

登录页识别 `reason=session_expired`，展示简短提示“登录已过期，请重新登录”。
提示不携带原始请求参数、Token 或后端内部信息。

## 数据流

正常请求：

```text
Admin 页面 -> BFF Cookie -> API JWT 校验 -> 200 -> 页面继续
```

会话失效：

```text
Admin 页面/会话守卫
  -> BFF 携带 Cookie
  -> API 返回 401 + TOKEN_EXPIRED/INVALID/MISSING
  -> BFF 原样返回并删除 Cookie
  -> 客户端清理会话级缓存
  -> replace 到 /login?reason=session_expired
```

真实无权限：

```text
Admin 页面 -> API 返回 403 FORBIDDEN -> BFF 原样返回 -> 页面展示权限不足
```

## 错误处理与安全边界

- 只有 401 触发会话退出，403、402、404、409、429 和 5xx 均不得误退出。
- 后端不可用或临时网络失败不会删除 Cookie，防止瞬时故障导致全员下线。
- JWT 继续只存在 HttpOnly Cookie，不暴露给浏览器 JavaScript。
- 不记录 Token、Cookie 内容或用户权限明细。
- 跳转使用固定站内路径，禁止从错误响应读取重定向地址。

## 测试与验收

### 自动化测试

1. BFF 后端代理收到 401 时保留响应并删除 Cookie。
2. BFF 对 403 不删除 Cookie。
3. `/api/auth/me` 对认证 401 删除 Cookie。
4. 认证错误分类仅接受 401，不把 403 判为会话失效。
5. 客户端失效处理器只跳转一次，并清理 Admin 会话级本地缓存。
6. 会话守卫对 401 触发退出；对 403、网络错误和 5xx 保持会话。
7. 登录页只在 `reason=session_expired` 时展示过期提示。

### 手工验收

1. 使用测试令牌或测试响应触发 `401 TOKEN_EXPIRED`，当前页面直接进入登录页，
   不出现“无权限”。
2. 返回 `401 TOKEN_INVALID` 和 `TOKEN_MISSING` 时行为一致。
3. 登录 Cookie 被清理，重新登录后恢复原有角色权限。
4. 模拟 `403 FORBIDDEN`，页面继续展示真实无权限且不会退出。
5. 页面保持打开后切换到其他标签，再返回时立即执行会话检查。
6. API 短暂返回 502/503 时不退出登录，恢复后可继续请求。

## 发布与回滚

本次仅修改 Admin，无数据库变更。发布时执行 Admin 类型检查、相关测试和生产
构建。回滚只需回退对应 Admin 提交；JWT、Cookie 名称和 API 契约均未改变，
不存在数据回滚。
