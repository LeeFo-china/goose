# 客户装修 AI 生图首期设计

日期：2026-09-13。状态：用户已确认首期方向及交互闭环，等待书面设计复核。本文只定义下一阶段，不表示生成入口已经发布。

## 1. 决策与交付边界

客户在微信或抖音小程序选择装修公司已发布的效果图，上传 **一张自家房间照片**，可选上传一张户型图；系统每次生成 **一张单房间参考效果图**，并依据最终生成图给出配色、材质、家具软装和现场确认建议。房间照片是空间主输入，所选已发布效果图是风格参考输入。户型图仅随方案私有保存、供客户主动咨询时使用，**不传给生图或建议模型，不承诺按户型图还原结构**。

推荐该方案，是因为单房间照片与风格参考图的双图链路已做过一次真实方舟验证。对比之下，“仅上传照片、不收户型图”会减少咨询资料；“让户型图参与空间推演”需要另设空间一致性验收，不能作为首期能力承诺。首期可引导用户上传客厅或卧室现状照，选择软装调整或整体翻新，不建设系统户型模板库，也不提供自由模型、提示词或整屋重建入口。

结果明确标为 AI 生成的装修沟通预览，不是施工图、尺寸承诺、准确色号、结构安全判断或报价。门窗、墙体、视角等原空间线索应尽量保留；明显偏移的结果不得作为通过审核的可交付图片。单次生成一张图，用户主动“重新生成”是新的次数消耗，不等同于网络重试。

## 2. 当前基线与不重复建设

- 已有双端效果图库列表/详情。gooes 提供 `/visitor/renderings/styles` 和 `/douyin-mini/renderings/styles`；微信 `orange/src/services/visitor_rendering_styles.ts` 及 `src/packageVisitor/pages/rendering-style-detail/index.tsx`、抖音 `apps/douyin-mini/src/api/rendering-styles.ts` 及 `pages/rendering-style-detail/` 已接浏览。客户生成入口未因此自动具备。
- 已有跨端额度基础：`/renderings/quota`、`/renderings/phone:bind`、共享 DTO、原子额度账本及相关开发环境验收。新增任务必须调用该账本的预占/结算能力，不能在任务表另记一份次数。
- 已有火山方舟双图生图适配及一次开发环境真实调用：输入两张非客户图，生成一张图并私有转存。约 94 秒的实测耗时只说明该样本链路可用，不代表客户照片质量、稳定性、成本和审核通过。
- 尚缺面向客户的私有上传、生成任务与 Worker、建议模型链路、私有历史和双端生成页面。建议模型与正式内容审核也须在开放前分别验证。

完整效果库及长期能力范围见 [原方案](2026-09-11-customer-rendering-library-design.md)。本文与原方案不同时，以用户于 2026-09-13 确认的本首期输入边界为准；原方案中写作草案的当前状态以实施时仓库代码和开发环境证据为准。

## 3. 客户流程

1. 保留现有效果图列表和详情；详情下方增加“看看你家装成这样”的入口，明确当前所选风格和“仅供参考”。进入生成表单前先取得可信装修公司与登录会话。
2. 必传房间照片，可选传户型图，各限一张、每张最多 10 MB。页面给出拍摄示例及隐私提示，显示空间类型、改造意图、可选的“希望保留的家具”说明。客户端先压缩/转换可支持格式（HEIC 必须真实转码），服务端仍验证真实文件类型、尺寸、大小和归属。
3. 查询服务端额度。未验证手机号可成功试用一次；第二次需完成平台可验证的手机号绑定。绑定后同一装修公司、同一已验证手机号跨微信/抖音累计最多五次，第一次计入五次；只绑定手机号不代表同意销售联系。客户端仅显示服务端返回的剩余次数及阻止原因。
4. 客户确认生成时创建一次带幂等键的任务。服务端复核素材仍已发布、文件可用且同租户/同主体，然后原子预占用户次数及租户预算。返回任务 ID；小程序离开页面后可凭当前身份恢复任务，不能因为网络超时就换键再提交。
5. 后台异步生成并审核，结果转存私有对象存储。图片可交付后核销一次，再异步生成建议。结果页展示原图/效果图对照、AI 标识、建议状态和剩余次数；建议暂时失败时仍可看图并单独补建议。
6. 客户如主动咨询，可另外授权共享生成图与建议。原房间照片和户型图需要单独勾选；生成体验、绑定手机号或查看结果都不自动创建线索或授予装修公司员工读取家庭原图的权限。

## 4. 服务边界与状态

双端 controller 只处理各自的认证、参数校验和 HTTP 响应，复用同一客户生图 service。service 编排可信租户/主体、素材、私有文件、额度、任务及建议；repository 访问 Supabase，gateway 访问 COS、内容审核和方舟。复用现有额度 RPC 与 Ark 双图适配，不引入第二套额度或新的通用 AI 平台。任何表、索引、RLS、RPC、场景配置或初始化数据变更均经 `supabase/migrations/`。

任务使用数据库持久化及已有部署形态的 Worker，不让 API 请求同步等待模型，也不靠进程内后台 Promise。创建任务时原子保存用户请求摘要与幂等键；提交模型前持久化 attempt、租约、模型/素材/提示词版本快照。Worker 以数据库 claim 和完成版本防止重复执行。

| 场景 | 服务端行为 | 客户可见行为 |
| --- | --- | --- |
| 同键同请求重放 | 返回原任务，不再次预占或调用模型 | 恢复进度 |
| 同键不同请求 | 409 冲突 | 提示重新确认后以新键提交 |
| 生成明确失败、输入/输出审核拒绝 | 释放用户预占，记录实际供应商成本及尝试频控 | 显示稳定错误，不展示违规图片 |
| 提交状态未知或超时 | 保留任务和预占，进入对账/人工处理；不自动再次付费生图 | 显示处理中或待处理，不鼓励重复提交 |
| 图片已生成但转存失败 | 优先恢复下载/转存；不可恢复才按失败处理 | 不展示临时方舟 URL |
| 私有图片通过审核并保存 | 核销一次；建议异步独立执行 | 先看图，建议可显示“生成中” |
| 建议失败 | 只补建议，不重画、不再扣次数 | 图片持续可见，显示补建议入口 |

模型只接收房间主图与所选风格图；户型图的文件 ID 可在方案中保存，但不得进入生图请求、提示词或建议请求。结果 URL 必须经可信地址校验、下载和私有转存，客户端只取短时授权地址。输出建议使用结构化 `RenderingAdviceSchema` 校验，区分画面可观察事实和搭配建议，不编造品牌、尺寸、隐藏工程或施工可行性。

## 5. 拟新增接口与双端交接

以下是**待实现合同**，不是现网可调用接口。微信前缀 `/visitor/renderings`，抖音前缀 `/douyin-mini/renderings`；两者共享业务 DTO，但维持各自会话/租户鉴权。既有 `GET /styles?page=1&pageSize=20`、`GET /styles/:id`、`GET /quota`、`POST /phone:bind` 保持兼容，不复用旧 `/visitor/picture-library/*` 的匿名 401 回退。

| 方法与相对路径 | 请求和响应要点 | 权限/失败语义 |
| --- | --- | --- |
| `POST /uploads:intent` | `purpose=room\|floor_plan`、mime、bytes；返回上传意图 ID、受限上传凭据和到期时间 | 当前主体与租户；文件大小、类型、次数受限 |
| `POST /uploads/:id/complete` | 确认上传；返回 `file_id`、审核状态 | 服务端校验对象、类型、大小及归属；可幂等重放 |
| `POST /jobs` | `RenderingJobRequestSchema`：素材、必需房间文件、可选户型图文件、空间、意图、保留说明、幂等键；返回 202、`job_id` 和最新 quota | 原子预占；409 手机号/额度/活动任务/幂等冲突，422 图片不合格，429 频控/租户日上限，503 功能未就绪 |
| `GET /jobs/:id` | 任务状态、图片就绪阶段、独立建议状态、结果短时地址及到期时间、稳定错误码 | 仅创建该任务的认证主体；无权或不存在均 404 |
| `POST /jobs/:id/advice:retry` | 幂等键；返回当前建议状态 | 仅图片已就绪且重试预算内可用 |
| `GET /history?page=1&pageSize=20` | 当前渠道主体的私有方案摘要和分页；`pageSize<=100` | 不因同手机号跨渠道绑定而自动共享历史图片 |

所有接口先检查会话与可信公司上下文。未选公司应给出可引导选择的稳定错误；会话失效返回 401，不匿名重试；素材隐藏阻止**新任务**但不破坏已受理任务。具体错误码沿用 [原方案的拟定合同](2026-09-11-customer-rendering-library-design.md#8-拟定-api-契约)，落地时由 shared domain、接口测试及交接文档固定。列表必须后端分页，默认 20、最大 100。

双端调用顺序：会话与公司 → 风格详情及 quota → 上传意图/上传/确认 → 必要时绑定手机号并刷新 quota → 创建任务 → 前台轮询/切后台停止 → 返回页面按任务 ID 恢复 → 查看图片与建议。客户端在发送 `POST /jobs` **之前**保存幂等键；同一内容的超时重试沿用原键，换图/换风格才生成新键。`active_job_id` 应恢复已有任务，不能靠按钮禁用代替服务端并发保护。

微信团队在 `orange` 中扩展 `src/services/visitor_rendering_styles.ts` 或新增独立生成 service，并扩展 `src/packageVisitor/pages/rendering-style-detail/index.tsx` / 新增任务结果页；该仓库由微信团队自行修改和验收。gooes 负责共享合同、后端、抖音 `apps/douyin-mini/src/api/rendering-styles.ts` 及详情/任务页。两端交接文档须提供最终字段、错误映射和真机会话 smoke，不能把本拟定路径当作已发布 API。

## 6. 隐私、成本与上线门禁

家庭原图、户型图和生成结果默认私有，不使用公开效果图库的上传路径。上传时清理 EXIF 定位数据，不记录原图、签名 URL、完整手机号或 Key；租户隔离、对象归属和短时读授权在服务端验证。输入/输出图片与建议均需内容审核；审核不可用时关闭新生成。首期预设：未提交任务的上传 24 小时清理，家庭输入保留 30 天，生成图与建议保留 90 天；客户删除后立即撤销读取，并在 24 小时内清理受控对象。实际隐私告知、备份到期和删除机制须在上线前完成评审。

租户启用生图前必须配置每日任务上限和费用预算；平台还需验证图片模型、独立的视觉建议模型、内容审核、实际单次成本和超时恢复。虽然方舟双图 smoke 成功，真实房间照可能出现明显结构再创作，不可直接对全量客户开放。先以 2–3 家公司和 30–50 组授权样本灰度；设计师按空间线索保留、风格相似度、建议真实性评审，统计首图完成率、p50/p95 耗时、单次成本和失败原因。不达门禁时保留效果图浏览，关闭生成开关。

## 7. 分阶段实施与验收

1. **后端私有输入与任务底座**：migration、上传意图与完成、归属/审核、幂等任务、额度及预算预占。验收跨租户/跨主体不可引用文件、并发剩余一次只成功一个任务、同键重放不重复消费。
2. **Worker、生图、建议与私有结果**：双图输入、提交未知恢复、可信下载/转存、审核、额度结算、独立建议。验收成功、明确失败、超时未知、存储失败、Worker 重启、建议失败均无重复付费生图或重复扣次。
3. **抖音接入与微信交接**：抖音详情上传及结果页；gooes 提供固定合同、错误映射和 smoke 清单，微信团队在 `orange` 实现相同流程。验收正常会话、未选公司、首次免费、第二次手机号、跨端累计五次、切后台恢复、历史私有访问和图片 URL 到期刷新。
4. **开发发布与小流量灰度**：按 migration 计划/应用/`supabase migration list` 后验、API/Worker 发布、两端真机联调，再启用试点租户。问题发生时关闭生成开关，不影响已发布效果图库浏览；已受理任务按状态继续结算或人工对账。

本次仅确认产品与技术设计，不执行 migration、付费调用、业务代码、发布或 `orange` 变更。实施计划须在本设计通过书面复核后另行编写。
