# D1 Admin 调拨接入设计

用户已授权按建议执行及任务内确认；承接 D1 设计与 DEV 604 条迁移，不重复审批，不操作生产/Orange，不自动赋予员工权限。

## 方案与边界

采用现有领退料工作区模式：分页列表、页内详情/草稿、确认弹窗。初始沟通提到详情抽屉，经代码核对，邻近实现为页内详情，故沿用实际模式。备选独立详情路由会增加导航状态维护；通用库存单据引擎会扩大本批范围，均不采用。

本批不改变数据库或后端业务规则。实现 Admin 调拨工作区、库存调拨来源跳转、平台独立开关 UI，再经过静态检查、组件/API测试、桌面/375px浏览器回归、独立审查和 DEV 发布。真实验收仅在固始晴天装饰工程有限公司，用已有权限员工及明确测试库存；缺权限时不得自行扩权。

## 页面与安全规则

- `/warehouse-transfers?order_id=<uuid>`，服务端取得会话与员工。读取只需 `inventory.stock.view`，不要求项目权限；管理 `inventory.transfer.manage`，完成 `inventory.transfer.approve`，仓库选择另需现有仓库查看权限。
- 列表：单号、源仓、目标仓、状态、材料数、金额、更新时间；关键词、两个仓库及状态筛选，默认20、最多100。详情明细独立分页；编辑必须完整取得最多100行且与单据 item_count/总数一致，防止部分明细覆盖。
- 草稿1–100 SKU、不同仓库、必填原因1–500字符，数量保持十进制字符串（14位整数/4位小数），拒绝0、指数、重复SKU（UUID大小写归一）。选择源仓变化清空材料，SKU来自源仓库存分页选择器，不输入成本或身份字段。
- 已保存草稿的源/目标仓锁定显示名称；更换仓库必须新建单据。依据已部署 atomic command migration 的 `SOURCE_CONFLICT` 约束，不能仅依据 save-draft 请求 schema 误判可改仓。
- 保存/提交/取消按管理权限，完成按确认权限；终态不可编辑。提交/完成/取消明确二次确认；完成说明双仓同时过账、不会产生项目成本/应付/付款。
- 复用既有冻结命令底层工具。sessionStorage按会话/租户/员工隔离；请求发送前冻结path/body/key，未知结果保留并重试原请求，不允许改body换key。关闭开关仍允许原成功请求重放及历史阅读；新命令全部禁用。确认回执单据ID、状态、版本+1匹配；409版本冲突重读后重新人工确认。
- session切换卸载旧工作区，AbortController取消读取，晚到响应不得污染新身份。无权限/加载/空态/失败重试均提供可读反馈。
- 平台租户设置增加“仓库调拨”，仅依赖module。关闭module前必须关闭调拨。新请求合并当前调拨值；已冻结的历史body保持不变。不给采购rollout链添加依赖。
- 库存来源新增严格transfer对象类型，显示调拨单号并链接工作区，不误渲染采购单/undefined；已有采购、领退料来源保持原权限规则。库存查看权限足以查看调拨历史，无需管理权限。
