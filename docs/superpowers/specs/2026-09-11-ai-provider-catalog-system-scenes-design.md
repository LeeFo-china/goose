# 供应商模型目录与系统场景管理设计

日期：2026-09-11。状态：用户已确认设计，P0 核验和 P3-A 共享场景定义已完成；其余后端/目录/UI 待实施，未应用新 migration、未发布。

## 1. 目标与授权边界

用户要求后端获取供应商模型列表，场景编码由系统自动生成和维护；已明确允许增加方舟目录读取所需的 AK/SK 安全配置。

交付目标：运营选择业务场景和供应商后，自动看到匹配的模型候选，不需要猜模型 ID、手写场景编码或手动指定场景模态。

本次仅涉及 Gooes API/Admin/domain、migration 和验证文档。Orange 只读；不新增小程序功能、计费规则、生成任务流程、Redis/队列或收费探测。新增依赖须另行说明和获批。录入凭证由用户在后台完成，禁止要求用户在聊天中发送凭证。本次批准不代表授权修改火山 IAM 策略、创建云端接入点或扩大云账号权限。

按两个实施批次交付：先模型目录与凭证，再系统场景及路由选择器；最终联合验收。两个批次共用已有 AI 配置边界，不建立第二套模型/路由系统。

## 2. 已确认的现状

- `ai-model-route-tab.tsx` 选择供应商只更新表单，不加载模型；仅搜索按钮调用候选接口。初始候选为空，无空结果提示；切换供应商/模态也未可靠清除旧候选。
- `AiConfigService.listRouteModelOptions` 仅为 OpenRouter 查询目录；其他供应商查询内部模型，手动候选仅支持 text。schema、Admin resolve 请求和 `createManualModel` 均固定 text。
- 排障时开发库的火山方舟有一条 `doubao-seedream-5-0-pro-260628` 模型，记录模态为 text；image 候选数为 0。此名称来自现有配置，不代表官方型号/可用性已核验。
- 已有 `ai_model_catalog_sync_runs` / `ai_model_catalog_entries`、目录预览/应用 RPC、分页模型候选及能力审核。RPC 内有 OpenRouter 专用约束，不能直接用新供应商调用旧 RPC。
- 现有密钥注册表四项同时用于推理密钥引用验证。不能把目录 AK/SK 加入该引用集合，否则会允许误当推理 API Key。
- `AiGateway.findSceneRoute` 按固定 `scene_code` 读取配置；装修问答、营销填充等业务已有固定编码。随机编码或根据可编辑中文名重新生成编码会破坏调用。
- 路由唯一性为 `(scene_code, quality_tier)`。本次不增加新的档位、不重构既有运行时档位解析。
- 已有独立 `gateways/ark-rendering` 图像/视觉请求适配，但它要求调用方验证 host、模型及参考图能力；有 gateway 文件不等于某个场景的端到端运行时已接通。计划必须核对场景到适配器的实际调用链，未接通项显示“运行时未接入”，不能为通过选择器验收绕过门禁。

## 3. 方案选择

采用“供应商适配获取 → 保存完整目录快照 → 后台分页读取 → 显式选择并绑定模型”。

备选一是每次展开下拉实时查询供应商：实现链路较短，但页面受上游延迟、限流、鉴权失败影响，难以审计。备选二是继续手工登记：只能作为高级兼容入口，不能满足自动目录和能力分类要求。

首版同步由有管理权限的用户明确触发；选择供应商自动读取已同步目录。没有目录时展示“尚未同步”及同步入口，不用 GET 查询隐式写库；本次不增加定时任务。同步后当前选择器自动刷新，不再要求额外点击搜索。

## 4. 供应商适配与凭证

### 4.1 协议与目录适配分开

保留 `provider_type` 的运行时含义，新增受校验的 `catalog_driver`：`openrouter`、`ark`、`openai_models`、`none`。它仅决定目录获取方式，不改变推理调用。

- OpenRouter 复用现有多模态目录能力与规则。
- Ark 使用独立的官方目录/版本与账号接入点查询适配，不把 OpenAI 兼容推理协议等同于支持 `/models`。
- `openai_models` 仅适用于已核验支持该接口的供应商；没有可靠模态信息时保留“能力待确认”，不默认 text。
- `none` 明确展示不支持自动同步，保留已有模型记录。
- 已有 OpenRouter 可按稳定 `provider_type` 回填；其他供应商不凭中文名猜厂商，需显式选择目录适配。不得在页面保存时悄悄修改 endpoint 或真实密钥。

### 4.2 AK/SK 成对安全存储

首版支持一个平台级方舟目录账号，新增 `ARK_CATALOG_CREDENTIALS`，与 `ARK_API_KEY` 完全隔离；Region 为非秘密配置，首版明确支持 `cn-beijing`。多账号及其他地域不在本次范围。

- UI 提供独立“配置目录凭证”弹窗，AK/SK 都是密码输入框，不回填、默认不显示内容；两项均非空才可提交，空白不清空。
- 后端专用严格 schema 接收一对字段，规范化为单个加密配置值，一次替换，复用现有 `system_settings` 加密写入机制；不得通过两次独立写入制造半更新。
- 此配置使用独立 allowlist/用途校验，不能出现在供应商“推理密钥引用”选项中，也不能被推理服务读取。
- 元数据仅返回是否配置、来源、配置异常状态；不返回 AK/SK、片段、长度、可逆摘要或原始异常。普通系统配置接口仍须遵守 secret 不回显规则，并禁止通过通用入口绕过凭证对结构校验。
- 写入要求平台身份及 `platform.ai_config.manage` + `platform.system_setting.manage`；读取状态要求对应 read 权限。同步要求 AI 管理权限，服务内部按固定用途读取密钥，不将解密能力暴露给请求参数。
- 保存仅表示“已配置（未验证）”。连接验证只调用已核实的目录读取接口，不生成内容、不创建/启动/更新/删除云端资源。
- API/Admin proxy 对秘密入口使用 private/no-store，未知字段、请求/响应、日志、审计、测试截图均不能泄露凭证；关闭弹窗清空输入。失败不自动重试凭证写入。

用户需在火山侧使用仅授予必要目录 List/Get 动作的 IAM 身份；后台程序只实现这些只读动作，但不能把“程序只读”宣称为已经验证用户 IAM 策略也只读。

### 4.3 官方接口合同验证门禁

已核对官方 SDK 的 `ListEndpoints` 使用 `volcengineSign`，SDK 凭证配置为 AK/SK。[Ark 官方 SDK](https://github.com/volcengine/volcengine-python-sdk/blob/master/volcenginesdkark/api/ark_api.py)、[官方凭证示例](https://github.com/volcengine/volcengine-python-sdk/blob/master/README.md)。

基础目录及版本接口的中国区当前响应、分页、模态字段和账户可用性语义尚未完成合同验证。实施计划第一项必须验证这些合同：以官方 API Explorer/文档及已安装 SDK 导出为依据，取得脱敏夹具后再实现适配。不能照搬 BytePlus 国际区字段，也不能用 ListEndpoints 的结果冒充全部供应商模型。

该门禁失败时，方舟同步标记“不支持/合同未验证”，保留原配置，停止宣称自动目录已交付；系统场景和通用选择器可独立验证。若发现需要额外依赖、写云端操作或更高权限，先向用户说明，不自动扩大范围。

## 5. 目录、模型与路由的数据流

Controller 只处理认证、参数与响应；service 编排目录拉取、投影和审计；gateway 负责供应商 HTTP/签名；repository/RPC 负责原子持久化。

复用现有目录表并用 migration 扩展通用保存/选择能力：新增通用入口，保留旧 OpenRouter RPC 签名作为受限兼容入口，内部复用相同实现。旧入口继续检查 OpenRouter，不放宽为任意供应商；新入口验证 driver/provider/run/hash 的一致性。

- 完整成功的快照才可成为当前目录。失败、超时、分页不完整不覆盖上一个成功快照；同供应商同步通过数据库锁/版本控制串行，迟到结果不能覆盖较新结果，不靠进程内锁保证多实例互斥。
- 目录项区分官方模型 ID、模型版本、可选账号 Endpoint ID、显示名、输入模态、输出模态、上游状态、账号可见性及项目适配状态。公开目录不代表账号已开通；账号可见也不代表当前推理 Key 已授权。
- 不保存任意上游原始 JSON。只投影允许字段，HTTP 响应严格校验；模型说明等文本按不可信文本展示。
- 目录未知模态允许在目录层表达为“待确认”，不得进入 `ai_models` 的合法模态或可绑定候选。复用表时同步收紧旧查询与 RPC 对未知项的排除，避免旧消费者把它当 text。
- 同步不批量启用模型、不改路由、不删除历史记录。模型下线只影响新选择提示；既有绑定显示告警，保留配置和审计。
- 选择目录项时后端复验当前目录、供应商状态、模态、能力和调用适配，按明确的 provider + 调用 ID + 模态幂等落实内部模型，再绑定路由；不能根据用户传入 label 建模型。
- “目录存在 / 账号可见或未知 / 项目支持 / 调用未验证”分开表示。未知账号授权可以提示未验证，但不自动触发收费请求；已知无权限、不支持运行时、能力不匹配的项禁止绑定。
- 图片场景需要参考图能力时按官方确认的能力筛选；不能将“支持图片输入的文本模型”分类为图片生成模型。视频/语音目录可以展示，未有运行时适配的不能被误标可调用。
- 现有手工入口不再将任意名称默认创建为 text；新路由优先选目录。高级手工登记必须明确模态和可信能力依据，不能绕过场景或适配校验。

### 性能与网络边界

对外所有列表默认 page=1/pageSize=20，pageSize 最大 100；目录候选跨页可浏览，搜索结果不能只看到前 20 项而无后续入口。必要字段投影、分页查询、provider/run/modality/filter 索引及唯一约束通过 migration 管理。

一次同步最多 10,000 条规范化项、100 次上游请求，总时限 60 秒、单请求时限 10 秒、单响应解压后 8 MiB、所有响应累计 32 MiB；超限明确失败，保留旧快照，不把截断结果作为完整目录。上游分页大小不能超过其官方限额。禁止数据库逐模型查询；投影使用有界批量读取/写入，不逐模型调用详情 API 来补缺字段。缺少批量元数据时保留未知能力，不猜测。

无无限重试；重复同步按供应商限频并给出稳定冲突提示。Ark 目录目标为适配器固定官方 HTTPS host，不跟随携带签名的重定向；通用 endpoint 复用并补齐项目出站校验，阻止私网/环回/云元数据地址和重定向绕过，不向任意请求指定 URL 发送凭证。

## 6. 系统场景注册与兼容

在 `@gooes/domain` 建立共享场景定义，在数据库用 migration 同步系统场景注册表：编码、中文名称、输出模态、必要输入能力、系统/历史来源、是否允许新增配置。业务代码与 Admin 使用同一定义。

- “系统生成”指开发接入业务时注册稳定语义编码，随 migration 建立对应场景；不是保存表单时生成 UUID，也不根据中文名称重新生成编码。
- 首批完整保留现有业务固定编码：`customer_log_share_copy`、`decoration_qa`、`decoration_qa_title`、`douyin_budget_explanation`、`marketing_page_block_fill`、`marketing_page_create_fill`、`marketing_page_settings_fill`、`project_operational_risk_summary`、`social_video_script`，以及已有图片场景 `decoration_raw_drawing`。登记图片场景不代表本次交付完整客户生图任务流程。
- 实施前扫描全部实际调用点、migration 和数据库现存场景，验证上述集合的覆盖；存在其他历史编码时完整保留为 legacy，不删除或强改名，已有路由继续可配置主备模型，但不开放新增 legacy 场景。
- 新路由选择中文“业务场景”；编码与模态只读并由后端解析。编辑现有路由不允许换场景身份；保留 `(scene_code, quality_tier)` 唯一性，重复创建返回明确冲突。
- 前端不能决定真实场景编码/模态。新接口接受系统场景身份，service 验证注册状态并派生字段；兼容旧请求时必须核对编码与模态一致、禁止修改已有身份，不静默接受错误值。
- 注册数据、外键/约束、输入能力元数据均走 migration。若同一历史编码存在互相冲突的模态，预检阻止应用并列出冲突，不任意选择一个模态覆盖。
- 运行时已有编码和值保持稳定。本次不顺手重构其他 AI 网关、计费/档位查找及业务流程。

## 7. Admin 交互

复用现有 admin-design 与 shadcn/local 组件，不重新设计整页布局。

供应商区增加目录适配、目录凭证状态、同步操作、最后成功同步时间；已有推理 Key 操作保持独立。无凭证、有权限但未同步、上游拒绝、目录空、能力不匹配分别给出可操作提示。

场景区将自由文本编码输入改为系统场景选择和只读编码/模态。选场景或供应商时清空不兼容选择及旧候选，自动加载新候选；首次编辑加载当前绑定与当前目录，保留已绑定但失效项的告警展示。

主备选择器分别维护请求序号/取消状态，旧供应商、旧模态、旧搜索、旧页码响应不得回写；加载、失败、真正空列表明确区分。只有服务器再次验证过的匹配项能保存；读权限不能触发同步、改密钥或保存路由。保留上一轮供应商受限删除、防重复提交和保存/删除互斥回归。

## 8. 迁移与历史模型处理

分开提交：凭证/目录结构和通用 RPC migration、系统场景注册/约束 migration、经过确认的历史模型修复 migration。所有种子配置初始为空，不包含真实凭证。

现有 Seedream 名称必须先被官方当前目录精确确认，再确定合法调用 ID、输出模态和参考图能力。若存在且确认是图片生成模型，修复前核对该记录全部路由/任务引用；无不兼容引用才通过精确条件和断言的 migration 修正，保留模型 ID 与历史事实。若名字无效或引用冲突，标记需处理并停止自动修复，禁止依据 `seedream` 字样直接改为 image。

回滚应用时保留密钥密文、目录历史、模型和注册表；不还原供应商 CASCADE 外键，不批量删除目录或清空配置。任何数据库回滚另建审核后的 migration。

发布顺序：预检、备份、逐条确认 migration、应用、`supabase migration list` 完整对齐，再发布固定版本 API/Admin。远端发布需用户明确授权，模型收费联调单独确认。

## 9. 验收与实施门禁

1. 官方合同夹具覆盖目录分页、签名、文本/图片区分、Endpoint 与 Model ID 区分；没有真实凭证时只能标记 mock 通过，不能声称方舟实连通过。
2. 密钥用合成夹具验证成对原子替换、空白拒绝、权限前置、非法用途拒绝、旧 API Key 不受影响，响应/日志/审计/浏览器截图均无凭证。
3. 同步验证失败保留旧快照、并发/超时/限额、下线与未知能力处理；旧 OpenRouter 目录、手工兼容和受限删除全部回归。
4. 场景验证固定编码覆盖、派生模态、防篡改、已有编码保留、重复 scene+tier 冲突及 legacy 兼容。
5. E2E 验证选择供应商即加载、图片场景可见合格图片模型、空/错/加载状态、分页、快速切换与迟到响应、权限、窄屏和保存流程；类型及导入检查必须先通过。
6. 隔离 PostgreSQL 执行 migration/RPC/权限/约束及并发测试，不把 SQL 静态测试等同于数据库执行验证。
7. 正式目录读取验收由用户在后台录入只读凭证后执行；验收只读取目录，不调用收费模型、不变更云端资源或现有路由。

本设计的审阅重点：单平台方舟目录账号、同步需明确触发但候选自动加载、场景身份不可改、目录和实际可调用状态分开。通过审阅后再进入 writing-plans；本文件不是已实现说明。
