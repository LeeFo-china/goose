# 租户侧抖音小程序工作台设计

**日期：** 2026-07-26
**状态：** 已完成产品设计确认，待书面评审
**适用范围：** Gooes Admin、API、Supabase migration、现有抖音第三方小程序代开发能力

## 1. 背景

平台已经具备抖音第三方小程序的授权、租户绑定、模板上传、体验二维码、审核、状态同步和发布能力。当前这些能力主要面向平台运营人员，装修公司租户尚无完整、受控的自助入口。

租户侧需要一个独立工作台，用于查看自己的小程序、完成授权和预览、提交抖音审核，并管理由小程序产生的装修咨询线索。平台继续掌握服务商凭据、异常处置和正式发布权限。

## 2. 目标

首版实现以下目标：

1. 每个装修公司租户只能管理一个启用中的抖音小程序。
2. 租户能够自助授权、查看运行状态、生成体验二维码并提交抖音审核。
3. 平台运营人员能够协助授权和异常处理，并独占正式发布权限。
4. 小程序复用现有公开资料、案例和工地数据，不复制内容体系。
5. 业主免费咨询进入独立抖音线索池，经分配、跟进后再转为正式客户。
6. 租户、角色和线索数据严格隔离，任何租户接口都不暴露抖音平台秘密信息。

## 3. 非目标

首版不包含：

- 一个租户同时运营多个品牌或多个城市小程序。
- 短信、电话外呼、抖音私信等外部通知渠道。
- 自动分单、抢单、轮转或基于规则的线索路由。
- 小红书、视频号等多渠道统一营销中心。
- 租户自行正式发布小程序。
- 为抖音重新建设案例、工地或公开资料编辑器。

## 4. 已确认的产品决策

- 一个租户只能有一个启用中的抖音小程序，历史解绑和停用记录保留。
- 租户自助操作为主，平台运营人员可以协助重新授权和处理异常。
- 租户可以提交抖音审核；正式发布只能由平台运营人员执行。
- 新咨询先进入抖音线索池，人工分配后跟进，再按需转为正式客户。
- 租户管理员默认拥有小程序相关权限，并可授权运营和销售人员。
- 名称、Logo、简介和服务区域沿用现有公开资料审核流程。
- 案例和工地沿用现有发布规则，小程序只读取已发布内容。
- 动态内容更新不触发代码上传或抖音审核；模板代码变更才进入版本流程。
- 新线索只使用 Admin 站内提醒、导航角标和待处理列表。

## 5. 总体方案

Admin 新增独立的“抖音小程序”业务模块，包含“小程序工作台”和“抖音线索”两个页面。工作台复用现有抖音安装与版本能力，线索页面承接业主咨询。

现有“服务商资料”、案例和工地页面仍是业务数据的唯一编辑入口。工作台只展示公开状态、数量和快捷入口，避免形成两套数据源。

建议页面路由：

- `/douyin-miniapp/workspace`
- `/douyin-miniapp/leads`

## 6. 页面与交互设计

### 6.1 小程序工作台

页面使用紧凑、可扫描的后台布局，不使用营销型 Hero 或多层卡片嵌套。

顶部状态栏展示：

- 小程序公开名称
- 授权状态
- 当前测试版本
- 当前线上版本
- 审核状态
- 最近同步时间

主体分为四个区域：

1. **概览**
   - 授权主体和运行状态
   - 当前待处理事项
   - 最近一次可信同步时间
   - 线上访问状态

2. **公开内容**
   - 名称、Logo、简介和服务区域的审核状态
   - 已发布案例数量
   - 已发布工地数量
   - 跳转至现有编辑页面的快捷入口
   - 明确区分“内部租户名称”和“小程序公开名称”

3. **预览与版本**
   - 当前测试版本
   - 生成或刷新体验二维码
   - 审核前检查清单
   - 提交抖音审核
   - 审核结果与驳回原因
   - 版本历史分页列表

4. **平台协助**
   - 授权失败、状态异常或版本异常时发起协助
   - 展示协助记录和处理状态
   - 不展示 AppSecret、Token、AES Key、授权票据、部署密钥和模板内部标识

租户已经存在启用中的小程序时，不显示新增入口，仅提供重新授权或停用申请。

### 6.2 抖音线索

页面提供四个业务视图：

- 待分配
- 跟进中
- 已转客户
- 已关闭

列表支持：

- 分页，默认 `page=1&pageSize=20`
- `pageSize` 最大为 `100`
- 状态筛选
- 负责人筛选
- 联系人姓名或手机号搜索
- 创建时间排序

线索详情展示：

- 来源小程序和来源页面
- 关联案例或工地
- 联系人和装修需求
- 提交时间
- 当前负责人
- 跟进记录
- 转化客户

管理员或获授权运营人员负责分配和改派。销售只能查看和跟进本人负责的线索，不能查看其他销售的线索。

### 6.3 站内提醒

首版提供：

- “抖音小程序”导航角标
- 新线索站内提醒
- 工作台待处理事项
- 待分配线索数量

首版不接入短信、外呼或抖音私信。

### 6.4 UI 实施约束

UI 编写必须同时使用项目指定的 `shadcn`、`design-taste-frontend` 和 `impeccable` 规范，并以现有 Gooes Admin 设计系统为最终边界。

设计定位：

> 面向装修公司租户管理员、运营和销售人员的高频后台工作台，采用务实、清晰、可信的 Gooes 黄黑产品语言，强调状态、责任人和下一步操作。

本功能的设计参数固定为：

- `DESIGN_VARIANCE: 3`，保持后台工具的熟悉性和可预测性。
- `MOTION_INTENSITY: 2`，只为加载、状态切换和操作反馈使用短时动效。
- `VISUAL_DENSITY: 7`，支持日常高频扫描，但不压缩中文可读性。

`shadcn` 约束：

- 实施前使用项目包管理器读取 shadcn 项目信息，确认现有组件、别名、基础库和图标库。
- 优先复用 `apps/admin/components/ui/*` 和本地业务组件。
- 使用组件前核对当前版本文档和实际导出，禁止猜测 API。
- 表单使用项目已有 Field 组合；状态使用 Badge；错误使用 Alert；空状态使用 Empty；加载使用 Skeleton。
- 使用语义颜色和现有 token，禁止为此功能单独引入一套颜色体系。
- 未经明确批准，不覆盖或批量更新现有 shadcn 组件。

`design-taste-frontend` 约束：

- 该技能原本不以后台和数据表为主要适用面，因此本功能只采用其审计优先、反模板化、完整状态、可访问性和预检规则。
- 不引入营销 Hero、巨型标题、装饰性图片、玻璃效果、渐变文字、三等分功能卡片或编排型页面动画。
- 不为追求视觉差异破坏标准表格、筛选器、分页、对话框和权限提示的熟悉性。

`impeccable` 约束：

- 使用项目现有 `PRODUCT.md`、`DESIGN.md`、全局 token 和邻近 Admin 页面作为设计依据。
- 工作台采用产品界面规则，状态和下一步操作优先于装饰。
- 全部交互必须具备默认、悬停、聚焦、按下、禁用、加载和错误状态。
- 普通动效控制在 150-250ms，并支持 `prefers-reduced-motion`。
- 中文正文和控件达到 WCAG AA 对比度，操作不能只依赖颜色表达。

页面结构约束：

- 工作台使用平面分区、分隔线、状态标签和必要留白表达层级，不使用卡片套卡片。
- 线索列表使用一个顶层列表工作区，筛选栏和分页固定在工作区内，表格区域独立滚动。
- 版本历史和线索活动记录必须分页，不以无限长列表替代分页。
- 桌面端优先支持高频操作；窄屏下筛选器可换行，表格使用横向滚动，不压缩文字至不可读。
- 所有权限不足、未授权、无数据、加载、同步失败和审核驳回状态都要有专门界面，不允许仅实现成功状态。

UI 完成前必须执行静态检查、浏览器检查和可访问性预检，并至少检查常规桌面宽度、窄屏、长名称、长驳回原因、空列表、错误状态和权限受限状态。

## 7. 核心用户流程

### 7.1 小程序开通

`进入工作台 → 发起授权 → 装修公司扫码确认 → 平台接收授权事件 → 建立安装与租户绑定 → 初始化运行配置 → 工作台显示可用`

若租户已有启用中的安装，服务层拒绝再次绑定；数据库约束作为最终保护。

### 7.2 预览、审核与发布

`完善公开资料 → 检查已发布案例和工地 → 生成体验二维码 → 手机验证 → 租户提交审核 → 同步审核状态 → 平台运营正式发布`

提交审核前必须满足：

- 授权有效
- 运行配置可用
- 公开资料已发布
- 存在可用测试版
- 已生成体验二维码
- 审核必填信息完整

租户端不提供正式发布操作。

### 7.3 线索转客户

`业主提交免费咨询 → 写入抖音线索池 → 站内提醒 → 管理员人工分配 → 销售跟进 → 转为正式客户或关闭`

转客户必须复用现有客户创建业务规则，并保留线索和客户之间的来源关系。

## 8. 状态设计

状态按职责拆分，避免使用一个含义混乱的总状态。

### 8.1 授权状态

- `unbound`：未授权
- `pending`：授权中
- `active`：已授权
- `expired`：授权失效
- `revoked`：已解除授权

### 8.2 运行状态

- `initializing`：初始化中
- `ready`：可用
- `configuration_error`：配置异常
- `suspended`：暂停服务

### 8.3 版本状态

对现有 `douyin_miniapp_releases` 状态进行租户侧展示映射，不另建重复版本表：

- 草稿
- 已上传测试版
- 审核中
- 审核驳回
- 审核通过
- 已发布
- 已被新版本替代

授权、运行和版本状态分别存储或聚合。系统必须能够表达“授权正常但新版本审核驳回”和“线上版本正常但新测试版仍在审核”等组合状态。

### 8.4 线索状态

- `unassigned`：待分配
- `following_up`：跟进中
- `converted`：已转客户
- `closed`：已关闭

状态变化写入活动记录。已转客户状态不可重复执行转换。

## 9. 权限与数据范围

新增租户权限：

- `douyin_miniapp.read`
- `douyin_miniapp.manage`
- `douyin_miniapp.audit.submit`
- `douyin_lead.read`
- `douyin_lead.assign`
- `douyin_lead.follow_up`
- `douyin_lead.convert`

权限默认规则：

- 租户管理员默认拥有全部租户级抖音权限。
- 运营人员可以按角色获得小程序管理、审核提交、线索查看和分配权限。
- 销售人员仅获得线索查看、跟进和转客户权限，并限定为本人负责的数据。
- 平台运营继续使用平台级权限处理全局协助和正式发布。

任何服务都必须同时校验功能权限和数据范围。仅有权限代码但不属于当前租户或负责人时，仍然拒绝访问。

- `tenant_service_provider_profiles`：小程序公开名称、Logo、简介和资料审核状态。

- `source_entity_id`

- `id`

- `metadata`

### 10.3 约束和索引

数据库变更全部通过 `supabase/migrations/` 管理，包括：

- 每租户最多一个启用安装的部分唯一约束或等价原子约束
- 线索幂等键唯一约束
- 线索与活动记录的租户一致性保护
- 转化客户唯一性和状态约束
- RLS/policy 或项目现有等价访问控制
- 权限字典和默认角色权限
- 租户、状态、负责人、创建时间和搜索所需索引

列表查询必须限定字段并使用 `.range()`、`.limit()` 或游标分页，禁止无上限返回全量数据和 N+1 查询。

## 11. API 与服务分层

### 11.1 租户工作台接口

建议提供：

- 获取当前租户工作台聚合状态
- 发起授权或重新授权
- 获取公开资料和内容同步摘要
- 分页获取版本历史
- 生成体验二维码
- 提交当前测试版审核
- 同步审核状态
- 发起平台协助

### 11.2 租户线索接口

建议提供：

- 分页查询线索
- 获取线索详情与分页活动记录
- 分配或改派负责人
- 新增跟进记录
- 更新业务状态
- 转为正式客户

### 11.3 分层规则

- Controller 只读取请求、执行 Zod 校验、调用 Service，并使用统一成功响应。
- Service 负责权限、数据范围、状态机、幂等和业务编排。
- Repository/Gateway 负责 Supabase、RPC、现有客户能力和抖音开放平台调用。
- 所有错误通过 `error-factory.ts` 包装，禁止直接 `throw new Error()`。

现有平台级发布接口继续保留。租户接口不能通过传入任意安装 ID 绕过当前租户绑定。

## 12. 安全数据流

1. 小程序请求到达 API 后，由后端根据可信的小程序身份解析 `installation_id` 和 `tenant_id`。
2. 小程序客户端不能自行指定或切换租户 ID。
3. 公开内容只查询已发布资料、案例和工地。
4. 咨询提交由可信安装绑定写入租户和来源，并使用幂等键防止重复提交。
5. 线索手机号按现有敏感信息规范返回；无查看权限时不返回完整号码。
6. 转客户通过事务型 RPC 或项目现有等价原子机制防止重复转换。
7. 租户响应模型显式排除 AppSecret、消息 Token/AES、授权票据、部署密钥、平台访问令牌和模板内部标识。

## 13. 异常与恢复

- **未授权：** 显示授权引导，不展示虚假的版本或线上状态。
- **授权失效或解除：** 禁止生成新二维码和提交审核，保留历史版本与线索，并提供重新授权入口。
- **公开资料审核中：** 小程序继续展示上一次已发布资料，工作台提示修改尚未生效。
- **审核驳回：** 展示可读驳回原因和整改入口，不展示内部请求或凭据。
- **状态同步失败：** 保留最后一次可信状态和同步时间，允许受控重试，不能误标为审核失败。
- **重复操作：** 授权、上传、审核、分配和转客户使用幂等或状态冲突保护。
- **平台异常：** 创建协助记录，保存租户、安装、版本、错误码和发生时间，禁止前端盲目重试。

## 14. 测试与验收

### 14.1 服务与契约测试

- 租户隔离和角色权限。
- 销售只能访问本人负责的线索。
- 一个租户只能启用一个小程序。
- 授权失效、解除和重新授权。
- 审核提交前置条件、审核驳回和恢复。
- 线索幂等提交、并发分配和单次转客户。
- API 响应秘密字段负向断言。
- 列表分页上限和筛选条件。

### 14.2 数据库验证

- migration 可重复应用于干净环境。
- 约束和索引符合预期。
- 必要时对线索列表关键查询执行 `EXPLAIN ANALYZE`。
- 应用 migration 后通过 `supabase migration list` 验证 Local/Remote 对齐。

### 14.3 Admin 验收

- 工作台加载、空状态、异常状态和恢复入口。
- 权限不足时隐藏操作并由后端再次拒绝。
- 长名称、长驳回原因、移动宽度和分页列表正常。
- 无卡片嵌套，复用现有 shadcn/ui 和本地业务组件。

### 14.4 手机验收

- 租户品牌资料正确。
- 只显示已发布案例。
- 只显示已发布工地。
- 免费咨询成功进入正确租户的线索池。
- 内容变更后无需重新上传代码即可生效。

## 15. 分阶段实施

### 阶段 1：只读工作台与安全绑定

- 新增权限和租户侧导航。
- 建立工作台聚合查询。
- 展示授权、运行、公开资料、内容和版本状态。
- 验证一个启用安装和租户隔离。

### 阶段 2：自助授权、预览与审核

- 发起授权和重新授权。
- 生成体验二维码。
- 增加审核前检查清单。
- 开放租户提交审核。
- 平台继续执行正式发布。

### 阶段 3：抖音线索池

- 建立线索与活动记录 migration。
- 实现分页列表、详情、人工分配和跟进。
- 实现幂等转客户。
- 增加站内提醒和导航角标。

### 阶段 4：异常协助与灰度上线

- 增加平台协助记录和异常恢复入口。
- 完成权限、隔离、状态机和性能验证。
- 进行 Admin 与手机端完整验收。
- 先对测试租户开放，再灰度至装修公司租户。

## 16. 完成标准

满足以下条件视为首版完成：

1. 租户管理员能够在不接触平台秘密信息的情况下完成授权、预览和审核提交。
2. 平台运营能够处理异常并独占正式发布。
3. 一个租户无法产生两个启用中的小程序绑定。
4. 小程序始终展示当前租户已发布的公开内容。
5. 咨询线索能够可靠进入正确租户，完成分配、跟进和单次转客户。
6. 权限、数据隔离、分页、数据库约束和关键异常路径均有验证证据。
