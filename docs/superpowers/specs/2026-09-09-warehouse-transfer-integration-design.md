# D1 库存来源与开关配置设计

用户已确认下一步并要求执行。本批在已有 D1 设计内补齐库存读取兼容和开关写入，不实现 Admin 调拨页面，不开启租户、不授予员工权限，不修改 Orange 或生产。

## 方案

采用现有库存 RPC 的分页后来源查询和供应商设置原子命令扩展。备选由 API 对每条流水查询单据会引入 N+1；另建独立设置接口会重复版本与审计逻辑，因此均不采用。

库存来源增加 `transfer_out`/`transfer_in` 及中文标签，返回 `source_document={transfer_order_id,transfer_order_no,source_warehouse_id,destination_warehouse_id}`。两个方向均校验来源类型、流水类型、明细 ID、租户、SKU、方向仓库以及单据 completed 状态；查不到合法来源返回 null，不拼接错误链接。采购、领料、退料原有来源结构保持不变。分页发生在来源查询之前，单页最多 100 条，保留定制执行计划设置与 ACL。

开关 `warehouse_transfers_enabled` 仅依赖供应商 module_enabled，独立于采购与领退料。平台现有设置入口接收可选 boolean；只要请求包含调拨或领退料开关就使用既有 JSON RPC overload，其余旧请求仍沿用原 typed overload。省略调拨字段在数据库行锁内保留当前值，不能被旧客户端意外关闭；未知字段、错误类型、版本冲突继续拒绝。模块关闭时调拨必须明确关闭或原本关闭。

扩展私有设置 core，不改 typed signatures、不改历史 `_request`，重放先于可变开关／版本校验。设置前后快照与命令审计沿用现有机制。权限继续要求平台员工及现有平台租户管理权限；租户员工不能通过此入口自行启用。读设置 select 新列（D1 列已 apply），历史回执缺该列仍可解析。

## 验证与发布边界

先失败测试，后实现；SQL 在一次性离线 PostgreSQL 中验证新开关、省略语义、旧回执重放、依赖失败原子性及调拨来源／分页。API/Domain 静态检查、相关回归和独立两阶段审查通过后提交。

所有函数变更通过新 migration，已应用 `20260908185501` 保持原样。DEV apply 前完整 plan 差集检查，apply 后 migration list 对齐。若版本兼容允许，维持 false 完成顺序发布；不在来源和客户端兼容验收前启用。开发主机先只读检查容量；不擅自删除备份、镜像或扩大清理范围。容量不满足发布门禁时保留验证代码并报告，不强行发布。
