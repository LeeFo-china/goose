# H5 活动编辑页滚动修复设计

## 问题

AdminShell 使用固定视口，并在主内容区设置 `overflow-hidden`。共享
`H5PageEditor` 的内容高度超过可用视口，但根容器没有占满剩余高度，
也没有建立纵向滚动区域，导致页面下部被主内容区裁掉。

该组件同时用于：

- 平台超管 `/platform/marketing-pages/[id]/edit`
- 装企端 `/marketing/h5-pages/[id]/edit`

## 方案

在共享 `H5PageEditor` 根容器建立页面级滚动边界：

- 使用 `h-full min-h-0` 占满 AdminShell 分配的可用高度。
- 使用 `overflow-y-auto` 让编辑器内容在自身区域纵向滚动。
- 增加底部留白，确保最后一行内容和操作区域不会贴住容器边缘。
- 保留现有三栏布局、编辑行为、接口和权限逻辑。

不修改 AdminShell 的全局滚动策略，避免影响固定高度列表、表头和分页。
不在平台路由单独包裹滚动容器，避免两个 H5 编辑入口行为不一致。

## 验收标准

1. 编辑器根容器具备完整的高度约束和纵向滚动能力。
2. 平台超管与装企端继续复用同一个修复后的编辑器。
3. 页面下部内容可通过编辑器滚动访问，不再被 AdminShell 裁掉。
4. 不产生横向页面滚动，不改变保存、发布、预览和模块编辑行为。
5. 布局回归测试、Admin 类型检查和生产构建通过。

## 验证

- 新增源码布局契约测试，先证明当前编辑器缺少滚动边界。
- 运行相关 Bun 测试。
- 运行 `pnpm --dir apps/admin check`。
- 运行 `pnpm --dir apps/admin build`。
- 浏览器可用时检查桌面和窄视口下的底部可达性；浏览器不可用时明确记录
