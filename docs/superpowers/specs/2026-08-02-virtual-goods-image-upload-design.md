# 微信虚拟商品图片本地上传设计

## 背景与目标

平台虚拟商品映射目前只允许超管手工填写 `item_url`。这要求操作者先在外部准备长期可访问的 HTTPS 图片地址，不符合后台统一配置的使用习惯，也容易因为图片尺寸、格式或可访问性不符合微信要求而在商品上传阶段失败。

本次在“系统配置 → 支付配置 → 微信虚拟支付”的映射表单中增加本地图片上传能力。目标是让超管在同一个表单内完成图片选择、校验、上传和 URL 回填，同时保留 URL 录入作为兼容入口。图片必须是 JPG/JPEG 或 PNG、文件不超过 2 MB，并且像素严格等于 200×200。

本次不修改虚拟商品的数据模型，不新增数据库字段，不改变微信商品上传、发布或校验流程，也不改动小程序仓库。

## 方案比较

### 方案 A：复用图片库上传场景

开发量较小，但图片库场景的权限、文件归属和用途都比支付配置更宽。虚拟商品图片属于平台支付配置资产，复用图片库会模糊权限边界和审计语义。否决。

### 方案 B：由 Admin 服务代理上传

可以在服务端同步完成校验，但会重复现有 COS 直传能力，并让大文件经过 Next.js 服务中转。否决。

### 方案 C：新增专用 COS 直传场景（采用）

新增 `branding_virtual_goods` 上传场景，沿用现有“申请签名 → 浏览器 PUT → 完成登记”链路。API 在签名阶段校验声明，在完成阶段从 COS 读取真实对象并再次校验内容和尺寸。该方案复用现有文件存储基础设施，同时把支付配置权限、文件归属和安全校验保持在独立边界内。

## Admin 交互

商品图片字段保持在映射表单原位置，不新增嵌套 Card：

- 左侧显示 80×80 的正方形预览或占位图，右侧显示“选择图片/更换图片”按钮、上传进度和规范说明。
- 文件选择器仅接受 `.jpg,.jpeg,.png`。选择后，浏览器先校验 MIME、大小和真实像素；不满足要求时立即显示中文错误并且不发起上传。
- 校验通过后立即上传。上传中禁用再次选择和表单保存，显示 Spinner；成功后把稳定公网 `public_url` 回填到当前映射草稿并展示成功反馈。
- 上传成功不自动保存映射、不触发微信商品上传或发布。操作者仍需点击“保存映射”，避免文件选择产生隐式业务写入。
- URL 输入保留在上传控件下方，标记为“或填写图片 URL（高级）”，用于迁移历史数据或使用已有 CDN 资源。手工修改 URL 会清除本地上传状态，但不删除已上传对象。
- 只读状态下可以查看预览和 URL，不显示可操作的文件选择按钮。

生产与沙箱映射各自维护草稿；上传结果只写入当前环境的草稿，不影响另一环境。

## 文件与权限边界

`branding_virtual_goods` 是公开存储场景，对象路径为：

`public/branding-virtual-goods/YYYY/MM/DD/<uuid>.<ext>`

申请签名和完成登记都必须满足：

- 已登录平台超管，`tenant_id` 为空；
- 存在有效员工上下文；
- 具备 `platform.payment.config.manage` 权限；
- `visibility` 必须为 `public`；
- 文件声明为 `image/jpeg` 或 `image/png`，大小为 1 字节至 2 MB。

上传凭证绑定场景、员工、对象路径、MIME、大小和过期时间，防止篡改完成请求或跨场景登记。该场景不授予租户管理员或普通员工。

## 双重校验与存储

客户端校验用于快速反馈，服务端校验才是可信边界。完成登记时 API 必须：

1. 使用 HEAD 确认对象存在，实际大小、Content-Type 和 ETag 与上传声明一致；
2. 以强 ETag 和有界 Range 下载对象，最大读取 2 MB；
3. 解码真实图片内容，确认真实 MIME 与声明一致；
4. 严格确认宽高均为 200 像素；
5. 只有全部通过后才在 `platform_file_objects` 登记 `scene=branding_virtual_goods`，保存真实宽高并返回稳定公网 URL。

任一检查失败都通过现有 error factory 返回 `FILE_STORAGE_UPLOAD_FAILED`，不登记文件对象。已写入 COS 但未登记的失败对象由现有存储生命周期策略清理，本次不引入同步删除或新队列。

## 前端状态与错误

上传状态为 `idle | validating | uploading | succeeded | failed`，并与映射保存状态互斥。错误文案按可恢复动作区分：

- 格式错误：“仅支持 JPG、JPEG 或 PNG 图片。”
- 大小错误：“图片不能超过 2 MB。”
- 尺寸错误：“图片尺寸必须为 200×200 像素。”
- 上传失败：使用现有安全错误归一化，默认提示“商品图片上传失败，请稍后重试。”

重新选择文件会清除上次上传错误；组件卸载或预览替换时释放本地 Blob URL。上传失败不影响继续手工填写 URL，也不阻断映射其他字段编辑。

## 测试与验收

- 纯函数测试覆盖 JPG/PNG、非法 MIME、超过 2 MB、非 200×200 和合法图片元数据。
- Admin 组件契约测试覆盖专用场景、文件 accept、预览、上传态、URL 回填、只读门禁以及“上传不自动保存”。
- API 声明策略测试覆盖 MIME、大小、visibility 和员工上下文。
- API 权限测试覆盖平台超管、缺少权限、租户上下文和缺少员工上下文。
- 上传凭证测试覆盖篡改场景、对象路径、MIME、大小、员工和过期时间。
- COS 完成校验测试覆盖 HEAD 不一致、ETag 不一致、伪造 MIME、解码失败、错误尺寸和合法 200×200 图片。
- 路由测试覆盖 init/complete 均调用专用权限检查并要求上传凭证。
- 完成相关 Bun 测试、API/Admin 类型检查、生产构建和文件大小检查；本次没有 migration，不执行数据库结构变更。
