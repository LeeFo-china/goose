## 2. 盘点流程

一单绑定一个启用的同租户仓库，选择1–100个不同且可访问的启用SKU作为本次盘点范围；并非自动盘点仓库所有物料。未选SKU不受影响，不能把未录入数量视作零。

状态：`draft → counting → submitted → completed`；前三种状态均可取消，两个终态不可编辑。

| 状态 | 展示动作 |
|---|---|
| draft | save_draft、start、cancel |
| counting | record_counts、submit、cancel |
| submitted | complete、cancel |
| completed / cancelled | 无 |

保存草稿只确定仓库、范围和必填盘点原因，不采信客户端账面数量。start 在短事务内读取并冻结选定SKU的余额ID（可空）、余额版本（可空）、数量、价值、单位成本和开始时间，范围此后不可修改。无余额行亦明确记录“行不存在”，不得靠补造零余额行掩盖并发变化。

record_counts 可分批提交已选择SKU的实盘数，每批1–100个不同SKU；未提交项保持“未盘”，可在counting状态修订已录入项。实盘数必须>=0，显式字符串`"0"`代表实际盘为零。每行可带差异原因；一旦实盘数不同于冻结账面数，服务端必须要求该行非空原因。无差异行可省略原因或传null，传入空白字符串视为无效输入，不静默存空理由。

全部选定SKU录入完成后才可submit。提交不改变库存；complete再次验证身份、权限、开关及快照版本，在同一数据库事务内按快照差异过账并完成单据。任何所选余额ID、版本或不存在状态变化均拒绝整个完成命令，包括数量先变后恢复；不自动重抓快照覆盖原始实盘依据。用户取消过时单并创建新盘点，不提供绕过冲突的force参数。

## 3. 数量、计价与财务边界

数量始终十进制字符串，最多14位整数、4位小数，范围`0`至`99999999999999.9999`，原文精度保留。不接受JSON数字、负数、前导零多位整数、指数、空白、NaN/Infinity；金额和数量运算只由后续数据库numeric命令执行。

差异=实盘数-冻结账面数。盘亏按未变化的库存移动平均成本计价，清空该SKU时使用剩余全部价值，避免分币残留；盘盈在账面数量>0时使用该快照的移动平均成本；合法零成本且正数量的库存仍允许按零计价。账面数量为0或无余额行却盘出正数时，没有当前移动平均成本依据，首期阻止过账，不猜测成本或允许客户端填写价格。零库存盘盈估价／期初建账属于独立后续边界，不以本批支持了数量输入而宣称已支持无成本依据入库。

无差异行不生成零数量库存流水；全单无差异可完成，保留盘点审计和成功回执。非零差异每明细生成唯一`adjustment_in`或`adjustment_out`，新来源`warehouse_stocktake_item`。来源明细、流水符号与数量金额在数据库绑定，项目／成本分类为空。不得写项目成本、供应商应付、付款或现金台账；不增加总账库存损益模块。

余额、差异流水、冻结过账金额、单据版本和成功回执整体提交；失败整体回滚。已完成纠错须通过新业务事实，不删原流水、不直接覆盖余额。沿用设置→仓库→单据→按SKU排序余额的锁顺序，覆盖并发开始／完成、调拨、领退料、收货和不存在余额的创建竞争。

## 5. 本批请求契约

拟用资源路径`/warehouse-stocktakes`及`/:id/items`，写命令子路径`save-draft`、`start`、`record-counts`、`submit`、`complete`、`cancel`；本批不注册端点。写请求沿用既有Idempotency-Key头、严格对象和expected_version约定。

保存草稿：

```json
{
  "expected_version": 0,
  "warehouse_id": "abcdef00-0000-4000-8000-000000000001",
  "reason": "季度材料盘点",
  "items": [{ "supplier_sku_id": "abcdef00-0000-4000-8000-000000000002" }]
}
```

录入盘点：

```json
{
  "expected_version": 2,
  "items": [{
    "supplier_sku_id": "abcdef00-0000-4000-8000-000000000002",
    "counted_quantity": "0.0000",
    "difference_reason": "现场复核短缺"
  }]
}
```

其他命令只接收`{ "expected_version": 1 }`。新草稿版本允许0，所有已存在单据命令必须1–2147483647整数；拒绝数值字符串和未知字段。仓库、单据、SKU必须合法UUID，SKU去重忽略UUID字母大小写。草稿原因去首尾空白后1–500字符；行原因若提供必须去空白后1–500字符或null。

列表过滤仅`warehouseId`、合法status、trim后最多100字符keyword及分页。列表和明细默认page1/pageSize20，上限100；明细不接收列表筛选字段。参数、空设置读取query、根对象和每个明细均严格，不允许客户端注入tenant、actor、project、status、账面快照、balance/version、difference_quantity、unit_cost、amount或force字段。

Domain只交付状态、中文标签、展示动作、三类请求DTO；响应模型留给数据库批次依据真实返回明确，避免提前造一组无实现的完整单据字段。展示动作不等于权限判断。
