# 微信支付结算规则选择设计

> 日期：2026-07-21  
> 状态：已确认，进入实现  
> 接入模式：普通服务商 + APIv3 + 平台统一小程序

## 1. 问题

租户进件表单当前要求用户分别填写 `settlement_id` 和 `qualification_type`。这两个字段是微信支付费率结算规则表中的关联值，普通租户不知道技术 ID，也容易提交不匹配的组合。

微信支付特约商户进件接口要求同时提交入驻结算规则 ID 和所属行业。官方对照表当前用于装修公司的无特殊资质通用规则为：

| 主体类型 | 规则 ID | 微信所属行业 | 费率与周期 |
| --- | --- | --- | --- |
| 企业 | `716` | `零售批发/生活娱乐/网上商城/其他` | 0.6%，T+1 |
| 个体工商户 | `719` | `零售批发/生活娱乐/其他` | 0.6%，T+1 |

来源：

- 微信支付特约商户进件“提交申请单”：<https://pay.weixin.qq.com/doc/v3/partner/4012719997>
- 微信支付费率结算规则对照表：<https://pay.wechatpay.cn/doc/v2/partner/4014115425>

## 2. 目标

1. 租户只选择可理解的“经营行业与结算规则”，不接触规则 ID。
2. 一次选择同时确定 `settlement_id` 与 `qualification_type`，不允许错配。
3. 主体类型变化后，表单自动切换到该主体可用的规则。
4. API 继续把两个微信原始字段保存到现有列，并在服务端拒绝篡改或无效组合。
5. 平台详情继续保留原始值用于审计，同时增加可理解的规则名称展示。

## 3. 方案

在 `@gooes/domain` 建立小型、只读的结算规则目录，作为 API 与 Admin 的共同来源。首版只纳入本装修平台实际支持的企业和个体工商户通用规则，不开放与业务无关或需要特殊资质的行业。

每条目录记录包含：

- `id`：提交微信的 `settlement_id`。
- `subjectType`：适用主体类型。
- `qualificationType`：提交微信的行业原文。
- `label`：租户可理解的业务名称。
- `rateLabel`、`settlementCycleLabel`：用于下拉项和辅助说明。
- `requiresSpecialQualification`：首版两条规则均为 `false`。

不新增目录 API，也不新增数据库表。规则总量很小且同时被前后端使用，共享领域常量比 Admin 硬编码或远端动态查询更稳定；微信对照表变化时，通过代码评审更新目录和测试。

## 4. Admin 交互

“经营及结算”步骤移除以下两个文本框：

- 结算规则 ID
- 所属行业

替换为一个 shadcn `Select`：

- 标签：`经营行业与结算规则`
- 选项展示：`装修装饰服务（其他） · 0.6% · T+1`
- 辅助说明：系统会根据主体类型提交微信对应规则，无需填写规则 ID。
- 隐藏提交字段仍为 `settlement_id` 和 `qualification_type`。
- 选择企业时使用规则 `716`；选择个体工商户时使用规则 `719`。
- 编辑历史草稿时，如果旧值不属于当前支持目录，不静默提交旧值，页面切换到当前主体的有效默认规则。

平台超管申请详情显示业务标签，并在次要文本中保留原始规则 ID 和微信行业值，便于审计。

## 5. API 校验

创建和更新草稿时，服务端根据 `subject_type` 查找目录记录，并校验：

1. `settlement_id` 存在且适用于当前主体；
2. `qualification_type` 与该规则完全一致；
3. 不匹配时返回字段级中文校验错误，不保存草稿。

正式提交微信前保留现有 readiness 检查，并再次使用已保存的有效组合构造 `settlement_info`。

## 6. 验证

- 领域目录测试覆盖企业、个体户及无效组合。
- API schema 测试覆盖合法组合、主体错配、行业错配。
- Admin 源码测试确认不再出现可编辑的“结算规则 ID”和“所属行业”文本框，并使用 shadcn Select。
- Admin 类型检查、API 类型检查与相关 Bun 测试通过。
- 浏览器 smoke 验证主体切换时选项自动切换，保存请求仍包含正确的两个微信字段。

## 7. 非目标

- 本次不开放餐饮、医疗、教育等需要特殊资质的行业。
- 本次不做运营后台动态维护结算规则。
- 本次不自动抓取微信网页作为运行时数据源。
- 本次不修改数据库结构。
