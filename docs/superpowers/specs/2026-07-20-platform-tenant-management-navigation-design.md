# 平台租户管理导航整合设计

日期：2026-07-20

## 目标

将平台超管侧边栏中的“平台租户”和“服务商入驻”收敛为一个“租户管理”入口，同时保留正式租户、入驻申请、服务商公开资料各自独立的数据模型、状态机和权限。

## 业务模型

- 装修公司是贯穿流程的业务主体。
- `tenant_onboarding_applications` 是创建租户前的申请和审核记录。
- `tenants` 是审核通过后的正式租户及数据隔离边界。
- `tenant_service_provider_profiles` 是租户可选的一对一公开资料扩展。

前端统一入口不改变上述边界，也不把三套状态合并为一个状态字段。

## 信息架构

平台侧边栏仅保留：

```text
平台运营
  租户管理
```

租户管理工作区提供三个同级页签：

1. 租户列表：正式租户管理、启停、管理员、用量和详情。
2. 入驻申请：租户创建前的申请审核队列。
3. 公开发布：正式租户的服务商资料发布审核。

现有 `/platform/tenants` 和 `/platform/tenant-onboarding` 路由继续保留。共享页签负责在路由之间切换，侧边栏通过激活别名在两个路由下都保持“租户管理”选中，避免破坏现有书签和后端接口。

## 权限

- “租户列表”对平台超管可见。
- “入驻申请”仅在拥有 `platform.tenant_onboarding.review` 时可见。
- “公开发布”仅在拥有 `platform.service_provider.publish` 时可见。
- 侧边栏入口不能绑定任一审核权限，否则拥有租户管理能力但缺少某项审核权限的账号会丢失整个入口。
- 用户直接访问无权限页签时，页面保留当前错误处理，不泄露数据。

## 生命周期跳转

- 已通过的入驻申请在详情中显示“查看已创建租户”，使用现有 `converted_tenant_id` 跳转租户详情。
- 带统一社会信用代码的租户显示“入驻审核创建”，并通过现有列表筛选跳转到对应的已通过申请，不为本次 UI 收敛扩展 API。
- 没有统一社会信用代码关联线索的租户显示“平台创建或历史导入”，不伪造申请记录。

## UI 规则

- 使用现有平台线型页签样式，不增加分段胶囊、嵌套卡片或新的主题色。
- 页面标题统一为“租户管理”，描述随当前页签说明当前任务。
- 页签允许在窄屏横向滚动，文字不缩小、不换行。
- 生命周期跳转使用现有 shadcn `Button` 和 Lucide 图标，保持键盘可达和清晰的动作标签。

## 验证

- 源码单测锁定唯一侧边栏入口、激活别名、权限化页签和双向生命周期链接。
- 运行相关 Bun 测试、`pnpm --dir apps/admin check` 和 `pnpm --dir apps/admin build`。
- 启动 admin，在桌面与移动视口检查侧边栏选中态、页签布局、文字溢出和页面滚动。
