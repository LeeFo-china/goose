# 商品与 SKU 工作区优化设计

## 目标

解决租户新建 SKU 时辅助目录被 rollout 门禁拦截的问题，并让用户在商品列表中直接看到 SKU 总数和已启用数量。查看 SKU 时，使用同一内容区域下钻，不再把 SKU 表追加到商品列表下方。

## 生产配置

生产租户 `3eebca47-961f-4899-b976-a3d3208d326b` 当前只启用了供应商模块，而开发环境已依次启用所有权读取、私有供应商写入和私有目录写入。通过既有平台超管 rollout 业务命令逐级启用这三个能力，保留版本校验、顺序校验和审计记录；禁止直接修改生产数据库。

## SKU 计数

商品列表响应增加 `sku_count` 和 `active_sku_count`。商品分页查询完成后，后端对当前页最多 100 个商品 ID 执行一次批量聚合，避免逐行查询。聚合只读取 `supplier_product_id`、状态和计数，并按平台或租户所有权范围过滤。

商品表新增“SKU”列，主文案显示总数，次要文案显示已启用数量。数量区域可点击并进入对应商品的 SKU 工作区，原“查看 SKU”按钮保留为明确操作入口。

## 同区域下钻

`SupplierProductList` 在商品列表和 SKU 工作区之间二选一渲染。进入 SKU 工作区后，顶部显示返回按钮、商品名称、状态和新增 SKU 操作，下方使用完整宽度展示 SKU 表。SKU 内容不再出现在商品表下方。

当前商品由 URL 查询参数 `productId` 标识。进入、返回和浏览器前进后退都通过该参数同步；供应商选择、搜索和分页参数保持不变。若商品已不在当前结果中，则清理无效参数并返回商品列表。

## 错误与状态

SKU 加载失败时保留工作区并显示现有 toast，允许用户刷新重试。计数聚合失败视为商品列表查询失败，不返回不可信的零值。零 SKU 显示为 `0`，已启用数量显示为 `已启用 0`。

## 验证

- 后端单元测试证明批量计数只执行一次、范围过滤正确且映射到商品响应。
- migration contract 测试证明聚合函数限制商品 ID 数量并按所有权过滤。
- Admin 测试证明商品表显示总数和已启用数、查看 SKU 后商品表被替换、返回后恢复商品表。
- API 和 Admin 类型检查、构建通过。
- 生产租户 rollout 配置与开发环境对齐，新建 SKU 弹窗的规格定义和单位接口不再返回 403。
