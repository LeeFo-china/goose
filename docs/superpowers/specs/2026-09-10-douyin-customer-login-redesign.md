# 抖音小程序客户登录页重构设计

**日期：** 2026-09-10
**状态：** 设计已确认
**范围：** `apps/douyin-mini/src/pages/customer-login`

## 1. 背景

当前客户登录页同时展示一键登录按钮、手机号输入、验证码输入和登录按钮，所有操作以
相近的视觉重量纵向堆叠。页面重复出现“客户登录”和“我的项目”两层标题，表单容器与
黑色大按钮占据过多空间，客户无法快速判断首选登录方式。

本次采用已确认的方案 A：突出抖音手机号一键登录，将短信验证码登录作为可展开的备用
方式。重构只改善信息层级、视觉样式和交互状态，不改变认证接口、客户身份解析、候选
身份选择或登录后的导航规则。

## 2. 设计目标

1. 客户进入页面后首先理解登录用途和可查看的项目内容。
2. 抖音手机号授权是唯一主操作，减少选择压力。
3. 短信验证码登录易发现，但默认不与主操作争夺注意力。
4. 表单标签、验证码倒计时、加载、错误和重复提交状态完整。
5. 页面视觉与装修服务的可信、克制、生活化定位一致。
6. 适配常见抖音小程序手机宽度，不出现文字溢出或控件跳动。

## 3. 非目标

- 不修改后端登录接口或 token 结构。
- 不修改手机号与客户档案的匹配规则。
- 不改变多客户身份候选的业务字段和选择结果。
- 不新增第三方依赖、图片资源或数据库 migration。
- 不重构其他小程序页面。

## 4. 信息架构

页面从上到下分为四个区域：

1. 原生导航栏保留“客户登录”，页面内不再重复显示“我的项目”。
2. 紧凑欢迎区显示租户标识、标题“查看我家的装修进度”和一句说明。
3. 登录区首先显示“使用抖音手机号登录”主按钮，再通过“其他登录方式”分隔线提供
   “使用短信验证码登录”入口。
4. 需要选择身份时，用候选身份列表替换登录区，避免登录表单和候选列表同时堆叠。

欢迎区说明使用客户能理解的结果语言，例如“登录后查看项目进度、施工日志和现场照片”，
不在页面内解释认证技术或操作教程。

## 5. 登录交互

### 5.1 抖音手机号登录

- 使用抖音手机号授权按钮作为页面唯一实心主按钮。
- 授权或登录请求进行中时保持按钮尺寸不变，显示短状态文案并禁用重复点击。
- 用户拒绝授权或授权失败时，在主按钮附近显示简洁反馈，同时保留短信登录入口。
- 登录成功后沿用现有规则进入“我的项目”。

### 5.2 短信验证码登录

- 默认只显示“使用短信验证码登录”次操作。
- 点击后在当前位置展开表单，不跳转新页面。
- 手机号和验证码使用显式字段标签，不以 placeholder 代替 label。
- 获取验证码使用描边按钮；发送成功后按钮原位显示倒计时，宽度保持稳定。
- “验证并登录”仅在短信表单内作为提交操作，不与一键登录形成两个并列主按钮。
- 再次点击短信登录入口或使用收起按钮时，可以收起表单，已填写内容在当前页面生命周期内保留。

### 5.3 多身份选择

- 返回多个客户身份时，隐藏两种登录方式，显示“选择装修公司”标题和候选列表。
- 每个候选项展示装修公司名称和现有辅助信息，整行可点击。
- 选择提交期间锁定所有候选项；失败后保留列表并在列表附近显示错误。

## 6. 状态与错误

- 页面级加载不遮挡原生导航栏。
- 一键登录、验证码发送、短信登录和身份选择分别维护提交状态，防止重复请求。
- 字段格式错误显示在对应输入框下方。
- 网络或服务错误显示在触发操作附近，不只依赖短暂 toast。
- 错误反馈不泄露手机号是否存在客户档案；身份匹配结果沿用后端现有业务提示。
- 键盘弹出后，当前输入框和提交按钮仍应可见并可滚动到达。

## 7. 视觉规范

- 页面背景使用现有冷灰色基底，内容区不使用大面积纯黑。
- 欢迎区使用启动数据中的租户主色；无法取得有效主题色时使用现有安全默认色。
- 主按钮、焦点和关键强调使用同一租户主色，正文使用高对比中性色。
- 默认圆角不超过 8px，不使用胶囊按钮、渐变、玻璃效果或大范围投影。
- 登录区使用分隔线和留白建立层级，不使用 Card 套 Card。
- 标题保持移动端功能页尺度，不使用营销页式超大字号。
- 控件设置稳定高度和响应式宽度，发送验证码文案变化不引发布局位移。
- 交互过渡控制在 150 至 250 毫秒，并尊重减少动态效果设置。

## 8. 数据与实现边界

- 页面通过现有 `getApp().startup` 获取公司名称、logo 和主题色，失败时使用本地默认值，
  不为视觉样式新增接口请求。
- 继续复用现有客户认证 API、`CustomerSessionManager` 和登录结果处理逻辑。
- 展开状态和各操作状态属于页面本地 UI 状态，不进入全局 session。
- TTML 负责语义结构，TTSS 负责响应式布局，`page.ts` 只增加展示状态和现有流程所需的
  状态转换。

## 9. 验收标准

1. 首屏只出现一个实心主操作，且一眼可识别为抖音手机号登录。
2. 页面不再同时展示完整短信表单和一键登录按钮。
3. 展开短信登录后，手机号、验证码、获取验证码和提交操作层级清楚。
4. 发送验证码后倒计时不改变布局宽度，重复操作被阻止。
5. 多身份结果出现时不再显示登录表单。
6. 登录接口、身份绑定、客户 token 存储和成功导航行为与现状一致。
7. 320px 至 430px 等效视口下无横向滚动、文字溢出和按钮遮挡。
8. 页面相关单元测试、TypeScript 检查和小程序构建通过。

## 10. 验证方式

- 为短信展开、提交锁定、主题回退和多身份替换状态补充页面单元测试。
- 运行 `apps/douyin-mini` 现有测试和 TypeScript 检查。
- 在抖音开发者工具中分别检查窄屏和常规手机视口，并完成一键登录拒绝、短信登录、
  多身份选择和网络失败 smoke。
