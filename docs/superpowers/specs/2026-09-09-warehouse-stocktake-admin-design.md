# D2.1 盘点 Admin 与受控 DEV 验收设计

## 授权与范围

用户“执行”接受上一批建议：Admin 盘点页面、来源跳转和平台开关，然后 apply、开发发布及固始晴天装饰工程有限公司验收。常规确认按既有统一授权执行；不发布生产、不修改 orange、不扩展手工调整 D2.2、不普遍授予权限。复用隔离工作树 feature/warehouse-transfer-admin-mainline，基线 4f54d15f。

## 方案选择

1. 采用现有调拨工作台的信息结构、分页选择器与本地 shadcn 组件，新增盘点领域适配层。只把确实相同的冻结请求与分页机制提取为共享组件，保留调拨行为及测试。
2. 通用库存单据引擎会扩大状态机和回归面，本批不选。
3. 全流程弹窗向导不利于多次录入、历史查阅和来源链接，本批不选。

沿用 PRODUCT.md / DESIGN.md 的密集、清楚、可信赖业务界面。平面工作区、语义色、原有字体、骨架/空态/错误态；不换品牌、不安装依赖。add-component 模板的 TanStack Router 基座不适用本仓库，仅参考明细导航原则。

## 页面与动作

- `/warehouse-stocktakes?order_id=…` 服务端会话与员工校验；库存查看权限决定历史访问和菜单/库存页入口，无项目或采购权限依赖。
- 单据列表 page=1/pageSize=20，最大100；单号/原因搜索、状态、仓库筛选，旧停用仓库仍可筛选。每次筛选重置页码，迟到响应不得覆盖新页面。
- 草稿选择一个启用仓库和1–100个唯一SKU，只发送 expected_version、warehouse_id、reason、items[].supplier_sku_id。SKU选择复用有界库存选择器；支持零余额已有SKU。已保存草稿锁定仓库，更换需新单。编辑前一次有界获取全部≤100行并核对总数、唯一行/唯一SKU、单据/租户/仓库身份，任何不完整均不得覆盖保存。
- 开始盘点确认后冻结账面快照；详情显示账面数量、实盘数量、差异数量、差异原因、冻结成本与完成后的金额，不通过 Number 计算数量或金额。
- 盘点中可分批录入并保存；空白不代表0，不发送空白项，显式字符串0合法。14位整数、4位小数、非负十进制；精确比较差异，非零差异必须填写≤500字符原因。每次录入使用当前版本，已保存实盘不因分页丢失；未保存输入切页/关闭须防丢失。
- 全部实盘保存后才可提交；待确认单仅 approve 权限可完成。manage 可编辑/开始/录入/提交/取消，approve 不自动拥有 manage；终态只读。开始/提交/完成/取消使用带标题的确认对话框和当前版本。
- 版本冲突重新读取但不自动重发；快照冲突明确取消后重盘，不提供强制完成。无成本基础盘盈说明服务端阻止原因，不允许录入单价绕过。
- 功能关闭仍读历史，配置读取失败/非法值阻止新写；成功回执必须匹配动作、单据、目标状态与精确下一版本才确认。
- 冻结命令按账号/租户/员工隔离持久化原路径、body字节与幂等键。网络/5xx/408/429/非法成功回执为未知结果，锁住新写，只能重试原请求；刷新、关闭开关、重新读取配置都不改变原命令。重试401/403/404仍保留；旧实例/旧响应不得消费新实例命令，存储不可用时阻止写入。

## 来源与平台配置

- adjustment_in/out 的 stocktake_order_id/no 显示“盘点单”并跳转，不能落入采购收货来源分支；空来源仍明确不可用。
- 新平台“仓库盘点”开关仅依赖供应商模块，与采购、领退料、调拨独立；盘点开启时阻止关闭模块。
- 新字段 warehouse_stocktakes_enabled 可选兼容旧响应。新管理员请求保持已有true值；旧响应缺失且无明确盘点意图时省略该字段，避免覆盖远端状态。明确开/关时发送布尔值。已有冻结请求不重建、不补字段。
