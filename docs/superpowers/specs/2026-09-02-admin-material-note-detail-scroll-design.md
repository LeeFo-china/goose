# 租户后台资料笔记详情滚动修复设计

日期：2026-09-02

## 背景

租户后台资料笔记列表进入详情页后，版本历史和正文编辑区域可能超过当前视口高度。
页面下方内容会被裁切，且无法通过页面滚动继续查看。

问题页面：

`/douyin-miniapp/materials/:id`

## 根因

后台 `AdminShell` 的主内容容器使用 `overflow-hidden`，以避免全局页面和业务工作台出现
双重滚动。各业务页面必须在自身高度边界内声明滚动区域。

资料笔记详情组件根节点目前只有纵向布局和底部留白，没有：

- `h-full`：继承主内容区域的可用高度；
- `min-h-0`：允许 flex 子项在视口内收缩；
- `overflow-y-auto`：承接超出视口的纵向内容；
- 稳定滚动条占位：避免长短内容切换时横向跳动。

因此正文超出 `AdminShell` 主区域后，被父级 `overflow-hidden` 裁切。

## 方案比较

### 方案 A：详情页根容器承接滚动（采用）

为 `MaterialNoteDetail` 根容器补齐完整高度、flex 收缩和纵向滚动能力，并保留现有内容
结构、间距和底部留白。

优点：

- 改动只影响资料笔记详情页；
- 页面只有一个纵向滚动区域；
- 与后台工作台、平台详情页等既有实现一致；
- 不改变接口、状态管理、正文编辑器或版本分页。

### 方案 B：正文编辑器内部滚动（不采用）

版本历史保持固定，只让正文编辑区域滚动。该方案会形成页面内容与编辑器的嵌套滚动，
在窄屏、长表单和键盘操作时不易判断当前滚动焦点。

### 方案 C：修改全局 AdminShell（不采用）

将全局主内容容器改为 `overflow-y-auto`。该方案会影响所有后台页面，并可能与已有表格、
财务和工作台内部滚动区域产生双滚动，回归范围明显超过本缺陷。

## 详细设计

修改 `apps/admin/components/douyin-miniapp/material-note-detail.tsx` 的最外层容器，使其：

1. 使用父级提供的完整内容高度；
2. 在 flex 布局内允许收缩；
3. 超出高度时提供纵向滚动；
4. 使用稳定滚动条 gutter；
5. 保留 `gap-5`、底部留白，并增加少量右侧留白，避免滚动条贴近正文。

不新增组件、不改变页面层级、不固定头部、不引入嵌套滚动，也不修改全局 Shell。

## 测试与验收

先在现有 `material-note-ui.test.tsx` 增加失败合同测试，明确详情组件根容器必须同时包含：

- `h-full`；
- `min-h-0`；
- `overflow-y-auto`；
- `[scrollbar-gutter:stable]`。

测试失败原因必须是当前详情页缺少上述滚动边界。随后只修改详情根容器使测试通过。

完成后执行：

1. 资料笔记 UI 聚焦测试；
2. Admin 类型检查和构建门禁；
3. 浏览器可用时，在长正文详情页验证滚动到底部、版本切换及窄屏内容完整性。

如果浏览器仍不可用，必须如实记录未完成的视觉 smoke，不以静态测试替代真机/浏览器
验收结论。

## 发布边界

本修复不涉及 API、数据库、migration、权限或抖音小程序代码。验证通过后只需构建并发布
Admin dev 服务；无需重新发布 API 或执行数据库迁移。
