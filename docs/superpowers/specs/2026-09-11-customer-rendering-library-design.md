# 客户 AI 装修效果库方案

日期：2026-09-11。状态：方案草案；用户已确认的方向与本方案建议默认值分别列出。本文定义产品、业务和技术边界，不表示功能已实现或开发环境已验证。

## 1. 目标与已确认条件

装修公司在 Admin 上传装修效果图，客户在微信或抖音小程序浏览、选择风格，上传自己的房间照片，由 AI 生成装修预览，再根据最终生成图片获得配色、材质、家具软装搭配建议。

用户明确的条件：

- 生图使用火山方舟；用户说明开发服务器已配置 Endpoint 和 Key，协议为 `openai_compatible`。
- 首次可以免留手机号试用；第二次必须留手机号；单客户累计最多使用 5 次。
- gooes 负责 API、Admin、抖音小程序、共享 domain 和数据库 migration；orange 仅只读参考。

本方案建议的首期默认值，供业务评审：

- 配额按同一装修公司累计计算，首次包含在 5 次内，不按日重置；绑定同一已验证手机号后跨渠道合并配额。
- 一次生成一张单房间预览，附一份建议；首期客厅、卧室，软装调整或整体翻新两个意图。
- 一张房间主照片和一张选中的风格图参与生图；户型图可以上传，但只作为咨询辅助资料，首期不参与空间推演。
- 客户不付费；装修公司承担体验额度，平台记录实际成本并控制总预算。
- 手机号绑定不等于同意营销联系；客户主动提交咨询后进入销售待跟进。
- 历史方案首期按原渠道已认证身份展示；跨渠道共用次数不自动开放另一渠道历史私密照片。

不包含整屋结构复原、多视角一致性、CAD/施工图、自动报价、家具品牌或 SKU 精确识别、客户在线购次、自训练模型、自由上传任意风格图、公共发布客户生成图。

## 3. 产品信息架构

“装修效果库”包含两个不同用途的集合：公司发布的风格素材、客户私有的 AI 方案。客户端入口可合并，权限和数据归属必须分开。

### 3.1 Admin：公司风格素材

- 租户菜单新增“装修效果库”，有素材列表、上传编辑、生成用量和已授权咨询入口。
- 素材字段：标题、空间类型、风格标签、配色说明、材质及搭配说明、来源类型、使用授权声明、封面、排序、发布状态。
- 来源类型区分实景案例、设计效果图、AI 概念图；AI 图不展示成施工实景。
- 支持一次选择最多 20 张，逐张显示进度和错误；每张文件最多 10 MB；批量设置公共标签后可以单独修改。
- 草稿保存为私有，审核通过并发布后才生成可公开浏览的展示资产；失败图片可单独重试。
- 支持草稿、已发布、已隐藏；隐藏阻止新的客户生成，保留历史任务引用。已经公开的图片可能存在外部缓存，隐藏不承诺撤回外部副本。
- 首期使用系统管理的空间/风格字典，分类本身仍支持分页；不开放自定义提示词覆盖业务约束。
- 客户私有照片不出现在素材管理中；上传素材权限不包含客户方案查看权限。

### 3.2 小程序：浏览和生成

进入页面即可浏览已发布素材。列表默认每页 20 张，最多 100；卡片使用缩略图，进入详情才加载大图。

详情上方为参考效果图及标签，下方为“看看你家装成这样”的上传区。显示已选风格、房间主照片、空间类型、改造意图及可选的保留家具说明（最多 300 字）。不要求用户输入模型或提示词。

选择首张照片前提供拍摄示例：能看清房间全貌、门窗与地面，避免镜面反射和人物。校验朝向、尺寸、内容及图片类型；HEIC 转为模型支持格式，不把仅改后缀当作转换。

首次生成前显示：

> 可免手机号体验 1 次，绑定手机号后累计可生成 5 次。效果仅供装修沟通参考。

第二次点击生成时显示：

> 首次体验已使用，绑定手机号后还可免费生成 4 次。

数字来自服务端剩余额度，不在客户端固定写 4。拒绝绑定仍可浏览和查看已生成结果。

结果页：原图/结果切换或滑动对比、AI 标识、建议卡片、剩余次数、重新生成、我的方案、预约量房。达到上限不影响历史查看和已允许的下载。

### 3.3 方案建议

建议基于最终输出图、原房间图和用户选择生成，结构分为：配色、材质视觉搭配、家具软装、需要现场确认的事项。

每条建议区分 `observed`（画面观察）和 `suggested`（搭配建议），服务端严格解析结构与长度。不得声称识别出真实品牌、精确漆号、尺寸、隐藏管线或承重结构。图像中的颜色值至多是屏幕近似参考，不能作为购买色号。

生图尽量保留门窗、视角、墙体与空间关系，但这不是几何保证。结果复核发现明显门窗消失、布局改变时，不将其作为可交付结果；记录失败原因。材料用量、正式预算及拆改由设计师确认。

## 4. 用户身份与次数

### 4.1 身份边界

体验用户可以没有 CRM 客户档案。不能为了体验生图自动创建正式客户，也不能要求既有客户项目登录成功才能领取第二次额度。

- 抖音：校验安装实例、app、租户和 subject；服务商实例未确定具体装修公司时不开放生成。
- 微信：校验已有访客或客户会话，并从可信分享入口/服务端确认的公司选择建立租户上下文；不信任任意 body 中的 `tenant_id`。
- 手机号：使用服务端消费的平台授权 code 或已验证短信结果；不能由客户端布尔值声明已验证。
- 已验证手机号的客户首期共 5 次，免手机号试用不额外赠送第 6 次。
- 额度主体独立于 CRM `customer_id`，可用已有稳定身份或租户范围的手机号 HMAC 关联。手机号查询标识使用服务端密钥与版本，避免可枚举的裸 SHA256。
- 手机号变更、解绑重绑、删除方案、换房间或清除本地缓存均不清除已用事实；合并历史账目按任务 ID 去重。
- 同手机号绑定仅用于额度关联，不自动合并 CRM 档案、不自动授予其他身份的图片访问权。更换号码和历史文件恢复沿用明确的身份绑定规则。

### 4.2 配额规则

| 状态 | 可用数量 | 行为 |
| --- | --- | --- |
| 未验证手机号，未成功试用且无预占 | 1 | 允许一次任务 |
| 未验证手机号，已成功试用 | 0 | 提示绑定手机号 |
| 已验证手机号 | `max(0, 5 - consumed - reserved)` | 允许剩余额度内任务 |
| 存在执行中的任务 | 当前任务继续 | 同一主体不能再次提交不同任务 |
| 技术失败或审核不通过 | 释放该任务预占 | 失败不扣用户次数，但适用尝试频控 |
| 可交付图片已保存且通过审核 | 核销 1 次 | 建议失败不退次数、不重画图片；免费补建议 |
| 主动重新生成/换风格生成 | 新预占 1 次 | 与网络重试区分 |

第一次的服务端识别精度是“平台账号”，不能承诺准确识别自然人。绑定之前，微信、抖音可能各试用一次；绑定后将两端已知成功和执行中任务计入同一额度账户，例如两端各成功一次后剩 3 次。已有总数大于等于 5 时剩余归零，历史不撤销。

绑定合并与任务提交在数据库事务中锁定相关账户，锁顺序固定。主体别名永久指向规范账户；进行中任务不丢预占，Worker 完成时按规范账户结算。合并后若存在多个历史在途任务，允许这些已受理任务完成但阻止新提交，并保留超额来源证据。

### 4.3 尝试频率和租户成本

建议默认每个主体 10 分钟最多 3 个新任务、每日最多 10 个新任务；所有失败尝试也计入频控，同幂等键重放不计入。每天按 Asia/Shanghai 切换尝试窗口，累计 5 次权益不重置。

租户另设每日任务上限和费用预算，两者均为启用前必填的正数，未设置时关闭生成。费用包含审核、图片、文字建议及必要重试的预算预占，结算依据实际调用记录；配置不允许无限预算。

小程序只得到“今日体验名额已用完”等稳定业务提示，不暴露租户余额、内部成本或供应商错误。

## 5. 火山方舟接入设计

协议继续为 `openai_compatible`，不要求装修公司维护供应商或 Key。平台分别为 `customer_room_rendering` 和 `customer_rendering_advice` 配置已验证的模型；前者生图，后者为可输入图片的视觉理解模型。

当前 Endpoint 与基础地址的语义不同。建议新增可选供应商字段 `api_base_url`，供新生图适配使用；保留现有 `endpoint_url` 完整对话地址及旧网关行为。新字段、校验和 Admin 文案只在明确的 migration 与适配任务中实现，不静默重写旧地址。

| 配置/调用 | 北京地域示例 |
| --- | --- |
| 新基础地址 | `https://ark.cn-beijing.volces.com/api/v3` |
| 现有对话完整 Endpoint | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` |
| 新生图实际请求 | 基础地址 + `/images/generations` |

新生图场景显式使用方舟适配器，不因协议名为 `openai_compatible` 就假设所有供应商支持方舟参数。基础地址由平台管理员配置并校验，客户端不提供请求地址。模型标识使用平台已开通、实测有效的 ID，不预写未经验证的具体版本。

平台模型管理需增加“经过能力验证的图片模型注册/选择”，当前只允许 text 的手动模型入口不能直接充当图片配置。能力至少验证：输入两张参考图、支持选定输出尺寸、单图输出、费用使用量字段、审核行为、结果下载与失败分类。视觉建议模型另外验证图片输入及结构化文本输出。

生图输入角色明确为“房间结构主图”和“风格参考图”，参考顺序、提示词、图片规格和模型版本写入任务快照。单图模式使用官方支持的参数，保留 AI 标识；不把聊天 `messages` 直接提交到生图接口。

调用成功返回的结果先校验类型、大小和下载地址，再转存私有 COS，之后标记图片可交付。供应商临时 URL 不作为长期方案地址。客户端只接收应用生成的短时签名访问链接。

## 6. 任务状态与恢复

采用数据库持久化任务和独立 Worker；复用现有 Worker 部署模式，不引入 Redis 或新消息队列。

```text
创建任务并预占额度/预算
  → queued → submitting
  → 明确得到结果：保存私有图片 → 审核通过 → 核销一次 → 生成建议
  → 明确失败：failed → 释放用户预占 → 结算实际供应商成本
  → 是否提交成功未知：submission_unknown → 查询/对账/人工处理
```

方舟同步生图请求与应用异步任务是不同层次，不能假设方舟天然有任务查询接口或支持幂等。能力验证决定能否查询/恢复；无法确认供应商接收状态时不自动再次生图。提交前持久化 attempt、租约和请求摘要；不得把普通 lease 超时等同于未提交。

任务、图片、建议和费用各有独立状态。内部任务状态优先沿用 `AiGenerationStatusSchema`；图片就绪后可返回 `result_ready` 的业务展示阶段，同时独立返回 `advice_status=pending/succeeded/failed`。业务展示阶段不是另一个通用任务状态枚举。

- Worker 用数据库 claim、租约与完成版本校验防止重复执行；不能用 API 进程内未等待的 Promise 运行长任务。
- 未知提交状态期间保留预算和用户预占，禁止重复执行；超过运营 SLA 后可人工关闭并释放用户预占，但费用继续可对账，迟到结果不得重新扣用户次数或自动交付。
- 图片已返回但存储失败，优先重试下载/转存，不重新生图；临时结果不可恢复时按失败处理。
- 输入/输出审核不通过不向用户暴露违规结果；失败尝试保留限流，避免无限免费调用。
- 建议失败仅重试建议，服务端自动重试最多 1 次；仍失败时可显示用户触发的补充建议入口，最多再 1 次并计入预算，之后转人工咨询。
- 任务取消首期只允许 queued，提交后的任务不向用户承诺可取消供应商计费。
- 小程序前台按 3/5/10 秒逐渐降低轮询频率，后台停止轮询；回到页面查询当前状态，不重新提交。

## 7. 数据模型与权限

下列为拟新增逻辑实体，执行时对照最新通用 AI 实现选择复用或创建，不复制账本。

| 实体 | 关键事实/约束 |
| --- | --- |
| 租户效果素材 | tenant、标题、空间/风格、授权及来源、发布状态、版本；租户复合外键 |
| 素材文件关联 | 素材、私有源文件、公开展示规格、审核状态；公开与私有对象分离 |
| 效果库设置 | tenant、启用开关、每日任务上限、费用预算、保留策略版本 |
| 体验身份关联 | tenant、渠道、app/安装、subject、规范额度账户；关联唯一 |
| 额度账户和只追加事件 | tenant、规范账户、任务、reserve/consume/release/merge；按任务去重 |
| 客户效果方案 | tenant、原始 actor、参考素材版本、输入文件、用户要求、可选 CRM 关联 |
| 生成任务与 attempt | 方案、幂等键、请求摘要、供应商/模型快照、状态、租约、费用和失败码 |
| 结果与建议 | 任务、私有文件、审核、建议结构、提示词版本、保留期限 |
| 咨询授权记录 | tenant、actor、方案、允许共享的资产、用途、时间和撤回状态 |

列表默认 `page=1&pageSize=20`，最大 100；只选必要字段，禁止关联后在内存分页。索引覆盖租户/发布状态/空间/风格/排序、主体/创建时间、可领取任务/下次处理时间。大列表筛选避免先取全量素材 ID 再 IN 查询。

设计权限为 `rendering_library.read/manage`、`rendering_consultation.read`，用 migration 注册并沿用角色授权方式。素材管理不授予咨询查看；咨询查看还必须满足现有线索负责人/部门数据范围及有效客户授权。平台运维默认查看脱敏状态和费用，不能因运维权限看到客户原图。

所有直接访问 Supabase/COS/模型 HTTP 的代码位于 repository/gateway；controller 只校验 HTTP、获取上下文、调用 service 并包装结果。新错误通过 `error-factory.ts` 返回。

## 8. 拟定 API 契约

以下路径是方案中的新增接口，尚未发布；最终 shared domain 合同与接口 smoke 通过后才能作为客户端开发依据。

双端分别使用 `/douyin-mini/renderings` 与 `/visitor/renderings` 前缀。薄 controller 做各自认证，复用同一业务 service；不扩大抖音 token 到全部访客/租户接口。

| 方法与相对路径 | 请求与返回 | 权限/幂等 |
| --- | --- | --- |
| GET `/styles` | page/pageSize、space、style；返回已发布素材 list/pagination | 可信公司上下文 |
| GET `/styles/:id` | 素材详情、展示图及标签 | 隐藏素材不可创建新任务 |
| GET `/quota` | trial_used、phone_verified、consumed、reserved、remaining、active_job_id、can_generate、blocked_reason | 当前体验身份 |
| POST `/phone:bind` | 服务端可验证的手机号凭据、idempotency_key；返回最新 quota | 绑定当前主体；不返回完整手机号 |
| POST `/uploads:intent` | purpose=room/floor_plan、mime、bytes；返回限对象上传凭据/意图 ID | 当前主体及公司；限制大小与数量 |
| POST `/uploads/:id/complete` | 确认上传；返回 file_id、审核状态 | 服务端 HEAD/内容校验；幂等 |
| POST `/jobs` | style_asset_id、room_file_id、可选 floor_plan_file_id、space、mode、keep_notes、idempotency_key | 原子预占，返回 202 和 job_id/quota |
| GET `/jobs/:id` | status、stage、advice_status、result、稳定错误码 | 仅所属主体或经明确授权的访问者 |
| POST `/jobs/:id/advice:retry` | idempotency_key；返回当前任务/建议状态 | 图片已就绪且未超过建议重试次数 |
| GET `/history` | list/pagination，缩略图按权限短时签名 | 当前渠道已认证主体；不按裸手机号开放历史 |
| DELETE `/history/:id` | 返回删除受理状态 | 隐藏方案并异步清理文件；不重置额度 |
| POST `/consultations` | job_id、contact_consent、share_asset_ids、idempotency_key | 已验证手机号；事务记录授权和线索来源 |

租户管理接口使用 `/tenant/rendering-library`，支持素材 CRUD/发布/隐藏、设置读写、用量分页查询及授权咨询详情。创建/修改均验证文件租户、权限和版本；统计只返回聚合，不附原始家庭图片。

错误语义：401 会话失效；404 资源不存在或不应暴露其存在；409 `RENDERING_PHONE_REQUIRED`、`RENDERING_QUOTA_EXHAUSTED`、`RENDERING_JOB_ACTIVE`、`RENDERING_IDEMPOTENCY_CONFLICT`；422 `RENDERING_IMAGE_REJECTED`；429 `RENDERING_RATE_LIMITED`；503 `RENDERING_UNAVAILABLE`。达到租户每日容量用 429 `RENDERING_DAILY_CAP_REACHED`。数据库及供应商细节不直接透传。

相同主体+操作+幂等键且相同请求摘要返回原结果；相同键不同内容返回 409。输入全部解析完、校验归属和素材可用状态后才创建任务；已成功接受的幂等重放不因素材后来隐藏而重新占次数。

## 9. 文件隐私与内容治理

- 家庭原图、户型图、生成结果默认私有；不沿用公共图库上传 scene。
- 模型侧传输采用服务端提供的短期受控访问或模型支持的文件内容，URL 有效期覆盖本次拉取窗口但不永久公开。
- 下载只允许受信的供应商结果地址，校验重定向、IP 范围、文件类型和大小，防 SSRF；客户端不能提交任意 URL 让服务器抓取。
- 输入元数据清理 EXIF 定位信息；不把私人图片、签名 URL、Key 或完整手机号写入普通日志。
- 公开素材和输入、输出均经过内容审核；审核供应商与开通权限在正式启用前验证，审核不可用则关闭新生成。
- 页面、下载图片保留 AI 标识；转码/转存需要保留或补充适用的显式与隐式标识。
- 建议默认：未提交任务的上传 24 小时清理，家庭输入保留 30 天，生成图/建议保留 90 天；展示到期时间。客户删除立即撤销读取并在 24 小时内清理受控存储对象，备份过期策略另行披露。
- 成功次数、幂等和费用保留最小审计事实，删除方案不返还已消费权益；账户注销的数据处理与保留依据纳入正式隐私评审。
- 租户员工读取私有结果必须同时经过授权与线索范围检查；客户撤回共享后不再签发新链接，已签发短链存在短时有效窗口，应在说明中体现。

双端提审前分别核对主体、类目、模型使用证明与隐私说明；供应商已备案不等于每个租户小程序已经完成材料。

参考：[抖音手机号能力规范](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/tutorial/open-capabilities/general-capabilities/new-phone-method)、[抖音 AI 标识要求](https://developer.open-douyin.com/forum/bulletin/post/68707f46fcd7910fb215137c)、[生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。

## 10. 线索与微信团队交接

“生成体验”只保留体验事实。用户主动咨询后复用 `marketing_leads` 及通用线索来源入口，新增明确的效果方案来源，附原渠道归因、方案 ID、用户主动提供的需求。不能伪装成抖音量房，也不能无预约时伪造 appointment。

同租户相同手机号已有线索时按既有去重规则追加来源，保留负责人和客户归属；只共享本次勾选的文件。默认共享生成结果与建议，原房间照片/户型图由客户单独选择。服务端确认共享对象确实属于该主体与方案。

微信团队只读参考位置：

- `orange/src/services/picture_library.ts`
- `orange/src/packageVisitor/pages/picture-library/index.tsx`
- `orange/src/packageVisitor/pages/picture-library-detail/index.tsx`

微信团队需增加效果体验页面和 service 包装，复用图库展示组件时保留原平台图库合同；新增入口要能取得可信装修公司上下文。收到已发布 shared domain 后映射如下：

| 服务端字段 | 客户端行为 |
| --- | --- |
| quota.phone_verified / blocked_reason | 控制手机号绑定提示，前端不自行判定实际权限 |
| quota.active_job_id | 恢复已有任务，不重复创建 |
| stage / advice_status | 分别展示生图和建议状态，不伪造百分比 |
| result.image_url / expires_at | 展示短时签名图；过期重新获取详情 |
| quota.remaining | 展示真实剩余次数，换设备后重新查询 |
| error.code | 显示对应动作：登录、绑定、等待、限额、重试 |

调用顺序：会话/公司上下文 → styles 与 quota → 上传意图/上传/确认 → 必要时手机号绑定并重取 quota → jobs → 前台轮询 → 结果/建议 → 可选咨询。客户端在创建请求发出前持久保存幂等键，网络失败复用该键，用户改变内容才生成新键。

微信小程序代码和发布由 orange 所属团队处理，gooes 不修改 orange。本方案不声称当前微信接口已经支持新场景。

## 11. 分阶段交付与验收

按 writing-plans 的范围拆分原则，先确定本方案，再分别编写每个阶段的可执行代码计划；本文件中的阶段是交付范围，不是包含完整代码的执行清单。

| 阶段 | 交付结果 | 完成证据 |
| --- | --- | --- |
| A 方舟能力验证 | 脱敏核对开发配置；确定生图/看图模型、地址语义、费用、恢复限制与审核方式 | 授权样本双图输入、单图输出、看图建议和受控错误样例；无密钥泄漏 |
| B 租户效果图库 | migration、权限、私有草稿/公开发布、Admin 上传与小程序可读 API | 跨租户隔离、批量部分失败恢复、发布隐藏和分页 smoke |
| C 身份和次数 | 体验身份、手机号验证、账户合并、预算与次数预占 | 无 CRM 档案可体验；并发和幂等数据库验证；两个渠道合并剩余正确 |
| D 生图与建议 | 方舟适配、任务 Worker、COS 转存、审核、看图建议、费用结算 | 成功、超时未知、存储失败、建议失败、Worker 重启恢复均有证据 |
| E 客户端及咨询 | 抖音页面、来源接入、共享 domain、微信接口交接 | 前后对比、额度门槛、切后台恢复、授权咨询；微信由对方联调 |
| F 灰度 | 2～3 家公司、30～50 组授权样本、租户开关和总预算 | 设计师评审、耗时与成本报表、提审材料、回退演练 |

实现时主要落点：

- 共享合同：新增 `packages/domain/src/customer-rendering.ts`，复用 `ai-generation.ts` 的通用状态。
- 租户素材：新增 `apps/api/src/controllers/tenant-rendering-library/index.ts`、`apps/api/src/services/tenant-rendering-library/`、`apps/api/src/repositories/tenant-rendering-library.ts`。
- 客户方案：新增双端 rendering controller、`apps/api/src/services/customer-rendering/`、`apps/api/src/repositories/customer-rendering.ts`。
- 模型网络边界：在 `apps/api/src/gateways/` 增加方舟适配，复用实际存在的 AI 任务抽象；不复制计划中尚未落地的通用模块。
- Admin：新增 `apps/admin/components/rendering-library/`，路由和导航按当前租户控制台模式挂接。
- 抖音：新增 `apps/douyin-mini/src/pages/renderings/` 和 `apps/douyin-mini/src/api/renderings.ts`，注册 `app.json`。
- migration：按阶段分别新增素材/权限、额度/任务/RPC、模型适配配置及咨询来源的 forward migration，执行时分配唯一时间戳。

必须验证的业务用例：

1. 未验证手机号的首次成功后第二次被服务端阻止；已验证客户总额度为 5。
2. 剩 1 次时并发提交两个不同请求只接受一个；相同请求多次重放只产生一次任务/扣费。
3. 微信与抖音各用 1 次后绑定同手机号剩 3 次；删除历史、换号码、重新绑定不能重置。
4. 绑定与 Worker 完成并发不丢预占/重复消费；额度合并不泄漏另一身份的历史文件。
5. 租户 A 素材/上传/任务不能被租户 B 引用；客户甲不能读取客户乙图片。
6. 没有 CRM 客户档案也能验证手机号继续体验；不自动创建客户或量房预约。
7. 生图成功、建议失败仍可看图，补建议不再次生图；生图明确失败释放次数。
8. 供应商提交未知不自动重试；Worker 重启和迟到结果不造成重复消费。
9. 手机号授权拒绝后可返回原结果；仅绑定手机号不进入主动联系队列。
10. 素材隐藏阻止新任务但不破坏已受理任务；历史签名过期可刷新，删除不恢复次数。
11. 未设置每日预算、模型未验证、审核不可用时不能启用客户生成。
12. 生成图和文字建议一致，用户指定保留家具得到合理处理；结构偏移纳入质量评审。

先运行变更范围的 Bun 测试和静态检查：`bun run api:typecheck`、`bun run admin:check`、`bun run douyin-mini:check`；涉及运行产物时再运行 `bun run api:build` 和 `bun run admin:build`。这些是未来执行命令，本次文档编写未运行业务验证。

数据库须在隔离环境验证并发、复合外键、RPC owner、RLS/ACL；远端应用前逐个列明待执行 migration，应用后运行 `supabase migration list` 检查 Local/Remote 对齐。生图 smoke 会产生费用并传送样本，使用用户授权的开发账号和样本执行，不以生产家庭照片作为默认测试数据。

质量建议门槛为至少 80% 样本经设计师判定可以作为客户沟通预览；这是评审目标，不是模型保证。记录首图完成率、首次体验后绑定率、主动咨询率、每条有效线索成本及 p50/p95 耗时；以真实测量决定超时和预算参数。

## 12. 发布与回退

依次发布兼容性 migration、API/Worker、Admin、抖音与微信客户端。先只对试点租户开启；全部前置能力未验证时开关保持关闭。

回退先关闭新任务入口，保留历史查询及在途任务对账；客户端可移除生成入口。已提交供应商任务继续处理结果和费用，不粗暴杀掉 Worker 造成未知账目。数据库保留新增事实，以 forward migration 修复，不回滚删除客户图片、次数账目或费用记录。旧图库和既有文字 AI Endpoint 行为必须保持兼容。
