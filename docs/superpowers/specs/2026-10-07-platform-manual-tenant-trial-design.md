# 超管手动建户试用期限设计

**日期：** 2026-10-07

**状态：** 待评审

**范围：** Gooes API、Admin、Domain 与 Supabase migration；不修改 orange 仓库

## 1. 目标与已确认规则

- 超管手动新建租户时可以设置试用天数。表单默认开启 30 天标准试用，也允许选择“暂不开通”。
- 手动创建的租户即使尚未完成企业核验，也可以开始试用。平台主动发放仍需要 `platform.service_trial.manage`、操作人和原因；租户自主申请仍要求已核验企业身份。
- 试用结束后固定进入 7 天只读宽限期；宽限期结束后停止试用访问。有效正式服务或已付款待开通服务仍按现有优先级放行。
- 租户列表展示实际服务访问状态、试用截止时间和宽限期截止时间；超管可以从列表延长试用。不提供缩短期限操作。立即终止沿用现有撤销试用能力。
- 暂不开通的超管新租户不能因为缺少旧订阅记录而得到无限期读写权限。

## 2. 现状与问题

`PlatformTenantService.create` 只调用 `create_tenant_with_default_template` 初始化租户和组织，不创建试用。试用发放 RPC `platform_service_trial_grant` 要求租户关联已审核入驻申请及一致的统一社会信用代码；手动建户没有这项资料，直接调用会报 `SERVICE_TRIAL_ENTERPRISE_IDENTITY_REQUIRED`。

当前服务访问按租户状态、正式合同、已付款待开通、有效试用、旧订阅依次判定。旧订阅状态只要不是 `locked`，包括没有订阅记录的 `null`，就返回无结束时间的 `legacy` 读写模式。因此仅新增试用截止时间字段不能实现到期封禁。试用访问还受 `PLATFORM_SERVICE_TRIAL_ACCESS_ENABLED` 开关控制，默认值为关闭。

超管建户和合作伙伴入驻都使用 `create_tenant_with_default_template`。改变该 RPC 的默认访问行为时必须显式保留合作伙伴现有路径，不能依赖调用人是否为空来猜测来源。

## 3. 方案选择

1. **只在 `tenants` 增加到期时间：不采用。** 会产生第二套与现有试用状态、范围、宽限期及审计不一致的授权规则。
2. **建户后单独调用现有发放接口：不采用。** 未核验身份会被拒绝；建户和发放分成两次提交也会留下建户成功、试用失败的中间状态。
3. **复用现有试用记录和受控命令，扩展平台手动建户来源：采用。** 创建和发放处于同一数据库事务，列表从同一试用与访问事实读取状态。

## 4. 数据和权限边界

新增显式的 `tenants.creation_source` 和 `tenants.service_access_policy`。来源区分历史未知、平台手动、合作伙伴和入驻审批；访问策略只有 `legacy_compatible` 与 `entitlement_required` 两种。历史租户经 migration 标记为旧版兼容访问。实现中确认合作伙伴和入驻审批存在共享 RPC、直接建户两条路径，因此保留数据库默认 `legacy_compatible`，仅新的超管手动建户包装 RPC 显式写入 `platform_manual` 和 `entitlement_required`。其他入口的新行来源暂记 `unclassified`，不改变其现有访问行为。创建来源不可通过普通租户编辑接口修改。不靠 `tenant_billing_subscriptions` 缺行推断。数据库 schema、约束、索引、回填均走 `supabase/migrations/`，不手动修改远端数据库。

试用记录增加身份依据：`verified_enterprise` 或 `provisional_tenant`。原有记录回填为前者，并保留现有企业摘要；后者仅允许 `platform_grant` 来源。实现保留既有非空身份键及命令锁协议：临时记录在 `enterprise_identity_hash` 中存储带 `provisional-tenant:` 前缀的租户身份摘要，并通过 `identity_basis` 明确区分，绝不据此认定企业已核验；已核验记录仍使用信用代码摘要。这样延期、撤销和正式服务归因可继续使用现有命令。另建临时试用按租户与有效状态的部分唯一索引，并在发放/申请时同时检查企业历史与租户历史。租户自主申请仍要求已核验企业身份。平台人员对未核验手动租户单独发放试用时，走相同的受控例外。延长、撤销、状态规范化和归因命令都必须支持两种身份依据；临时身份不伪装为企业统一社会信用代码摘要。试用类型、范围、规则快照、幂等键、版本、审计事件和权限仍复用既有试用机制。

企业后续完成核验时，临时试用保留原始身份依据和审计历史。发放及自主申请命令会一次性查出相同已核验企业对应的租户，将这些租户的临时试用纳入重复、有效试用及冷却期检查。不会改写或静默撤销已有试用；重复发放返回现有业务错误，超出规则仍需特批。本次不新增企业核验流程及核验时的冲突记录机制。

## 5. 创建和访问流程

超管创建接口接收“是否立即开通试用”和试用天数。默认 30 天；天数遵守当前试用策略上限，具备 `platform.service_trial.override` 权限时才允许规则内的例外。手动建户的宽限期固定为 7 天，表单说明固定 7 天只读，创建后列表显示服务器计算的两个截止时间。试用开启时，建户 RPC 在同一事务内完成租户、组织、管理员和标准试用发放；任何一步失败都回滚。试用关闭时只创建租户，服务访问为“未开通”。建户响应返回最终租户和试用事实，Admin 不推算服务器时间。

统一访问判定维持“租户停用 > 正式合同 > 已付款待开通 > 有效试用 > 显式旧版兼容资格 > 未开通／到期”的优先级。试用截止时进入 `grace`，只允许读与恢复类请求；7 天后进入 `service_blocked`。已撤销试用立即失效。平台管理和服务购买、申请等恢复接口遵循现有路由访问矩阵。

上述受控访问在试用访问开关启用后才能对用户生效。因此上线顺序必须先验证数据库事实和访问判定，再启用新的建户试用入口；开关关闭时禁止创建会被错误放行或错误阻断的试用租户。

## 6. 租户列表

分页列表按当前页租户 ID 批量取得实际服务状态和当前／最近试用事实，避免逐行 RPC 或 N+1。展示“未开通、试用中、只读宽限期、已到期、正式服务、旧版兼容、已停用”，并显示试用及宽限期截止时间。列表里的“延长试用”只对现有命令允许的 `active`、`grace_period` 状态开放，使用既有 `expected_version`、幂等键、权限、原因和审计；过期或无试用时不显示可执行的延期按钮。列表保留进入试用管理详情的路径以查看完整历史和撤销操作。

## 7. 验证与上线

验证手动新建默认试用、指定天数、暂不开通、建户事务回滚、未核验租户发放、试用截止转只读、宽限期截止阻断、延期后重新计算截止时间、撤销立即失效、已付费优先、旧租户兼容、合作伙伴建户不回归，以及分页列表无 N+1。重点验证数据库时间边界和试用开关状态。数据库迁移应用前确认待执行文件，应用后以 `supabase migration list` 核对 Local/Remote；回滚需提供前向补偿 migration，保留试用及审计历史，不删除已发放记录。

不新增缩短期限、独立免费期表、0 元订单或新缓存与队列。

## 8. 实施与验证（2026-10-07）

实现分支：`feat/manual-tenant-trial`，独立工作区：`.worktrees/manual-tenant-trial`。除四个主体 migration 外，增加延期版本校验和核验后历史去重两个 migration。延期在行锁内先校验客户端版本，再规范化时间状态，避免刚进入宽限期时被错误判为版本冲突。

本地独立 PostgreSQL 已应用本功能六个 migration，`supabase migration list` 在验证用目录中 Local/Remote 对齐。真实 SQL smoke 位于 `supabase/tests/manual_tenant_trial.sql`，覆盖原子建户/回滚、未核验身份、30 天试用与 7 天宽限、暂不开通、其他来源兼容、宽限期延期、幂等和陈旧版本、过期及 100 条上限。

完整历史重放在既有 `20260828170000_repair_transferred_tenant_public_profile.sql` 因缺少特定租户数据而中止，验证目录使用已应用基础历史、组织模板依赖和本功能 migration。未向远端部署、未修改远端开关。发布时需安排 API/Admin 与 migration 同一维护窗口，迁移新增字段会改变严格响应解析契约；先确认目标环境历史和六个待应用文件，再验证开关与业务访问，最后开放入口。

回滚使用前向补偿 migration 恢复函数/访问策略，保留试用、审计和初始化记录；不要删除试用历史或直接删除新列。

验证结果：`bun run api:check`（类型、构建、文件长度）、`pnpm --dir apps/admin check`、定向 API 回归及 `git diff --check` 通过。浏览器模拟 API 验证默认 30 天、修改为 15 天、暂不开通、宽限期延长和状态刷新，无页面异常；真实数据库回归同时覆盖补开试用固定 7 天及撤销。小规模本地批量事实查询 `EXPLAIN ANALYZE` 为约 4.2 ms，不能代表生产数据规模。已复核服务角色权限及分页边界；本轮为当前代理代码自查，未执行独立子代理审查。
