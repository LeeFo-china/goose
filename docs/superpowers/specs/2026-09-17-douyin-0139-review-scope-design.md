# 抖音小程序 0.1.39 提审范围收敛设计

## 目标

把抖音小程序 0.1.39 收敛到已经验证过的装修服务范围，降低再次触发
“AI 工具”类目审核的风险：保留已有装修问答交互，但所有用户界面统一使用
“装修问答”；装修效果图只提供装修公司已发布的实景图和设计图浏览。

## 范围

### 装修问答

- 首页入口、问答页标题和导航栏标题统一为“装修问答”。
- 保留现有问题预设、自由输入、回答流式展示、错误处理和量房入口。
- 不修改问答接口、模型调用、回答免责声明和数据协议。
- 小程序用户界面不得再出现“AI 装修问题助手”字样。

### 装修效果图

- 列表只展示 `real_case` 和 `design` 两种来源。
- 移除“AI 概念图”提示和标签。
- 详情页只保留已发布图片、标题、空间、风格、来源、色彩说明、材质说明和发布时间。
- 移除房间照、户型图上传，手机号验证，生成参数，任务进度和生成结果对比等交互。
- 抖音目录接口在数据库查询阶段限制来源，保证分页条数和总数准确。
- 抖音详情接口同样限制来源，旧分享或深链访问 `ai_concept` 时返回素材不存在。
- 微信访客端仍可访问原有三种来源，避免影响已上线能力。

## 实现边界

- 在共享目录 service 根据 `channel` 选择可见来源，并把来源限制传给 repository。
- repository 在 Supabase 查询中增加来源过滤，列表继续使用数据库分页，不在客户端分页后过滤。
- 抖音详情页恢复成只读展示模型，并删除页面对上传、生成和恢复模块的引用。
- 清理只服务于抖音生成链路的应用启动恢复状态；保留后端上传与生成接口，便于其他端继续使用及以后恢复。
- 不修改数据库结构，不新增依赖，不修改 `/Users/leefo/Public/work/orange`。

## 错误处理

- 目录会话失效、租户暂停、筛选错误和通用加载失败继续沿用现有错误状态。
- 不可见的 `ai_concept` 详情与不存在素材统一返回
  `RENDERING_STYLE_NOT_FOUND`，不暴露隐藏原因。
- 详情页刷新失败时保留现有陈旧内容提示和重试能力。

## 验证

- 先修改测试并确认其因旧文案、旧来源或旧生成界面而失败。
- 验证抖音目录查询带有来源限制且分页保持服务端计算。
- 验证抖音详情拒绝 `ai_concept`，微信目录行为不变。
- 验证首页、问答页和导航标题均为“装修问答”，且无旧 AI 文案。
- 验证效果图详情模板及页面入口不再包含上传、手机号验证、生成任务或 AI 结果内容。
- 运行抖音小程序完整检查和受影响 API 单元测试、类型检查。

## 发布说明

代码库不把体验版号写入运行时代码。完成构建和验证后，上传抖音开发者平台时将
版本号填写为 `0.1.39`，发布说明写为“优化装修问答名称，效果图调整为已发布案例浏览”。
