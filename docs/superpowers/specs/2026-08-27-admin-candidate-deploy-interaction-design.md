# Admin 生产候选部署交互设计

## 问题

版本发布页默认选择开发环境。最近发布记录会展示生产候选为“可部署”，但候选证据区只在发布表单选择生产环境时渲染。记录行的“候选证据”操作仅保存候选 ID，不会显示或定位到证据区，导致用户点击后看不到部署入口。

## 目标

- 可部署生产候选的操作不依赖新建发布表单当前选择的环境。
- 用户从发布记录选择候选后，页面明确定位到对应候选的证据和部署操作。
- 保留候选证据校验、生产确认文本和后端权限门禁，不缩短生产安全链路。

## 交互

1. 服务发布页始终展示“生产候选证据”区。
2. 没有可部署候选时展示现有空状态，部署按钮保持禁用。
3. 存在可部署候选时默认加载最新候选，并显示“部署此构建到生产”。
4. 发布记录行操作改为“部署候选”。点击后选择该 Run、切回服务发布标签，并平滑定位到生产候选证据区。
5. 点击“部署此构建到生产”后仍使用现有二次确认对话框，只有输入“确认部署生产环境”才能提交。

## 边界

- 不自动修改新建发布表单的目标环境、服务或引用，避免覆盖用户正在填写的内容。
- 不在记录表内复制部署表单和候选请求逻辑。
- 不修改生产发布 API、工作流或数据库。

## 验证

- 契约测试确认候选证据区不再受生产环境条件控制。
- 契约测试确认记录行提供“部署候选”并执行选择、标签切换和定位。
- 运行 Admin 类型检查、相关测试与生产构建。
- 部署开发环境后，用已登录请求确认页面 HTML 包含部署入口，并验证真实候选仍为可部署。
