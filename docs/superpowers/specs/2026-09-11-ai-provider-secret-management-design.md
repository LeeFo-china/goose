# AI 供应商密钥管理设计

日期：2026-09-11

状态：用户已确认；本地实施与验证记录见同目录 progress 文档。尚未迁移或发布。

## 目标与已确认方向

用户选择先在本地完善供应商密钥管理，再统一发布。超管应能在 AI 模型路由的供应商页面找到真实 API Key 的录入入口，不必猜测“密钥配置 Key”的含义。密钥输入留空不修改已有值。

本设计延续现有 ai_providers.api_key_setting_key 引用 system_settings 的方式，不把真实密钥写入供应商记录。真实密钥仍由系统配置服务加密，只有服务端调用时读取。

## 现有证据与问题

- `apps/admin/components/platform-ai/ai-model-routing-sections.tsx` 的供应商表单使用自由文本填写引用名；没有真实密钥录入入口。
- `apps/api/src/services/ai-config/index.ts` 保存供应商引用后直接返回，未证明引用是有效的 AI 敏感配置。
- `apps/api/src/services/system-settings/legacy/settings.ts` 按配置元数据加密并保存真实值；getSecretString 最终按配置名解析数据库或环境变量。
- `apps/admin/components/settings/settings-actions.tsx` 当前通用编辑器会将空输入提交为 null。已有数据库密钥时按钮仍可点击，导致误清空。
- `apps/api/src/services/ai-gateway.ts` 的既有通用链路存在旧配置回退。配置状态不能用来证明模型、额度、权限或生成能力可用。
- 功能 worktree 已有 ARK_API_KEY 定义和 migration，但开发环境尚未应用、发布。

## 方案比较

1. 只改提示并跳转系统配置：改动最小，但仍跨页面，不满足供应商页面录入的完整体验。
2. 供应商页面提供已登记 AI 配置选择、状态和独立密钥编辑：复用加密存储与权限，避免隐式双写，采用此方案。
3. 每个供应商自动创建独立凭据并把两类保存合为事务：支持多账号更灵活，但需要新的凭据生命周期、并发与迁移设计，本轮不做。

## 交互

### 配置引用

- 将“密钥配置 Key”改为“密钥配置”，使用本地 Select，不再让用户自由输入真实值或配置名。
- 可选项只来自后端登记的 AI 敏感配置：AI_API_KEY、DEEPSEEK_API_KEY、OPENROUTER_API_KEY、ARK_API_KEY。
- 显示中文名称，引用名作为辅助文字。兼容协议不等于方舟，不能根据 openai_compatible 自动选择 ARK_API_KEY。
- OpenRouter 延续固定 OPENROUTER_API_KEY 的约定。
- 历史未知引用显示“配置引用异常，请重新选择”，不回显疑似凭据、不自动迁移其内容，也不自动覆盖。
- 新供应商先保存基本信息和引用，再提供配置密钥操作；已保存供应商若修改引用，需要先保存引用后才能编辑对应密钥。

### 配置／更换真实密钥

- 已保存供应商的编辑区提供“配置密钥／更换密钥”入口，使用现有 Dialog、Input、Button、Badge。
- 弹窗明确显示供应商名称和目标配置名称；真实密钥使用 password 输入，不回填旧值。
- 密钥独立保存，不随供应商基本信息表单一起提交。不宣称两个请求具有原子性。
- 空白输入禁用保存，提交处理也不发送写请求；服务端新密钥命令拒绝空白和 null。
- 保存成功后清空输入并刷新配置状态；关闭弹窗和切换供应商时清除输入，避免误写其他配置。
- 保存期间禁止重复提交。错误信息固定且脱敏，不展示上游响应、密钥、密文或请求体。
- 网络结果不明时不自动重试，不宣称未写入；提示刷新状态，必要时重新配置。
- 本轮不提供密钥删除／清空功能，也不改变环境变量。轮换配置会影响引用同一配置的所有供应商，保存前明确提示共享影响。

### 状态

- 未配置：受支持的配置没有有效数据库值或环境变量来源。
- 已配置（未验证）：存在配置来源；不代表密钥有效或模型可用。
- 配置引用异常：未知、非 AI、非敏感、停用或疑似真实凭据的引用。
- 状态加载失败：显示独立错误和重试，不误报未配置。
- 不增加付费验证请求，不展示没有真实探测依据的“连接成功／验证失败”。模型与图片生成能力验证仍属于后续真实联调。

### 系统配置页一致性

仅调整上述 AI 敏感配置的编辑行为：空白不提交、不清空，文案为“输入新密钥以更换，留空不修改”。非 AI 配置及支付等专用编辑器保持现状，避免扩大影响。

## 后端与权限边界

- 新增聚焦 AI 密钥配置的元数据读取和非空替换命令，controller 仅处理认证、严格校验、调用 service 和 ResponseHandler。
- service 只接受登记的 AI 敏感配置，不允许任意 system_settings key。复用系统配置服务的加密、持久化、缓存失效机制，不另存一份凭据。
- 读取要求平台上下文及 `platform.ai_config.read`、`platform.system_setting.read`；替换要求 `platform.ai_config.manage`、`platform.system_setting.manage`。无系统配置权限者仍可查看原供应商列表，但无权加载或编辑密钥状态。
- 租户管理员不可通过新入口读取或更换平台密钥。前端隐藏按钮不能替代后端权限检查。
- 元数据返回显式 DTO，只含配置名、显示名、来源与状态；不得返回原始 value_text、stored_value、effective_value、密文或明文。
- 状态只读取所需配置元数据，不为显示状态解密或调用供应商。数据源限定四项；若使用非分页辅助端点，代码注释注明总量四项且小于 50 的豁免依据。供应商列表保持默认 20、最大 100 的分页。
- 供应商新增／显式修改引用时验证其属于允许的配置集合；对历史未知引用的无关字段编辑保留原值，要求单独显式修复，不静默丢弃。
- 新响应和 Admin 代理使用 private/no-store。审计只记录操作者、配置名、动作和结果，不记录密钥或其派生指纹。
- 所有新错误由 error-factory 包装。服务和日志不得透传包含敏感请求体的异常。

## 数据、发布与非目标

- 不新增密钥表、不自动创建任意配置槽、不改变加密算法。ARK_API_KEY 的初始化继续通过现有 migration，禁止远端手工修库。
- 不改变当前通用模型调用回退策略，不接入新的模型目录、生成 worker、额度规则、小程序页面或生产环境。
- 先完成本地实现和验证，再复核待执行 migrations、开发环境目标及固定发布版本；应用后必须使用 supabase migration list 验证对齐。
- GitHub 曾拦截旧提交 `193ee4b3d` 中的测试夹具。本轮不绕过保护；移除凭据形态的完整字面量，使用明确合成的测试数据。发布历史清理需保留原功能分支，不能强推共享分支或删除用户历史。
- 不读取／搬运历史疑似密钥，不替用户填写真实密钥。若真实值曾被写入引用字段，由用户在方舟轮换后通过新入口录入。
- 回退应用时保留已加密配置与素材事实；不自动恢复旧密钥、不删除数据库记录。

## 验收

1. 服务端测试：无认证、租户身份、两类权限缺失、未知／非敏感 key、空白/null/额外字段均被拒绝；拒绝发生在持久化之前。
2. 服务端测试：正常保存调用现有加密链路；元数据及写响应、日志和审计不含输入秘密、旧值或密文；环境来源状态正确。
3. 供应商引用测试：允许四项登记配置、拒绝真实密钥和未知引用；历史异常引用不自动回显或覆盖；保留既有版本冲突检查。
4. Admin 测试：选择引用、打开密钥弹窗、留空不写、成功清空、失败保留可修正状态、切换供应商不串写、无权限及加载失败状态。
5. 系统配置页回归：AI 密钥空白不写；非 AI 配置原有清空行为不改变。
6. 在各包正确工作目录运行相关 Bun 测试及 API/Admin 类型检查；静态检查通过后进行浏览器 mock 验收，覆盖窄屏、键盘、焦点、加载及错误。
7. 本地验证与真实联调分别记录；没有真实调用不得宣称密钥有效、生图成功或开发发布完成。

## 设计自审

范围已限定为密钥管理，不把模型验证和发布安全清理混同为已完成事项。明确共享密钥影响、双步骤保存、空白输入语义、权限、返回字段和历史异常处理；无待填占位项。用户已书面确认，进入实施与验证。
