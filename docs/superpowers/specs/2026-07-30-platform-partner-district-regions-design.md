# 城市合伙人区县运营区域设计

## 目标

将城市合伙人的运营区域从手工填写城市级编码，调整为以区县级行政区划为准的结构化权限配置，同时满足以下约束：

- 新建、申请审核通过和区域编辑只接受启用中的区县级 `adcode`。
- 同一区县同一时间只能归属一个启用中的城市合伙人。
- 存量城市级编码不自动扩展、不自动迁移，避免无依据扩大权限。
- 已存在的装企绑定继续按 `partner_id` 生效，不随区域配置变更自动转移。
- 区域变更具备操作原因、审计快照和乐观并发控制。

## 已选方案

继续使用 `platform_partners.region_codes text[]` 作为当前归属匹配的数据源，新增服务端区域规则与数据库约束，不在本期引入新的区域关系表。

选择该方案的原因：

- 当前装企归属匹配已经支持省、市、区县三级，并优先精确区县。
- 当前数组字段已有 GIN 索引，能够支持区县重叠查询。
- 改动集中，能够保持现有匹配、门户和装企绑定链路稳定。
- 后续需要有效期、分区负责人或区域历史查询时，再迁移为独立关系表。

未选择的方案：

- 只修改管理端输入：无法防止接口直调、拼写错误和并发重复授权。
- 立即拆分 `platform_partner_regions`：长期模型更强，但会扩大本次匹配、申请、邀请码和门户契约的改造范围。

## 数据与并发

为 `platform_partners` 增加 `region_version integer NOT NULL DEFAULT 1`，仅在区域变更成功后递增。

新增数据库触发器：

1. 新增合伙人或修改 `region_codes` 时，区域不能为空，且每个编码必须对应启用中的 `administrative_areas.level = 'district'`。
2. 合伙人处于 `active` 时，对排序后的区域编码获取事务级 advisory lock。
3. 在同一事务中检查其他启用合伙人的 `region_codes` 是否重叠；存在重叠时拒绝写入。
4. migration 不修改任何存量 `region_codes`，因此不会擅自扩大或收缩历史经营范围。

服务层在数据库写入前执行相同的业务校验，返回稳定、可读的错误码；触发器负责防止并发绕过。

## API

新增独立区域变更接口：

`PATCH /platform/partners/:id/regions`

请求：

```json
{
  "region_codes": ["411502", "411503"],
  "change_reason": "按实际运营范围调整为浉河区、平桥区",
  "expected_version": 1
}
```

行为：

- 校验平台合伙人管理权限。
- 校验全部编码为启用区县。
- 校验不存在启用区域冲突。
- 使用 `id + region_version` 条件更新；版本不一致返回 409。
- 不修改 `tenant_partner_bindings`。
- 写入 `platform_audit_logs`，记录变更前后编码、版本和操作原因。

新建合伙人、审核申请通过、启用合伙人和创建指定区域邀请码时复用同一区域规则：

- 新建和审核通过至少选择一个区县。
- 启用前重新检查区县合法性和冲突。
- 邀请码指定区域必须属于该合伙人的区县范围。

## 管理端交互

新建、申请审核和区域编辑共用 `PlatformPartnerRegionPicker`：

- 省、市使用可搜索单选。
- 区县使用可搜索多选，选择结果可以跨城市累积。
- 已选区域显示完整名称和 `adcode`，支持单项移除。
- 存量城市级编码显示“待迁移”提示，保存前必须改选为区县。
- 加载、失败、空结果、禁用和键盘操作状态均复用现有 shadcn/Radix 组件。

合伙人列表区域列显示行政区名称，保留编码作为次要信息；操作列增加“区域”编辑入口。编辑提交必须填写变更原因，并携带 `region_version`。

## 错误码

- `PLATFORM_PARTNER_REGION_REQUIRED`：未选择区县。
- `PLATFORM_PARTNER_REGION_INVALID`：编码不存在、停用或不是区县级。
- `PLATFORM_PARTNER_REGION_CONFLICT`：与其他启用合伙人区域重叠。
- `PLATFORM_PARTNER_REGION_VERSION_CONFLICT`：编辑数据已被其他操作更新。
- `PLATFORM_PARTNER_INVITE_REGION_OUT_OF_SCOPE`：邀请码区域不在合伙人运营范围。

## 验收

- 新建、申请审核和区域编辑不能提交空区域、城市级编码或不存在编码。
- 两个启用合伙人不能占用同一区县，包括并发写入。
- 待审核合伙人可以创建，但其区域不能与现有启用合伙人冲突。
- 暂停合伙人重新启用时重新校验区域。
- 修改区域后 `region_version` 加一，并产生平台审计日志。
- 区域调整前后的 `tenant_partner_bindings` 数量和归属不发生变化。
- 管理端不再要求用户手工输入逗号分隔编码。
- 存量城市级记录可见且明确提示迁移，但 migration 不自动改写。
