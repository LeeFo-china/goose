# 平台品牌权益商品管理设计

## 目标

在 Gooes Admin 平台超管侧提供年度品牌权益商品配置入口，让具备
`platform.branding_product.manage` 权限的超管可以查看和修改商品名称、
年度价格、购买说明及上下架状态。

本次只补齐批次 B 已有商品接口的管理交互，不增加订单、权益授予或退款
功能，不修改小程序仓库，也不改变既有订单快照语义。

## 方案比较

### 方案一：计费中心新增页签

把商品配置放入现有 `/platform/billing`。

- 优点：所有价格配置集中。
- 缺点：计费中心已有多个复杂页签，品牌权益的权限码和领域语义独立，
  会继续扩大现有页面。

### 方案二：平台配置新增独立页面（采用）

新增 `/platform/branding-addon`，在“平台配置”导航组中提供“品牌权益”
入口。

- 优点：与 `platform_branding` 权限模块一致，边界清楚；后续可以在不
  污染计费中心的情况下扩展品牌订单只读入口。
- 缺点：平台导航增加一个菜单项。

### 方案三：系统配置增加一个表单区块

把商品表单放入 `/settings`。

- 优点：改动页面数量少。
- 缺点：系统配置以环境和通道配置为主，年度商品属于业务运营配置，
  放置后难以发现且权限边界不自然。

## 页面与权限

- 路由：`/platform/branding-addon`
- 菜单：平台配置 → 品牌权益
- 菜单仅对拥有 `platform.branding_product.manage` 的会话展示。
- 页面服务端再次检查平台超管身份和同一权限；缺少权限时不请求商品
  接口，页面显示无权访问提示。
- 后端继续作为最终权限边界，前端权限判断只用于导航和页面体验。

## 页面结构

页面保持后台配置页的紧凑布局：

1. 页头显示“品牌权益商品”和用途说明。
2. 状态摘要展示商品编码、权益编码、固定周期和当前上下架状态。
3. 单个配置卡片内使用现有 shadcn `FieldGroup`、`Field`、`Input`、
   `Textarea`、`Switch` 和 `Button`。
4. 可编辑字段：
   - 商品名称，最长 100 字符；
   - 年度价格，界面以元输入，最多两位小数；
   - 购买说明，最长 500 字符；
   - 上架状态。
5. 商品编码、权益编码和 `term_years=1` 只读，不允许 Admin 修改。
6. 页面明确提示：价格修改只影响新订单，历史订单保留创建时快照；
   数字权益支付成功并开通后不支持退款。

## 数据流与并发

页面服务端使用 Admin 登录凭证调用：

```text
GET /platform/branding/entitlement-product
```

客户端保存时通过现有 `/api/backend` 代理调用：

```text
PATCH /platform/branding/entitlement-product
```

请求只提交四个可编辑字段和当前 `version`。金额从元字符串精确转换为
正整数分，避免浮点四舍五入产生静默误差。保存成功后使用响应中的商品
及新 `version` 更新表单基线。

遇到 `BRANDING_ADDON_PRODUCT_VERSION_CONFLICT` 时，页面提示“配置已被
其他管理员修改”，并提供重新加载入口，不自动覆盖他人修改。

## 校验与错误处理

- 价格必须在 `0.01..21474836.47` 元之间，最多两位小数。
- 启用商品时价格必填且必须为正整数分。
- 名称和购买说明去除首尾空白后不能为空。
- 提交期间禁用所有字段和保存按钮，防止重复提交。
- 后端稳定错误消息直接展示；未知错误使用“品牌权益商品保存失败”。
- 保存成功显示成功状态，不使用浏览器原生弹窗。

## 测试与验收

- 纯函数测试：元/分转换、非法价格、PATCH payload 和版本字段。
- 导航测试：权限存在时显示菜单，缺少权限时隐藏。
- 页面契约测试：服务端 GET、客户端 PATCH、权限检查和版本冲突提示。
- 运行 Admin 文件大小检查、类型检查和生产构建。
- 本地 Admin 3010 + API 3000 做浏览器 smoke：加载、编辑、保存、刷新，
  并确认控制台无错误。
