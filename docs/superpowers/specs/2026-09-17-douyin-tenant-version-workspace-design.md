# 租户抖音小程序版本工作区设计

## 背景与问题

平台已经确认新的 `0.1.39` 模板，但租户抖音小程序工作台同时显示：

- 当前可发布模板版本异常 `0.1.39`；
- 平台当前模板不是该租户的新版本；
- 当前动作只有“提交审核”，没有生成测试码入口。

根因是现有工作台把语义版本号作为模板新旧判断的第一依据。当平台重新确认一个模板编号不同、版本号仍为 `0.1.39` 的模板包时：

1. `availableTemplate()` 比较得到版本号相等；
2. 模板编号或描述与租户最近发布记录不同；
3. 系统把该状态归为 `stale_version`；
4. 动作策略仍以租户最近的旧发布记录为准，旧记录处于 `testing` 时只显示“提交审核”。

数据库交付唯一键目前为 `(installation_id, template_version)`，原子上传 RPC 也按安装与版本号查找发布记录。因此，即使前端放开入口，同版本不同模板编号仍会触发交付冲突。问题必须同时修复版本身份、数据库约束、服务编排和租户工作台交互。

## 目标

- 正确识别同版本号下重新确认的模板修订。
- 租户可以在一个版本工作区中选择当前真正可执行的版本。
- 新模板修订可以生成测试码，验收后再提交审核。
- 历史发布记录保持可追溯，不参与不可执行的版本选择。
- 所有动作继续遵守租户、权限、审核状态和操作租约边界。

## 非目标

- 不允许任意历史模板重新生成测试码或重新提审。
- 不提供测试版本与提审版本两个独立选择器。
- 不允许客户端提交任意模板编号绕过平台当前模板。
- 不改变抖音开放平台只支持 `latest`、`audit`、`current`、`gray` 阶段的能力边界。
- 不引入缓存、队列或新的第三方依赖。

## 核心决策

### 精确模板身份

一个可交付模板使用前两项作为精确身份，第三项作为确认新鲜度证据：

- `template_id`：抖音模板编号；
- `template_version`：展示与平台阶段匹配使用的语义版本；
- `confirmed_at`：平台确认该模板进入 Gooes 可发布集合的时间。

`template_id` 是交付包身份，`template_version` 是用户可读版本，`confirmed_at` 用于判断用户选择是否仍指向当前确认记录。相同版本号但模板编号不同表示“新的模板修订”，不能判为旧版本或复用原发布记录。相同模板编号与版本被再次读取时保持幂等，不因确认时间变化重复上传。

版本关系按以下顺序判断：

1. 模板编号与版本号均相同：当前发布记录属于该模板。
2. 当前确认模板的版本号高于最近发布记录：存在新版。
3. 版本号相同但模板编号不同：存在同版本新修订。
4. 当前确认模板的版本号低于最近发布记录：平台确认模板发生回退，作为真实阻断。
5. 任一版本号不是合法语义版本：作为配置异常，不能猜测顺序。

描述变化只用于展示，不再决定模板身份。

### 单一版本工作区

租户页面使用一个“当前操作版本”选择器。选择器只包含当前可执行项，默认选中下一步最明确的版本。历史版本位于下方只读记录中。

可执行项分为两类：

1. 当前确认模板：尚未为该精确模板生成租户发布记录时，可执行上传并生成测试码。
2. 当前租户发布记录：其精确版本与抖音 `latest` 或 `audit` 阶段相符时，可执行刷新测试码、提交审核、同步状态或发布。

每个选项由服务端返回动作能力，前端不根据文字或局部状态自行推断。

## API 与数据流

### 可操作版本接口

新增租户接口：

```text
GET /tenant/douyin-miniapp/release-options?page=1&pageSize=20
```

默认 `page=1&pageSize=20`，`pageSize` 最大为 `100`。服务流程：

1. 从登录上下文解析租户并校验 `douyin_miniapp.read`。
2. 查找租户当前有效安装和平台当前确认模板。
3. 分页读取该安装的发布记录，只选择生成选项所需字段。
4. 使用安装授权调用抖音版本列表接口，读取 `latest / audit / current / gray`。
5. 使用版本号与安全交付标记匹配本地发布记录和抖音阶段。
6. 根据精确模板身份和抖音阶段生成可执行选项。
7. 返回选项、平台阶段摘要和分页信息，不返回访问令牌、部署键、开放平台日志原文或其他敏感字段。

响应结构：

```ts
type TenantDouyinReleaseOption = {
  id: string;
  source: "confirmed_template" | "release";
  template_id: string;
  template_version: string;
  label: string;
  stage:
    | "ready_to_upload"
    | "testing"
    | "audit_pending"
    | "audit_rejected"
    | "audit_approved";
  actions: Array<
    | "create_test_version"
    | "get_test_qr"
    | "submit_audit"
    | "sync_status"
    | "publish"
  >;
  confirmed_at: string | null;
  updated_at: string;
};
```

`source=confirmed_template` 的 `id` 使用部署模板记录 UUID；`source=release` 的 `id` 使用租户发布记录 UUID。响应中的 `actions` 只是界面投影，写接口必须重新执行完整权限与状态校验。

### 生成测试版

调整现有接口：

```text
POST /tenant/douyin-miniapp/releases/from-current-template
```

请求体新增：

```json
{
  "expected_template_record_id": "当前选择项对应的部署模板记录 UUID",
  "expected_template_id": "当前选择项对应的模板编号"
}
```

服务端重新读取平台当前确认模板并校验部署模板记录 UUID 与 `expected_template_id`。若页面打开后平台模板已变化，返回明确的 `409 DOUYIN_DEPLOYABLE_TEMPLATE_CHANGED`，提示用户刷新版本列表，不使用旧选择继续上传。

上传成功后继续在同一服务流程中获取 `latest` 测试二维码。返回新的发布记录，前端将选中项切换为该记录并显示二维码。

抖音官方版本列表文档只提供版本号和 `summary`，没有模板编号。为避免两个 `0.1.39` 被错误恢复为同一个远端包，新上传版本的 `user_desc` 使用确定性的安全交付标记，例如 `[#78690] 装修行业生产模板`。标记由服务端根据模板编号生成，原始业务描述仍单独保存在发布记录中。生成逻辑必须限制总长度不超过当前上传接口已经接受的本地描述上限。参考：[获取小程序版本列表信息](https://developer.open-douyin.com/docs/resource/zh-CN/thirdparty/API/smallprogram/auth-app-manage/develop/versions)。

同版本修订的远端证据必须同时匹配版本号和交付标记。上传超时、提审前校验和状态恢复均不得只依赖版本号。历史发布记录没有交付标记时，仅在该安装与版本号不存在模板身份歧义的情况下沿用原有版本号恢复；存在歧义时返回 `DOUYIN_RELEASE_OUTCOME_UNCERTAIN`，不猜测远端包身份。

### 已有发布记录动作

刷新测试码、提交审核、同步状态和发布继续使用带 `releaseId` 的现有接口。服务端通过租户安装归属、状态机、抖音平台精确版本证据和权限完成校验。

提审只允许当前选中且已完成体验测试的精确发布记录。界面不提供另一个“提审版本”选择器。

## 数据库迁移

新增 migration，完成以下变更：

1. 将 `douyin_miniapp_releases_delivery_key_unique` 从 `(installation_id, template_version)` 调整为 `(installation_id, template_id, template_version)`。
2. 更新 `get_or_create_and_claim_douyin_miniapp_release_upload`，按安装、模板编号和版本号创建或恢复记录。
3. 更新 v2 包装 RPC 的返回与权限声明，保持调用签名和安全边界稳定。
4. 为发布记录增加可验证的交付摘要字段，保存实际发送给抖音的安全交付标记；旧记录允许为空。
5. 保留审核中、审核通过、`created` 记录和有效操作租约的互斥规则。
6. 允许已上传或体验测试中的旧模板被精确身份不同的新确认模板替代，但不修改旧记录状态，保留审计历史。

迁移前检查是否存在完全相同的 `(installation_id, template_id, template_version)` 重复记录。发现重复时 migration 失败关闭，不自动合并生产数据。

回滚方案：停止租户版本创建，确认每个安装不存在同版本多个模板记录后，恢复原唯一键与旧 RPC。若生产已产生同版本不同模板记录，必须先通过单独评审的数据迁移处理，不能直接回滚约束。

## 页面交互

### 初始状态

首屏“当前进度”内依次显示：

1. 授权与发布状态 Badge；
2. “当前操作版本”选择器；
3. 所选版本的模板编号、确认时间和阶段说明；
4. 当前主要动作和必要的次要动作；
5. 与动作对应的测试版或审核版二维码。

同版本新修订显示为：

```text
0.1.39 · 新模板修订 · 可生成测试码
版本号相同，但模板包已经更新。
```

主按钮为“生成 0.1.39 测试码”。不再显示“当前可发布模板版本异常”。

### 生成后状态

生成过程禁用版本选择和其他写操作，按钮展示加载状态，附近使用 `aria-live` 文案说明“正在上传模板并生成测试码”。

成功后：

- 当前选项切换为新发布记录；
- 阶段显示“体验测试中”；
- 二维码在动作区下方展示；
- 可用动作变为“刷新测试码”和“提交审核”；
- 页面不依赖整页刷新才能看到结果，后台刷新只用于重新获取服务端最终状态。

### 历史记录

动作区下方展示分页历史，包含版本号、模板编号后四位、状态、更新时间和失败原因。历史记录不进入操作选择器，也不出现无法执行的按钮。

## 异常与恢复

- 抖音版本列表暂时不可用：保留本地发布记录，显示“平台状态暂未同步”，禁用依赖远端状态的提审和发布，提供“重新同步”。
- 平台当前模板在提交前变化：返回 `DOUYIN_DEPLOYABLE_TEMPLATE_CHANGED`，刷新选项后再操作。
- 同一精确模板重复点击生成：恢复或复用原发布任务，保持幂等。
- 另一个发布操作持有有效租约：返回现有的操作进行中错误，不创建重复任务。
- 当前版本正在审核或等待发布：新模板选项可以展示，但生成按钮禁用并说明阻断原因。
- 平台模板真实回退或版本格式非法：显示具体配置阻断，并保留可读取的历史记录。

所有业务错误继续通过 `error-factory.ts` 包装。前端不吞掉错误，也不把失败状态转换为成功提示。

## 代码边界

- controller：读取分页或请求体参数、Zod 校验、调用 service、包装 `ResponseHandler.success`。
- service：组合当前模板、租户发布记录和抖音阶段，生成动作能力并执行状态校验。
- repository：分页读取必要发布字段，数据库写操作继续通过原子 RPC。
- gateway：沿用现有抖音 `getVersionList()`、测试码、提审和发布能力，不新增猜测的第三方接口。
- admin：复用本地 `Select`、`Button`、`Badge`、`Alert` 和二维码组件。

## 验证标准

### 服务与数据库

- 同版本、不同模板编号被识别为“新模板修订”。
- 同模板编号、同版本号保持幂等，不创建重复记录。
- 同版本新修订可以建立新的发布记录并生成测试码。
- 审核中、审核通过和有效租约仍阻止不安全替换。
- 可操作版本列表分页受限，只返回必要字段。
- 抖音 `latest / audit / current` 与本地记录不一致时不暴露错误动作。
- 同版本修订的超时恢复同时校验版本号和交付标记，不把旧包误认成新包。
- migration contract 覆盖新唯一键、精确身份查询、权限与回滚注释。

### 管理后台

- `0.1.39` 同版本新修订显示“生成测试码”，不再只显示“提交审核”。
- 版本选择器只包含可执行项，历史记录只读。
- 生成中、成功、失败、平台状态不可用和权限不足状态均有明确反馈。
- 测试二维码展示后可以继续提交审核，且提交的发布记录与所选模板身份一致。
- 桌面与移动宽度下，选择器、按钮、长错误文案和二维码均可读可操作。

### 发布验证

1. 运行相关 API 与 Admin 回归测试。
2. 运行 API/Admin 类型检查和构建。
3. 本地应用 migration 并验证行为。
4. 生产执行前确认待应用 migration 和目标 Supabase project ref。
5. 执行后用 `supabase migration list` 验证 Local/Remote 对齐。
6. 在生产租户生成新 `0.1.39` 测试码，扫码确认内容后再提交审核。
