# 采购创建弹层工作台重构设计

**日期：** 2026-09-08
**状态：** 实施计划已确认
**范围：** Gooes Admin、`@gooes/domain`、小程序交接文档；orange 仓库只读

## 1. 背景

租户 Admin 当前有两个采购创建入口：

- “新建采购批次”：面向按项目或仓库发起、允许跨供应商选品的主采购入口。
- “发起采购申请”：面向单项目、单合作供应商的临时采购申请入口。

两个入口目前都使用右侧 Sheet，但把基础字段、商品目录、已选明细依次堆在同一个
长滚动区域中。采购原因和备注使用大面积文本框，商品目录与已选商品不能同时保持
可见；采购申请弹层还先展示空的已选明细，再展示可操作的商品目录。用户的主要任务
是找商品和调整采购数量，现有信息层级却把低频说明字段放在了更显眼的位置。

小程序端已经采用“搜索常驻、分类/供应商筛选、商品列表、购物车汇总常驻”的选品
模型。本次不照搬移动端外观，而是把这一任务模型适配为高密度桌面采购工作台。

## 2. 设计目标

1. 商品搜索、筛选和选择成为弹层的视觉与操作主体。
2. 商品目录和已选明细同时可见，减少上下往返滚动。
3. 采购去向、采购用途等必要上下文保持紧凑，不阻挡用户浏览商品。
4. 两个入口复用同一交互骨架，同时保留批次与单供应商申请的业务差异。
5. Admin 与小程序使用一致的采购用途词汇，不把自由文本字段错误收紧为枚举。
6. 保持现有权限、分页、服务端计价、幂等、版本和审批规则不变。

## 3. 非目标

- 不修改采购审批、预算判断、价格冻结、拆单、入库或应付逻辑。
- 不修改 `reason` 请求字段名、数据库字段或 1–500 字约束。
- 不把“采购用途”改成数据库枚举。
- 不在本次引入租户自定义用途、最近购买、收藏商品或新的推荐算法。
- 不修改 orange 仓库代码。

## 4. 已确认的设计方向

采用“双栏采购工作台”方案。桌面端以全高宽 Sheet 承载任务，上方为紧凑采购上下文，
中部左侧为商品目录，右侧为已选商品，底部为固定汇总和主操作。

设计参数：

- `DESIGN_VARIANCE = 3`：延续现有后台组件与深蓝语义，不创建全新视觉语言。
- `MOTION_INTENSITY = 2`：只保留必要的 Sheet、确认框和折叠过渡。
- `VISUAL_DENSITY = 7`：适合采购人员高频操作的紧凑桌面密度。

## 5. 信息架构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 标题                                            关闭                 │
├──────────────────────────────────────────────────────────────────────┤
│ 采购去向  项目/仓库  采购用途快捷项/单行输入  到货日期  补充信息   │
├──────────────────────────────────────────┬───────────────────────────┤
│ 搜索商品编码、商品名称、SKU 编码或 SKU 名称 │ 已选商品  8 项            │
│ 分类筛选  供应商筛选  清除筛选           │                           │
│                                          │ 商品 / 数量 / 成本分类    │
│ 分页商品列表                             │ 单项金额 / 删除           │
│ 商品、SKU、供应商、单位、价格、加入操作  │                           │
│                                          │ 独立滚动                   │
├──────────────────────────────────────────┴───────────────────────────┤
│ 8 个 SKU · 3 家供应商 · 预估 ¥12,680.00       取消  保存草稿        │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.1 Sheet 外壳

- 保留 Radix/shadcn Sheet 语义，宽度适配桌面工作台，不改成全屏路由。
- Sheet 自身不整体滚动；标题、上下文区和底部操作固定，中间双栏各自滚动。
- 移除目录和已选明细外层的重复 Card 套 Card，用分隔线和中性表面建立层级。
- 标题说明只保留对当前状态有用的短文案，不重复解释整个业务流程。
- 小屏宽度下降时改为单栏：商品目录在前、已选商品在后，底部汇总仍固定。

### 5.2 紧凑采购上下文

第一行只放完成采购所需的上下文：

- 新建采购批次：采购去向、项目或仓库、采购用途、期望到货日期。
- 发起采购申请：项目、合作供应商、采购用途、期望到货日期。

采购用途规则：

- 页面名称统一由“采购原因”或“临时采购原因”改为“采购用途”。
- 使用紧凑快捷项，不使用大面积 Textarea。
- 项目采购提供“项目备料”“现场补料”。
- 仓库采购提供“仓库补货”。
- “其他”是端侧交互入口；选择后展示单行自定义输入，不作为持久化枚举值。
- 采购用途继续必填，但不阻止商品浏览；保存时才统一校验并定位到该字段。

备注与其他低频字段收进“补充信息”：

- 默认折叠。
- 展开后显示备注输入；备注保持选填。
- 有内容时，折叠标题显示“已填写”，避免用户忘记已有内容。

### 5.3 商品目录

- 搜索框在目录栏顶部保持可见，关键词仅对应现有 RPC 支持的商品编码、商品名称、SKU 编码和 SKU 名称。
- 提交搜索后重置到第一页；清空搜索恢复完整目录。
- 批次目录展示商品/SKU、供应商、采购单位、服务端参考价和加入操作。
- 采购申请目录由顶部选择的合作供应商限定，使用现有关键词分页搜索，不重复显示
  供应商筛选，也不在本次新增分类查询契约。
- 批次目录提供分类和供应商筛选；复用现有分页接口与目录查询字段。
- 分类、供应商选项必须分页加载，禁止为了左侧筛选一次性拉取全量数据。
- 已加入的商品显示明确的“已选”状态；再次点击不会生成重复 SKU。
- 价格说明压缩到目录工具栏附近，最终仍以保存后的服务端冻结结果为准。

桌面端不机械复制移动端的窄分类侧栏。分类数量较少时使用紧凑横向/下拉筛选；分类
较多时使用可搜索的 Popover/Combobox，以保留商品表格的有效宽度。

### 5.4 已选商品

- 右栏常驻显示当前已选数量，内容独立滚动。
- 新增商品后立即出现在右栏，并获得短暂的非装饰性高亮反馈。
- 每行可以直接修改数量、成本分类和删除，不再跳到页面下方查找。
- 项目采购和仓库补货都继续按当前 Admin 规则选择成本类目；仓库补货的成本类目只
  用于采购归类，不参与项目预算占用。
- 数量仍支持最多 4 位小数，不用仅支持整数的加减器替代输入框。
- 每行显示单价和估算小计；服务端保存返回后以冻结金额刷新。
- 空状态直接说明“从左侧商品目录加入商品”，不展示一张空表。
- 达到 100 个 SKU 或 20 家供应商限制时，在加入按钮附近解释原因，而不是只禁用按钮。

### 5.5 固定汇总与保存

底部固定汇总展示：

- 已选 SKU 数。
- 新建采购批次的供应商数。
- 当前目录参考价计算的预估金额。
- 当前未完成项数量，例如“2 项待选成本分类”。

主按钮仍为“保存草稿”。保存行为保持现有契约：

1. 客户端校验采购去向、采购用途、商品、数量和必要成本分类。
2. 使用稳定 `Idempotency-Key` 调用现有保存命令。
3. 服务端重新解析目录和价格并冻结金额。
4. 成功后关闭或进入现有详情流程；价格变化、目录失效、版本冲突继续使用现有恢复机制。

## 6. 两个入口的差异

| 能力 | 新建采购批次 | 发起采购申请 |
| --- | --- | --- |
| 采购去向 | 项目或仓库 | 保持现有项目申请范围 |
| 供应商 | 可跨供应商选品 | 顶部固定一个合作供应商 |
| 商品筛选 | 关键词、分类、供应商 | 关键词；供应商由上下文限定 |
| 审批主体 | 整个采购批次 | 单采购申请 |
| 保存后计价 | 服务端冻结并生成供应商拆单预览 | 服务端按该供应商目录重新计价 |
| 右栏汇总 | SKU、供应商、金额 | SKU、金额 |

两个入口复用工作台布局、采购用途、补充信息、目录状态和底部汇总组件，但不强行合并
各自的命令状态、恢复逻辑或 API service。

## 7. 关键操作规则

### 7.1 初始化

- 未选择项目、仓库或供应商时，不请求无效目录。
- 商品区保留可见，显示“先选择采购去向后加载可采购商品”，让用户理解下一步。
- 采购用途未填写不影响目录加载。

### 7.2 改变采购上下文

- 尚未选商品时，切换项目、仓库或供应商后立即刷新目录。
- 已选商品时，切换会改变有效目录，必须先确认“切换后将清空已选商品”。
- 用户取消确认时，保持原上下文和已选商品不变。
- 用户确认后，原子更新上下文、清空商品与失效校验状态，并加载新目录。

### 7.3 离开未保存草稿

- 表单相对初始值发生变化后关闭 Sheet，显示未保存确认。
- 保存中禁止重复提交和切换关键上下文。
- 请求失败后保留所有用户输入与已选商品，允许沿用同一恢复状态重试。

### 7.4 校验与错误

- 字段错误贴近对应上下文或明细行展示。
- 目录加载错误只占据左栏，不覆盖右栏已选内容。
- 保存命令错误在底部操作区上方显示，同时把相关字段或行标记出来。
- 版本冲突、价格变化和目录失效沿用后端错误码，不通过吞错或前端猜测绕过。

## 8. 共享包与小程序一致性

`@gooes/domain` 增加稳定的用途建议配置，按采购去向区分：

```ts
export const SUPPLIER_PURCHASE_PURPOSE_PRESETS = {
  project: ["项目备料", "现场补料"],
  warehouse: ["仓库补货"],
} as const;
```

边界：

- 该配置是跨端稳定业务词汇，不是 `reason` 的封闭值域。
- `reason` 仍允许 1–500 字任意有效文本，兼容历史记录和“其他”输入。
- “其他”、placeholder、Picker/按钮组、折叠状态属于端侧 UI，不进入共享包。
- Admin 本次直接使用共享配置。
- `@gooes/domain` 从 `1.21.0` 升级到 `1.21.1`，重新构建并产出本地交付包。
- 小程序团队升级共享包，删除采购用途快捷值的本地硬编码，并把界面标签统一为“采购用途”。
- Gooes 只提供交接文档；orange 仓库保持只读。

## 9. 接口与数据边界

- 保存请求继续发送 `reason`，不增加 `purpose` 字段。
- 本次新增采购批次权限域内的只读分类选项接口，不修改既有保存接口，也不新增数据库表或字段。
- 2026-09-08 规格审查后，用户批准新增一个只读 schema migration：
  `resolve_supplier_purchase_batch_category_options(uuid,timestamptz,text,integer,integer)`。
  该 RPC 使用 `SECURITY INVOKER`，仅授予 `service_role` 执行权，无业务写入；它必须先按最新
  供应商资质/合同规则和批次 catalog 的品牌、单位、ownership、计价单位及唯一有效价格候选规则
  得到真实可采购 SKU，再对 active 叶子分类去重、关键词过滤和分页。精确回滚为
  `DROP FUNCTION public.resolve_supplier_purchase_batch_category_options(uuid,timestamptz,text,integer,integer);`。
- 批次目录继续使用 `GET /supplier-purchase-batch-catalog`，参数保持分页并按需增加
  `categoryId`、`tenantSupplierId`。
- 采购申请目录继续使用现有单供应商分页目录接口。
- 批次分类筛选使用新增 `GET /supplier-purchase-batch-category-options` 只读接口，沿用批次
  controller/service/repository 分层和 `supplier.purchase-requisition.manage` 权限，返回当前租户
  可实际采购的租户与平台叶子分类选项；请求支持 `page`、`pageSize`（最大 100）和关键词，响应
  仅包含 `id`、`code`、`name`、`full_name`、`status` 及分页元数据。
- 供应商筛选选项复用现有分页资源；`pageSize` 不超过 100。
- 不新增无上限列表接口，不在客户端对单页结果伪造全局分类筛选。

## 10. 可访问性与视觉规范

- 使用现有 shadcn/Radix Button、Input、Popover/Combobox、Sheet、AlertDialog 和 Table。
- 所有输入有可关联 label；仅图标按钮提供可读名称和 tooltip。
- 键盘可以完成搜索、筛选、加入商品、编辑明细、保存和关闭确认。
- 焦点样式使用现有 `focus-visible` token，不依靠颜色单独表达已选或错误状态。
- 状态色只用于错误、警告和成功；不使用装饰渐变、玻璃效果或营销式大标题。
- 默认圆角不超过现有后台 8px 规范，表格和工具栏保持紧凑间距。

## 11. 验收标准

1. 打开任一创建弹层后，商品区是最大且最先被感知的操作区域。
2. 采购原因和备注不再以两个大 Textarea 占据首屏。
3. 商品目录与已选明细在桌面宽度下同时可见并独立滚动。
4. 批次可以按关键词、分类和供应商筛选；所有列表保持服务端分页。
5. 添加商品后可在右栏直接修改数量、成本分类或删除。
6. 更换项目、仓库或供应商前，对清空已选商品进行确认。
7. 保存、幂等、版本冲突、价格变化和审批规则与现状兼容。
8. Admin 与小程序最终显示“采购用途”，并消费相同的共享用途建议。
9. `@gooes/domain@1.21.1` 构建、类型声明校验和 packed consumer 校验通过。
10. Admin 相关单元测试、类型检查、ESLint、开发构建和两条采购 E2E 工作流通过。
