# 生产迁移安全修复与官网发布设计

## 背景

企业官网候选提交 `98ba7616a5e5231cfb4dc46f56b4b88ea5896748`
已通过官网检查、362 项测试、生产构建和 Lighthouse 门禁，并已生成标签
`v2026.07.18.1`。生产迁移只读预检确认数据库当前最新版本为
`20260707223000`，共有 21 个待执行版本，数据库尚未发生写入。

发布审计发现三项需要在应用迁移前解决的问题：

1. `20260714170000` 含特定租户的一次性账单修复，虽然生产只读检查证明
   该租户、订阅和账单均不存在，实际执行会跳过，但这类业务数据修复不应继续
   留在通用建库迁移中。
2. `20260709103000` 创建的 `security definer` RPC 会先授权
   `authenticated`，下一条迁移才撤销，两个独立提交之间存在短暂越权窗口。
3. 生产迁移工作流执行带显式 `BEGIN`/`COMMIT` 的文件时，会在文件提交后才
   登记迁移历史；如果登记失败，可能出现结构已应用但历史未记录的分裂状态。

生产只读检查同时确认：相关表最大仅 432 kB，服务区数据不存在空白、未 trim
或归一化重复的 `adcode`，短信场景均符合现有约束，当前没有活跃锁等待。因此，
修复上述发布机制后，21 条迁移的锁风险可接受。

## 目标与边界

本次只解决阻断官网生产发布的迁移安全问题，并继续完成 API、Web、证书和
`www.goodcms.cn` 流量切换。

不重构迁移框架，不引入新依赖，不选择性跳过 21 条待执行迁移，不修改 orange
仓库，也不通过手工远端 DDL/DML 修库。所有生产数据库变更仍只允许由已审阅、
纳入版本控制的 migration 经生产工作流执行。

## 方案选择

采用“修正尚未进入生产的迁移源文件，并补强现有生产工作流”的最小方案：

- 从 `20260714170000` 删除特定租户的一次性账单修复块。该块在生产确认是
  无操作；删除不会改变生产预期状态，也避免新环境意外写入测试业务数据。
- 将 `20260709103000` 两个 RPC 的授权收紧为仅 `service_role`。后续
  `20260709104500` 保持幂等防御，迁移最终权限状态不变，同时消除中间窗口。
- 对包含显式事务的迁移，生产工作流必须在该文件最后一个独立 `COMMIT;`
  之前插入迁移历史记录，使业务结构和历史版本在同一事务提交。工作流先验证
  文件恰好含一个独立 `BEGIN;` 和一个独立 `COMMIT;`，不满足即在写入前失败，
  禁止猜测复杂事务结构。
- 不带显式事务的迁移继续沿用工作流外层 `BEGIN`、迁移 SQL、历史登记、
  `COMMIT` 的现有方式。

未采用的方案：发布时暂停 PostgREST 会扩大服务中断范围；只执行官网两条迁移
会让应用提交与数据库历史不一致；继续依赖硬编码谓词和短暂权限窗口则无法消除
已确认的结构性风险。

## 数据流与失败处理

发布按以下顺序执行：

1. 契约测试先证明危险授权、硬编码租户和非原子历史登记会被识别。
2. 修复迁移与工作流，运行最小测试、完整相关测试和官网生产检查。
3. 创建新提交和不可变标签 `v2026.07.18.2`，不移动或复用旧标签。
4. 对新标签重新运行生产迁移 `plan`，要求仍精确列出 21 个版本且生产历史未变。
5. `apply` 先生成 `public` 与 `supabase_migrations` 备份，再逐文件执行。
6. 应用后核对迁移数量、最新版本、Local/Remote 对齐和 RPC 权限，再发布 API。
7. API 健康且修订号匹配后构建、门禁并部署 Web，最后处理证书和 Nginx 切换。

任一迁移失败时，当前文件事务回滚并停止后续版本；不得盲目重跑。先比对结构与
`schema_migrations`，确认未发生分裂后再决定前向修复。若应用后业务验证失败，
优先回滚应用容器，并通过经审阅的新 migration 撤销数据库入口；涉及业务历史的
表不做直接删除。全库恢复仅作为最后手段，使用发布前备份并另行审阅恢复步骤。

## 测试与验收

自动化契约至少覆盖：

- 初始 RPC migration 不得向 `authenticated` 授权；
- 通用 migration 不得包含已知租户 UUID 和一次性账单修复标记；
- 显式事务迁移的历史登记位于最终 `COMMIT;` 之前；
- 非法的多事务文件会被工作流拒绝；
- 原有生产预检制品、备份和迁移汇总契约继续成立。

生产验收要求：21 个迁移版本全部对齐至 `20260716093000`；API 与 Web 容器
修订号均等于新标签提交；`https://www.goodcms.cn/`、`/partners`、
`/sitemap.xml` 和至少一个已发布内容路径使用有效证书并通过严格 HTTPS smoke；
Admin 仅 `/partners` 保留查询参数跳转到官网，其他后台路径不受影响；所有预存
生产容器除明确发布目标外保持不变，并保留可追溯的构建、迁移、部署和切换记录。
