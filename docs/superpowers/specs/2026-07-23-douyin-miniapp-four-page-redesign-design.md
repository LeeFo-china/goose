# 抖音装修小程序四页优化设计规格

状态：设计已确认，等待规格复核

日期：2026-07-23

关联审计：

- `docs/superpowers/specs/2026-07-23-douyin-miniapp-four-page-ui-audit.md`

## 1. 设计结论

推荐采用“租户主色 + 施工档案型”设计。

这套设计把小程序理解为装修公司面向业主的内容与信任入口，而不是平台后台、品牌宣传册或通用营销落地页。案例负责证明审美与交付结果，工地负责证明过程透明，免费咨询负责承接已经建立的信任。

设计参数：

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 2`
- `VISUAL_DENSITY: 5`
- 设计模式：`Redesign - Preserve`

## 2. 设计目标

1. 让不同装修公司只配置 Logo、主色和内容，就能形成一致但不冲突的品牌体验。
2. 用户切换到案例或工地后，首屏能直接开始浏览有效内容。
3. 首页在一个屏幕内同时回答“这是谁”“是否可信”“下一步做什么”。
4. 咨询页先完成姓名、手机号和验证码，再由用户决定是否补充房屋信息。
5. 保留现有接口、分页、埋点、短信、隐私和幂等业务契约。
6. 达到移动端触达、文字对比度、读屏名称和状态反馈的基础可访问要求。

## 3. 不在本次范围

- 不修改 Tab 数量、名称或路由。
- 不新增后端接口、数据库字段或 migration。
- 不改变租户隔离、内容公开边界和工地隐私规则。
- 不改变现有咨询提交字段名和请求结构。
- 不增加 Taro、组件库、图标库或动画依赖。
- 不引入深色模式。
- 不操作抖音开发者工具的上传、提审或发布。

## 4. 视觉系统

### 4.1 色彩

租户配置的 `primary_color` 是页面唯一品牌强调色，应用于：

- 主按钮和文本链接
- 当前筛选项
- 重点状态标签
- 步骤或进度的当前节点
- 可交互元素的聚焦与按压状态

平台保持统一的语义色：

| Token | 用途 | 建议默认值 |
|---|---|---|
| `page` | 页面底色 | `#F5F5F3` |
| `surface` | 内容表面 | `#FFFFFF` |
| `ink` | 主要文字 | `#191817` |
| `muted` | 次要文字 | `#625F5B` |
| `subtle` | 元数据文字 | `#706C67`，位于页面底色时对比度 `4.77:1` |
| `border` | 卡片和输入边界 | `#DDDAD5` |
| `surface-soft` | 次级分组背景 | `#ECEAE6` |
| `success` | 成功状态 | `#1F6B45` |
| `danger` | 错误状态 | `#B42318` |

不再保留固定陶土主色。主色前景继续由现有对比度函数选择黑色或白色；任何动态组合都必须达到普通文字 `4.5:1`。

### 4.2 字体层级

沿用系统字体，不加载远程字体。

| 层级 | 建议字号 | 用途 |
|---|---:|---|
| 页面标题 | `42rpx` | 案例、工地、免费咨询页标题 |
| 区块标题 | `34rpx` | 首页主要内容区 |
| 卡片标题 | `30rpx` | 案例、工地标题 |
| 正文 | `28rpx` | 表单和说明 |
| 次要信息 | `24rpx` | 区域、阶段、更新时间 |
| 辅助信息 | `22rpx` | 必须满足对比度的元数据 |

首页只允许品牌区域保留一次英文或小号 kicker。其余栏目直接使用中文标题，避免重复模板语法。

### 4.3 形状与边界

- 内容卡：`16rpx` 圆角，1px 语义边框，无常驻重阴影。
- 输入框和普通按钮：`12rpx` 圆角。
- 筛选项和短状态：全圆角胶囊。
- 图片圆角跟随卡片，不额外叠加不同半径。
- 错误与隐私提示使用完整浅色表面，不使用左侧装饰色条。

### 4.4 动效

- 可点击卡片和按钮使用约 150ms 的 `transform` 与 `opacity` 按压反馈。
- 页面内容不做逐项入场、滚动视差或装饰性动画。
- 骨架屏保留现有 reduced motion 降级。

## 5. 首页

### 5.1 信息顺序

1. 租户品牌头部
2. Hero 信任主张
3. 精选案例
4. 在建工地
5. 服务流程
6. 服务范围与公司信任信息

删除页面底部与 Hero 同意图的重复咨询卡。免费咨询仍可通过 Hero 主按钮和 Tab 进入。

### 5.2 品牌头部

- 保留租户 Logo 和名称。
- 次要描述最多两行。
- 不额外使用大卡片包裹整个头部。
- Logo 缺失时使用名称首字或现有业务占位，不新增通用插画。

### 5.3 Hero

- 保留租户可配置 Banner。
- 文字保持短标题、单段说明和一个主 CTA。
- 使用渐变遮罩保证动态图片上的文字对比度。
- CTA 使用租户主色和可读前景色。
- 不加入第二个并列按钮。

### 5.4 精选案例

- 区块头直接显示“精选案例”和“查看全部”。
- 首页展示一张主案例；图片比例保持内容主导。
- 元信息只保留户型、面积或风格中最有辨识度的两项。
- 无案例时使用现有空状态，不显示虚构样例。

### 5.5 在建工地

- 区块头直接显示“在建工地”和“查看全部”。
- 卡片突出当前阶段、区域和更新时间。
- 不显示门牌号、业主姓名、手机号或其他私密信息。
- 施工阶段使用文字加短进度表达，不依赖颜色单独传递含义。

### 5.6 服务与信任

- 流程使用一条轻量步骤轨道，不为每个步骤创建独立浮层卡。
- 服务区域和公司介绍合并到同一个信任区。
- 只展示能由真实租户资料支持的信息，不生成“服务上千家庭”等宣传数字。

## 6. 案例页

### 6.1 首屏

- 使用紧凑中文标题和一行用途说明。
- 筛选紧接标题，不再使用额外 kicker。
- 第一张案例应尽可能进入首屏，不让营销页头挤占内容区域。

### 6.2 筛选

- 当前项使用租户主色胶囊。
- 未选项使用浅表面和语义边框。
- 多筛选生效时提供明确的“清除筛选”动作。
- 有筛选且无结果时，空状态提供同一清除动作。
- 清除动作只重置前端筛选并按现有查询契约重新加载第一页。

### 6.3 案例卡

- 保留纵向大图，使用统一 16rpx 卡片轮廓。
- 标题最多两行。
- 户型、面积、风格以不超过两行的元数据呈现。
- 卡片整体可点击，保留业务 `aria-label`。
- 屏外列表图片启用 `lazy-load`，显示模式继续使用 `aspectFill`。

## 7. 工地页

### 7.1 首屏

- 使用紧凑中文标题和简短说明。
- 隐私说明改为单行浅色提示，必要时允许换行。
- 第一张工地卡紧接提示出现。

### 7.2 工地卡

- 与案例卡共享边框、圆角、标题和按压规则。
- 保留更适合施工信息的横向或紧凑图片比例。
- 视觉优先级为：当前阶段、项目名称、区域、更新时间。
- 阶段标签同时包含文字，不以主色深浅作为唯一识别方式。
- 图片启用 `lazy-load`。

### 7.3 隐私边界

公开内容只允许显示：

- 行政区或已脱敏区域
- 施工阶段
- 已公开项目名称
- 已公开图片
- 更新时间

不通过视觉改版扩大现有公开字段范围。

## 8. 免费咨询页

### 8.1 页面结构

1. 紧凑标题和提交用途说明
2. 必填联系信息
3. 可展开的补充装修信息
4. 隐私同意
5. 主提交按钮
6. 安全说明和电话入口

保持单页、单次提交，不改成多步骤向导。

### 8.2 必填联系信息

第一组只展示：

- 姓名
- 手机号
- 短信验证码

验证码按钮维持现有发送、倒计时、禁用和错误处理。

### 8.3 补充装修信息

小区名称、房屋面积、预算范围、计划开工时间和装修需求归入“补充装修信息（选填）”区域，默认折叠。

- 折叠时显示填写价值说明。
- 展开后沿用原字段类型和数据绑定。
- 已填写内容在折叠和展开之间保持。
- 展开状态不改变提交契约。

### 8.4 校验与错误

- 每个 `input` 和 `textarea` 增加清晰 `aria-label`。
- 字段错误显示在对应字段下方。
- 页面级错误摘要继续保留并使用 `role="alert"`。
- 首个错误字段进入可见区域，但不新增自动提交或绕过校验。

### 8.5 隐私同意

- 视觉勾选框可以保持紧凑。
- 整个同意行至少 88rpx 高并可切换同意状态。
- 隐私政策链接保持独立点击，点击链接不误切换同意状态。
- 未同意时维持现有提交阻止逻辑。

## 9. 共享组件调整

预期复用或调整以下现有组件，不创建第二套相似实现：

- `tenant-brand`
- `hero-banner`
- `case-card`
- `site-card`
- `lead-form`
- `sms-code-input`
- `privacy-consent`
- `page-skeleton`
- `empty-state`
- `error-state`
- `pagination-loader`

新增共享组件必须满足两个以上页面确实复用，并在实施计划中说明原因。页面头部如果仅有少量 TTML，可通过共享 TTSS 规则统一，不为抽象而抽象。

## 10. 状态设计

四页必须继续覆盖：

- 首次加载
- 有内容
- 无内容
- 接口错误
- 分页加载
- 分页错误和重试
- 图片缺失
- 表单发送验证码
- 验证码倒计时
- 表单校验错误
- 提交中
- 提交成功
- 重复点击防护

优化不能用静态样例替换任何真实状态。

## 11. 验收标准

### 11.1 视觉与主题

- 四页不再出现固定陶土品牌色。
- 页面只使用一套卡片、圆角、标题和状态语言。
- 更换租户主色后，主按钮、链接、筛选和重点状态同步变化。
- 动态主色与其前景文字达到 `4.5:1`。

### 11.2 首页

- Hero 与底部不再出现两个同意图咨询 CTA。
- 案例、工地、流程和信任区层级可清楚区分。
- 首屏在当前 393px 模拟器内能看到品牌、价值主张和主动作。

### 11.3 案例

- 有筛选的空结果能一键清除筛选。
- 案例图片启用懒加载。
- 卡片整体可点击且具有可访问名称。

### 11.4 工地

- 隐私提示不使用左侧装饰色条。
- 工地卡明确展示阶段、区域和更新时间。
- 不新增任何业主或详细地址字段。

### 11.5 免费咨询

- 第一组仅包含姓名、手机号和验证码。
- 选填字段可展开并保持输入值。
- 每个输入控件具有独立可访问名称。
- 字段级错误和页面级错误摘要同时可用。
- 隐私同意触达区域不小于 88rpx。

### 11.6 性能与验证

- Hero 与 Logo 立即加载，屏外案例和工地图片使用 `lazy-load`。
- 最小静态检查、相关测试和构建通过。
- 抖音 IDE 中逐页复核 393px 设备的首屏、中段、底部和所有状态。
- 手机预览由用户执行，Codex 不点击上传、提审或发布。
- 实施后重新运行五维审计，P1 问题清零，总分目标不低于 17/20。

## 12. 已确认决策

用户于 2026-07-23 确认：

- 品牌策略：租户主色作为唯一强调色。
- 页面方向：施工档案型。
- 咨询策略：选填装修信息默认折叠。
- 首页策略：移除底部重复咨询 CTA。

本规格确认的是设计目标、交互和业务边界。具体文件改动、测试顺序和验证命令将在后续实施计划中展开，实施不得扩大本规格范围。
