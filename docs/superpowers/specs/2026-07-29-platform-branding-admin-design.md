# 平台默认品牌管理设计

## 目标

在 Gooes Admin 超管侧新增独立的“平台品牌”配置入口，让具备
`platform.branding.manage` 权限的超管维护没有租户自定义品牌时使用的
默认品牌名称和 Logo，并通过草稿、预览、发布流程安全生效。

本次只补齐已有平台品牌接口的 Admin 交互，不修改数据库、API 契约、租户
品牌权益、品牌权益商品或 Orange 小程序代码。

## 信息架构

采用独立入口：

```text
平台配置
├── 平台品牌
└── 品牌权益
```

“平台品牌”负责平台默认品牌资料；“品牌权益”继续负责年度权益商品名称、
价格、购买说明和上下架。两者使用不同权限和接口，不合并为同一表单，也不
通过页签共享一个权限边界。

- 路由：`/platform/branding`
- 菜单：平台配置 → 平台品牌
- 权限：`platform.branding.manage`

菜单按权限隐藏，页面服务端再次检查平台超管身份和权限；后端仍是最终权限
边界。

## 页面结构

页面使用一个顶层工作区卡片，保持与现有 Admin 配置页一致的紧凑布局。

### 页头

- 标题：“平台品牌”
- 说明：“维护租户未启用自定义品牌时展示的默认名称和 Logo。”

### 状态区

展示：

- 当前状态：未配置、草稿、已发布、存在未发布修改；
- 草稿版本和已发布版本；
- 最近更新时间和最近发布时间。

状态使用语义化 Badge，不只依赖颜色表达。

### 编辑区

- 品牌名称：必填，去除首尾空白后为 2–40 个 Unicode 字符；
- 品牌 Logo：JPEG 或 PNG，最大 2MB；
- Logo 上传复用 `brand_logo` 直传场景；
- 上传成功后保存 `file_id`，草稿只提交 `logo_file_id`；
- 上传中禁用选择、保存和发布操作；
- 新 Logo 上传成功但草稿尚未保存时，明确显示“待保存”状态。

### 实时预览

预览区域始终显示当前表单中的名称和 Logo。首次配置时使用后端返回的
`effective` 平台品牌作为起始预览；上传新 Logo 后立即使用本地对象 URL，
保存成功后切换为后端返回的可信 Logo URL。

预览说明明确区分“编辑预览”和“当前线上品牌”，避免用户误以为保存草稿
已经发布。

### 操作

- “保存草稿”：调用 `PATCH /platform/branding`；
- “发布品牌”：调用 `POST /platform/branding/publish`；
- 发布前如果表单仍有未保存修改，先阻止发布并提示保存草稿；
- 发布按钮仅在存在完整草稿且存在未发布修改时启用；
- 提交期间禁用所有会改变状态的操作，并显示 Spinner；
- 保存或发布成功后使用响应中的 profile、effective 和 version 更新页面
  基线。

## 数据契约

页面服务端读取：

```text
GET /platform/branding
```

响应使用：

```ts
interface PlatformBrandingResult {
  profile: PlatformBrandProfile | null;
  effective: EffectiveBranding;
}
```

保存草稿：

```json
{
  "display_name": "Gooes",
  "logo_file_id": "uuid",
  "version": 0
}
```

首次保存使用 `version: 0`，后续保存使用当前 profile 版本。

发布：

```json
{
  "version": 1
}
```

页面不接收或提交租户 ID。

## 并发、错误和恢复

- `BRANDING_PROFILE_VERSION_CONFLICT`：提示资料已被其他管理员修改，提供
  “重新加载”操作，不覆盖远端版本；
- 上传校验错误显示在 Logo 字段附近；
- 保存与发布错误使用标准 `StatusAlert`，保留后端稳定错误消息；
- 页面加载失败不显示空表单，避免把读取失败误当作首次配置；
- 上传失败保留原草稿 Logo，用户可以重试；
- 首次配置没有 profile 时，默认表单名称取 `effective.display_name`，Logo
  预览取 `effective.logo_url`，但 `logo_file_id` 保持为空，必须重新上传可信
  文件后才能保存。

## 骨架屏

骨架屏与真实结构对应：

- 页头标题和说明；
- 状态摘要；
- 品牌名称字段；
- Logo 上传区域；
- 品牌预览；
- 底部保存和发布操作。

不使用与真实页面无关的表格或多卡片占位。

## 测试与验收

- 纯函数测试：初始化表单、名称校验、草稿 payload、未保存修改判断和发布
  条件；
- 导航测试：`platform.branding.manage` 控制“平台品牌”菜单；
- 页面契约测试：服务端 GET、客户端 PATCH/POST、`brand_logo` 上传、权限和
  版本冲突恢复；
- 骨架屏契约测试：关键区域与真实页面一致；
- 运行 Admin 定向测试、文件大小检查、类型检查和生产构建；
- 浏览器 smoke 验证加载、首次配置、替换 Logo、保存草稿、发布、刷新后
  状态保持及控制台无错误。

## 非目标

- 不修改受控后端回退常量；
- 不新增独立 `support_text` 字段，文本继续原样等于 `display_name`；
- 不管理租户品牌资料；
- 不管理品牌权益商品、订单、授予、退款或支付；
- 不增加依赖；
- 不修改 Orange 仓库。
