# 默认工作流模板实施计划

目标：复制晴天当前已发布的五套标准工作流到天喜，并自动初始化后续新租户。

范围：customer_main、project_signing、construction_main、expense_approval、supplier_purchase_batch_approval。不包含非默认自定义施工流程。固定当前发布快照；不复制运行实例、历史版本或具体员工。复制图节点和连线时重建所有租户与 UUID 引用。

方案：复用 tenant_templates / tenant_template_applications 记录版本化配置与应用结果；新增私有 SQL 初始化函数并接入现有 initialize_default_decoration_tenant 包装器。既有组织初始化函数、建户入口、安全检查与权限保持不变。新租户原子初始化五套流程；既有租户重试初始化不覆盖业务流程。天喜通过单独的有数据漂移断言的 migration 应用同一模板，采购流程新增发布版本并保留旧版本。

替代方案：每次新建时实时读取晴天配置会随晴天业务修改而漂移，且依赖该租户持续存在；只复制一次无法满足后续租户要求。采用版本化静态模板。

- [x] 导出并归一化五套发布快照，检查无租户专属配置引用。
- [x] SQL 行为测试：新建租户获得五套发布流程和默认施工绑定，先验证现有实现失败。
- [x] 新 migration 保存固定模板、私有应用函数、初始化接入；重复调用不重发、不重置租户自定义。
- [x] 单独 migration 限定天喜并检查已有采购版本、草稿与实例无漂移，复制四套并发布采购新版本。
- [x] 本地实际 PostgreSQL：图完整性、快照租户隔离、版本保留、默认绑定、角色权限配置、幂等、历史租户不自动回填、权限边界、异常整笔回滚；现有建户测试。
- [ ] 独立审查；通过后提交、生产 migration plan 确认仅本次两项、apply、migration list 对齐、只读验收。

回退：后续 forward migration 恢复原初始化包装器并停用模板。天喜若已产生实例，保留已发布版本和实例，恢复原采购 active_version、将新定义归档；禁止删除已被实例引用的版本。未使用的新增流程可在明确审计后处理。其他既有租户和晴天不变。
